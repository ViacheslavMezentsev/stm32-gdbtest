# write

[API](index.md) · [English](../../en/api/write.md)

> **MMIO:** Даже verify=False сохраняет чтение before. Однократный RHS не устраняет повторное вычисление LHS и возможный RMW битового поля. Для MMIO outside нет подтверждающего readback; это не делает запись безопасной для WO/FIFO/read-to-clear. [Ограничения и проверка на модели/плате](../MMIO.md).

`write(path, value, *, verify=True) -> dict`; `write(rows, *, verify=True) -> list[dict]`

| Свойство | Значение |
| --- | --- |
| Поддержка в модуле | 0.3.0; уточнение в кандидате 0.4.2 |
| Контракт принят в ТЗ API | принят, ревизия 0.3.17 |

## Назначение

Записывает значение в адресуемый объект программы и возвращает результат с диагностикой эффекта. Значение — целое, конечное `float`, `bool` (передаётся как 1/0) или выражение GDB (константа enum, макрос); выражение сравнивается при проверке по результату вычисления. Другие значения отвергаются до записи (`unsupported_value`).

## Контракт и ограничения

С проверкой (`verify=True`) чтение после записи подтверждает применённое значение.

Ограничения: адресуемые объекты в RAM объявленного скалярного типа; целочисленные ширины, 64-битные значения, `float`, bool, enum и указатели
проверены на нейтральном ELF в Renode. Это не новая аппаратная приёмка. Проверка чтением выполняется только для
объектов в окне SRAM: регистр периферии читается по своим правилам, поэтому для него запись
выполняется, а прочитанное значение и признак `verify_scope=outside` попадают в результат без
заявления о подтверждении. Ошибка записи не скрывается и возвращается как
отказ операции; уже применённый эффект не откатывается.

### Выражение в значении и таблица записей

Строковое значение — выражение C, которое GDB вычисляет **до** записи: в нём допустимы операторы
(`|`, `&`, `~`, `<<`, `>>`, `+`, `-`, сравнения) и макросы прошивки. Поэтому чтение-изменение-запись
регистра записывается одной строкой. Запрещены перевод строки, `;` и присваивания (`=`, `|=`, `<<=`,
`++`, `--`): присваивание адресату попадает в `mutations`, но вызванная RHS-функция может менять другие объекты (`unsupported_value`).

`write(rows)` с единственным аргументом-списком выполняет записи `(path, value)` по порядку и
возвращает список результатов. Структура всех строк проверяется до первой записи; отказ строки
останавливает остальные, уже выполненные записи не откатываются. `verify` действует на все строки.

```python
# Запуск непрерывного преобразования, пока ядро остановлено: порядок строк важен.
t.write([
    ("ADC1->CFGR1", "ADC1->CFGR1 | ADC_CFGR1_CONT"),
    ("ADC1->CR", "ADC1->CR | ADC_CR_ADSTART"),
])
t.write("ADC1->CR2", "ADC1->CR2 & ~ADC_CR2_ADON")        # сброс бита выражением
t.write([("SysTick->CTRL", control), ("NVIC->ISER[0]", enabled)])   # восстановление сохранённых значений
```

## Пример

```python
t.write("app_state.ticks", 41)
t.write("app_delay", 100)
```

Запись в неизменяемую область (Flash, регистры только для чтения) завершается диагностикой, а не
молчаливым успехом.

## Уточнение 0.4.2 и миграция

RHS вычисляется один раз при успешном присваивании независимо от `verify`, в том числе в таблице.
Ожидание берётся из результата присваивания GDB с преобразованием к типу адресата: например,
257 в `uint8_t` проверяется как 1. Нет промежуточного сведения всех типов к Python int.
Прежняя 0.4.1 могла вычислять строковый RHS дважды при verify=True; исправление устраняет этот эффект.
Явный evaluate → готовое значение → write остаётся допустимым и переносимым приёмом.

`path` должен обозначать стабильный объект без побочных эффектов: его чтение и проверка адреса
предшествуют присваиванию, затем выполняется readback в SRAM. Число вычислений LHS не ограничено
одним; атомарность, неизменность volatile и безопасность MMIO не обещаются. Для MMIO сохраняется
verify_scope=outside и отсутствие подтверждающего чтения после записи.

Ошибка команды: command_failed / command / unknown (RHS мог уже изменить состояние).
Ошибка чтения после записи: read_failed / readback / applied; запись остаётся в mutations с after=None.
Ошибка преобразования результата присваивания: conversion_failed / readback / applied.
Несовпадение readback сохраняет verification_failed. Повторов и отката нет.


Кандидат 0.5.0, API_VERSION=3: правила sync/async, таймауты, запрет скрытых вызовов и миграция — [живое исполнение](../LIVE_EXECUTION.md#исполнение-в-api_version3-кандидат-050).
