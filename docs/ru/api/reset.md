# reset

[API](index.md) · [English](../../en/api/reset.md)

`reset() -> dict`

**Доступен с:** 0.3.0 · **API 3 (0.5.0):** в `async def` — `await t.reset()`; в эмуляторе отклоняется (`unsupported_backend`). [Правила sync/async](../LIVE_EXECUTION.md).

## Назначение

Сбрасывает цель через команду backend-а, оставляет ядро остановленным и инвалидирует кэши отладчика.

## Контракт и ограничения

Активная точка сценария (breakpoint или watchpoint) даёт `active_points` до сброса; её нужно удалить
явно. После команды выполняется инвалидация кэша
регистров и кадров, в том числе после неудачной попытки; результат описывает состояние и шаги
инвалидации.

Источник команды: диалект backend-а. OpenOCD сбрасывает командой `monitor reset halt`, ST-LINK GDB
Server и J-Link — `monitor reset`; секция профиля цели для выбранного сервера (schema 2) или
переопределение сессии `STM32_GDBTEST_RESET_COMMAND` меняют значение. Значение разрешается один раз
при подготовке прогона и используется и загрузкой, и `reset()`; сценарию оно доступно как
`stand.reset_command`. Ключ `api.toml` `reset.command` больше не влияет на выполнение и остаётся данными файла. Schema 1 задаёт команды только OpenOCD. Override не меняет завершение и recovery. После неудачной попытки кэши инвалидируются, автоповтора команды нет, кадры и регистры невалидны до нового `reach`.

Ограничения: команда сброса принадлежит backend'у (`monitor reset halt` для OpenOCD,
`monitor reset` для ST-LINK GDB Server и J-Link); остановка до первой инструкции программы не гарантируется; содержимое
RAM до запуска программы не сохраняется; при активной точке наблюдения сброс не выполняется.

## Пример

```python
result = t.reset()
t.check("halted after reset", result["outcome"], "halted")
t.reach("main")
```

Ошибка команды backend-а возвращается как отказ операции с сохранением причины и шагов инвалидации;
состояние связи после ошибки не гарантируется.
