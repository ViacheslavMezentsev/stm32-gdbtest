# check-failed

[API](index.md) · [English](../../en/api/check-failed.md)

`CheckFailed(AssertionError)`

| Свойство | Значение |
| --- | --- |
| Поддержка в модуле | не выпущено: проект пакета 0.3.0 |
| Контракт принят в ТЗ API | не принят; проектируемая ревизия 0.2.5 |
| API_VERSION | 1 (действующий контракт не изменяется) |
| Основание | согласованная проверочная прошивка `tests/firmware` и её сценарии (`HW_CI_RET_RECEIVER`, `HW_CI_MEASUREMENT_SERIES`) |

## Назначение

Сообщает, что проверка сценария не совпала с ожиданием, и попадает в отчёт как провал проверки.

## Контракт и ограничения

Исключение содержит имя проверки и доступно отчёту наряду с фактическими и ожидаемыми значениями.

Ограничения: строгий режим проверки ещё согласуется; несовпадение не прерывает прогон немедленно,
если сценарий продолжает работу, но итог прогона — провал.

## Пример

```python
target.check("ticks advanced", target.value("app_state.ticks") > 0, True)
```

Провал проверки отличается от отказа операции: сценарий продолжает работу, но прогон не может быть
успешным.
