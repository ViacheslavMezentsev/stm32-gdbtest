## Возможности

Локальные и SSH-запуски, CMake/CTest, пакеты, Hardware CI и конечные автономные циклы;
OpenOCD, ST-LINK GDB Server, st-util и J-Link. API содержит навигацию, наблюдение данных,
инъекции, таблицы проверок и сопоставители, `profile`, произвольные `record`/`records`,
`skip(reason)`. Захват записей на диск включается конфигурацией; экспорт, проверка целостности
и HTML выполняются отдельно. Исходы PASS/FAIL/ERROR/SKIP не взаимозаменяемы.

## Известные ограничения и долг

- Длительные F411/F030-прогоны ST-LINK GDB Server не приняты из-за повторяемого USB ERROR.
  Владелец принял v0.4.0 с этим ограничением; успешный OpenOCD/st-util его не закрывает.
- st-util 1.6.0 и 1.9.0 имеют разные подтверждённые границы; см. [backend st-util](backends/st-util.md).
- Linux x86_64 с локальным USB и WSL2/usbipd аппаратно не приняты; поддержка новой платы
  требует проверки конкретного MCU, GDB, сборки и backend. H503 не принят.
- Открыты диагностика бинарного USB serial, причина прежней аномалии F429 SP/SRAM и границы
  принудительного cleanup. В DDTT-проверке потребителя один Windows prepare при `-j 2`
  отверг каталог вывода; последовательный повтор прошёл, причина ещё не изолирована.
- Halt меняет время и IRQ; инъекция не воспроизводит физическую причину отказа. Recovery
  не гарантирует восстановление оборванной связи. Внешние приборы и управление питанием — отдельные инструменты.
