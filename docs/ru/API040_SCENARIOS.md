# Сценарии приёмки API 0.4.0

[Документация](index.md) · [English](../en/API040_SCENARIOS.md)

Дополнение к штатным примерам: четыре сценария с меткой `api040`, общие для пяти STM32-профилей.
Они используют существующую CMSIS-прошивку без новых тестовых hooks. Это проверка новых возможностей
пакета, а не полный повтор приёмки API или свидетельство для всех GDB/backend.

| Сценарий | Что показывает | Ожидаемый исход |
| --- | --- | --- |
| [HW_CI_040_RECORDS](../../tests/firmware/common/tests/board/test_release040_records.py) | Состояние MCU, переход, измеренный шаг счётчика и произвольная диагностика в одном журнале; независимость копий | PASS, четыре записи |
| [HW_CI_040_SKIP](../../tests/firmware/common/tests/board/test_release040_skip.py) | Применимость по конфигурации, решение через records, завершение всего сценария и выполнение finally | PASS при true; SKIP при false |
| [HW_CI_040_SKIP_VALIDATION](../../tests/firmware/common/tests/board/test_release040_skip_validation.py) | Отказ пустой/нестроковой/некорректной Unicode-причине и превышению лимита; последующая навигация работает | PASS, шесть ожидаемых отказов |
| [HW_CI_040_STRING_VIEWS](../../tests/firmware/common/tests/board/test_release040_string_views.py) | Один RAM-буфер как char[3], char[] и char*: ограничение чтения размером без изменения памяти | PASS |

## Конфигурация и выбор

В `session.toml` включите сохранение журнала (если секция уже есть, измените её):

```toml
[results]
capture = true
```

В выбранном `api.toml` управляйте только применимостью примера:

```toml
[user.release040]
optional_loop = false
```

Отсутствующий параметр означает true: штатный общий набор не получает обязательный SKIP.
False моделирует явно выключенную возможность, а не неисправность платы. Неверный тип — FAIL.
Сохраняйте две независимые конфигурации и каталоги результатов для обоих вариантов.
Не меняйте target.toml или ELF ради выбора сценария: они должны соответствовать build manifest.

После обычной сборки прошивки выбирайте один ID; остальные сценарии не запускаются:

```text
python -m stm32_gdbtest run --session <session.json> --test HW_CI_040_RECORDS --stand <stand.toml> --prepare-only
python -m stm32_gdbtest run --session <session.json> --test HW_CI_040_RECORDS --stand <stand.toml>
```

Повторите для четырёх ID; SKIP проверьте с true и false (пять аппаратных запусков на плату).
Используйте обычную конфигурацию CMake/session, чтобы дескриптор ссылался на выбранный session.toml.
Ожидаемый код SKIP — **77**, не 0. Общий `run_suite.py` ожидает PASS: для этого опыта применяется
явный выбор через CLI, а не запуск всего набора. [Контракт skip](api/skip.md).

## Проверка артефактов

- Каждый аппаратный запуск: проверенный образ, штатный reset/run в teardown и подтверждённое завершение сервера.
- PASS: `capture.status=saved`, `completion=normal`; SKIP: saved/interrupted, непустой skip_reason, JUnit skipped.
- Отключённый пример содержит capability и optional.finally; optional.executed и optional.completed отсутствуют.
- Включённый пример содержит все четыре записи и не увеличивает число пропусков.
- Журнал RECORDS сохраняет разные типы: 0, false, null и целое `2**60+1`. Sequence задаёт порядок, не время.
- Общий экспорт сохраняет **все** записи. Измерение выбирается проекцией явно; имя записи не задаёт её тип.

Создайте selection.json только из новых аппаратных запусков, затем выполните
[results export, verify и report](RESULTS.md). Проверяйте отдельно исход обработки файлов и вердикт сценария:
успешная генерация HTML не превращает SKIP в PASS. Исходные ошибки и повторные попытки не перезаписываются.

## Результаты

Проверено 10.10.2026: Windows, xPack 13.3.1-1.1 (GDB 14.2.90, Python 3.11.4),
SSH → OrangePi/Ubuntu 20.04, st-util 1.9.0 и libusb 1.0.27. Основа runtime — `3613a00`;
четыре новых сценария проверены в рабочем дереве и сохранены вместе с хешами исходников.

| Плата | Подготовка | Аппаратные исходы | Захват / JSON / JUnit |
| --- | --- | --- | --- |
| F030R8 | 5 PASS | 4 PASS + 1 ожидаемый SKIP | 5/5 |
| F103 / WeAct BluePill-Plus | 5 PASS | 4 PASS + 1 ожидаемый SKIP | 5/5 |
| F401CC | 5 PASS | 4 PASS + 1 ожидаемый SKIP | 5/5 |
| F411CE | 5 PASS | 4 PASS + 1 ожидаемый SKIP | 5/5 |
| F429ZI | 5 PASS | 4 PASS + 1 ожидаемый SKIP | 5/5 |

Итого: 25 prepare PASS, 20 HW PASS и 5 ожидаемых SKIP (код 77). Во всех 25 аппаратных
запусках подтверждены образ, teardown, idle и exit 0 удалённого сервера. Сохранено 65 записей;
общий экспорт совпадает с исходными журналами. Отдельная проекция пяти измерений даёт
пять значений 1 tick, сохраняя все 20 записей выбранных запусков. Export/verify/report завершились
успешно; HTML разделяет 20 PASS и 5 SKIP. Проверки docs+host в Docker: 6/6.

Первый prepare вернул stale_selection после переноса target.toml: до сервера выполнение не дошло.
Сохранён исходный ERROR; в конфигурации возвращена ссылка на исходный target из manifest.
Это исправление запуска, не ослабление проверки и не изменение ядра. Старые аппаратные сценарии
в этой кампании не запускались; результат не закрывает ограничения ST-LINK GDB Server или AT32.
