# Кандидат v0.2.0-rc.1: состав и приёмка

[Документация](index.md) · [English](../en/RC020_READINESS.md)

Согласован 03.10.2026. Python `0.2.0rc1`, ТЗ API **0.2.3**, API_VERSION=1,
api.toml schema=1, общее ТЗ **0.65**. Кандидат готовится локально; тег и публикация не выполнены.

## Состав

- record/records, публичный RecordError и неизменяемые config/config_props.
- Явный SESSION_CONFIG, session.toml и захваченный снимок TOML в GDB/пакете.
- Совместимость прежних session.json, PROFILE_DIR и пакетов.
- Пять CMSIS-профилей, HAL F030, техники таблиц и статистики измерений.
- Стек/контекст, experimental read/finish, RTOS и адаптивный движок не включены в API.

## Миграция с v0.1.0-rc.2

1. Обновить закреплённый gitlink модуля до проверенного SHA кандидата и повторить CMake configure.
   Установка через pip не предусмотрена.
2. Старые PROFILE_DIR, target.toml, session.json и сценарии продолжают работать.
   Для использования config из новых TOML выбрать SESSION_CONFIG явно.
3. Создать session.toml с `[config]`, `target = "target.toml"`, `api = "api.toml"`;
   при full-image добавить `image = "full-image.toml"`. Пути разрешаются относительно session.toml.
4. В api.toml задать `schema = 1`, `[records]` и при необходимости пользовательские секции.
   Неизвестные поля доступны сценарию; известные ограничения проходят валидацию.
5. Не совмещать SESSION_CONFIG с прежним выбором PROFILE или image override.
   session.json остаётся генерируемым дескриптором запуска; вручную заменять его TOML не нужно.
6. record/records — журнал одного вызова сценария, без автоматического экспорта.
   Новый пакет со снимком конфигурации запускать новой версией модуля.

Примеры и ограничения — [API](API.md), [техники](TESTING_TECHNIQUES.md),
[принятые результаты](API_ACCEPTANCE.md).

Lifecycle включает build/prepare, boot/GPIO/strict, full-image A5, ожидаемый ERROR

успешный GPIO. 10/10 — количество этапов, а не десять уникальных аппаратных сценариев.
Ожидаемые ERROR в протоколах сохранены. F030/F103 CMSIS и F411 HAL восстановлены.

Изолированный потребитель — настоящий Git-репозиторий `c8dc670` с gitlink режима
160000 на `972af7c`. Создан из отслеживаемых файлов minimal-consumer; исходный
проект владельца не менялся. Переход legacy → SESSION_CONFIG проверен configure,
build и CTest. Во время аппаратного запуска пакета исходные session.toml и api.toml
были недоступны; сценарий подтвердил config и record/records. Затем файлы возвращены.

Первый Linux host-прогон выявил ожидание старой строки `0.2.0.dev0` в test_public_api;
после замены на `0.2.0rc1` все host-проверки прошли. Начальная ошибка не удалена
из протокола. Ни исправления runtime, ни повторной прошивки из-за этого не потребовалось.

Предыдущая полная кампания: [принятые результаты](API_ACCEPTANCE.md).
Предупреждение Flash F103 сохранено. Orange Pi/SSH на этом этапе не перепроверяется.
Слияние, подписанный тег и публикация — отдельные действия владельца после приёмки.

## Граница публикации и уровни

В состав кандидата не входят локальные исследования и прототипы; проверка
`docs.public` обязательна. Принятые выводы и воспроизводимые проверки —
[API_ACCEPTANCE](API_ACCEPTANCE.md). ТЗ API 0.2.3 уточняет публичные источники и
версию кандидата, без изменения методов. Общая ревизия 0.65 задаёт L0–L6.
Матрица выше покрывает L1–L6. Проверка L0 в закреплённом образе прошла:
версии инструментов и GDB-Python для GCC 13/14/15 подтверждены verify.py.
Пересборка образа и повторная проверка контрольных сумм исходных архивов не выполнялись.
После отделения экспериментальной host-проверки и добавления контроля публикации
финальный публичный набор проверен отдельно; прежние 164 относятся к исходному кандидату.

Финальный чистый публичный снимок: docs/spec/API-spec/links/pairs/public,
format, host и HAL — **8/8 PASS**. Host: Windows 144 PASS/11 skips,
Linux 151 PASS/4 skips (155 тестов). Из 164 исключены 14 тестов локальной модели,
добавлены 5 проверок публикации. Публичный benchmark ядра: 13 форм и 5 границ PASS.
Runtime совпадает с аппаратно проверенным 972af7c; менялись CI/документация/состав
поставки. 278 исключённых файлов побайтно сохранены локально; история Git не переписана.
