# Cortex-M-совместимые МК других производителей

[Документация](index.md) → Совместимые МК · [English](../en/COMPATIBLE_MCU.md)

Модуль проверяет прошивку через GDB-Python и не зависит от производителя МК, если ядро — Cortex-M, а GDB-сервер
умеет подключаться к кристаллу. Клоны и совместимые МК (Artery AT32, GigaDevice GD32, Geehy APM32 и т. п.)
подключаются своим профилем `target.toml` и CMSIS производителя; ядро модуля не меняется. Проверенный пример —
профиль `at32f403a` проверочной прошивки: WeAct AT32F4 Core Board (AT32F403ACGU7), J-Link, 44 сценария.

## Профиль

| Поле | Что указать | AT32F403ACGU7 |
| --- | --- | --- |
| `mcu`, `name` | маркировка кристалла и имя профиля | `AT32F403ACGU7`, `ciat32f403a` |
| `[identity]` | адрес, маска и значение идентификатора из RM. Ширина любая: 12-битный DEV_ID у STM32, 32-битный PID у Artery | `0xE0042000`, `0xFFFFFFFF`, `0x70050347` (RM 27.4.1) |
| `flash_size_address` | 16-битный заводской регистр размера Flash в КиБ (без него аппаратный запуск отклоняется) | `0x1FFFF7E0` (RM 1.3) |
| `breakpoint_limit` | число кодовых компараторов FPB | 6 |
| `fault_handlers`, `core_registers`, `[diagnostic_registers]` | как у ядра Cortex-M того же класса | как у STM32F4 |
| `jlink_device` | имя устройства в J-Link, если сервер — J-Link | `AT32F403ACGU7` |
| `openocd_target` | скрипт OpenOCD; у многих совместимых МК он есть только в OpenOCD производителя | `target/at32f403axx.cfg` |

Стенд для J-Link не меняется; `interface = "JTAG"` в `[probe]` нужен только для кристаллов без SWD. Для OpenOCD
с другим зондом стенд задаёт `interface` (скрипт `interface/*.cfg`) и при необходимости `transport`
([GDB-серверы](BACKENDS.md)).

## CMSIS производителя

Прошивка собирается с заголовками производителя, а не STM32Cube. SDK не копируется в репозиторий: проверочная
прошивка читает его из `AT32_SDK_ROOT`. В CI архив закреплён в `ci/dependencies.lock.json` (URL и SHA-256),
извлекаются только `libraries/cmsis` и `libraries/drivers/inc`. На рабочем компьютере тот же архив ставит

```powershell
python tools/vendor_sdk.py
```

в `%USERPROFILE%/Artery/<пакет>` (Linux — `/opt/Artery/<пакет>`), где его по умолчанию ищет CMake; другое место —
`--destination` и переменная `AT32_SDK_ROOT`. Build manifest записывает пакет Artery так же, как STM32Cube.

## Сценарии

- Общие сценарии модуля (навигация, `ret`, `watch`, `call`, измерения) работают без изменений.
- Сценарии периферии пишутся заново: имена регистров и макросов у производителей разные. У Artery SDK описывает
  регистры битовыми полями, и выражения GDB читают их напрямую: `GPIOC->odt_bit.odt13`, `CRM->ctrl_bit.hicken`.
- Значение регистра целиком сравнивается с константой из позиций битов RM, а не с масками прошивки.
- Регистры только для записи читаются нулём. У AT32F403A это `RTC_DIV` и `RTC_TA`: проверяйте их по читаемым
  `RTC_DIVCNT` и `RTC_CNT`. На STM32F103 те же регистры по RM тоже только для записи, хотя на плате читаются; на
  такое поведение не стоит опираться.
- Константы пересчёта (датчик температуры) берутся из даташита или примера производителя; источник отмечается
  кодом качества в результате (`adc_units.c`: 4 — константы примера производителя).

## Пошагово: подключить свой совместимый МК

Порядок для проекта потребителя; подключение модуля и первый сценарий — как в
[подключении и примере](GETTING_STARTED.md). Значения берутся из RM и даташита кристалла, а не из STM32-аналога.

1. **Отладчик видит кристалл.** Подключитесь без модуля. J-Link Commander:
   `JLink.exe -device <имя> -if SWD -speed 4000 -autoconnect 1` (Linux — `JLinkExe`); имя устройства — из
   списка поддерживаемых устройств SEGGER или окна выбора устройства. Если J-Link кристалла не знает, подключится
   имя ядра (`Cortex-M4`), но запись Flash так, как правило, недоступна: нужен OpenOCD производителя. Для OpenOCD —
   `openocd -f interface/<зонд>.cfg -f target/<цель>.cfg`, затем `telnet localhost 4444`.
2. **Три значения из RM, прочитанные на плате.** Прочитайте их той же сессией (`mem32 <адрес> 1` в J-Link
   Commander, `mdw <адрес>` в OpenOCD, `x/wx <адрес>` в GDB) и сверьте с RM:
   - идентификатор кристалла (у STM32 и многих совместимых — `0xE0042000`) → `[identity]` `address`, `mask`,
     `value`; маска оставляет только биты, которые RM называет идентификатором;
   - заводской размер Flash в КиБ (младшие 16 бит слова) → `flash_size_address`; без такого регистра аппаратный запуск
     отклоняется — для такого МК модуль пока не подходит;
   - `FP_CTRL` (`0xE0002000`): кодовых компараторов FPB = `NUM_CODE` (биты 14:12 — старшие, 7:4 — младшие)
     → `breakpoint_limit`.
3. **Профиль.** Скопируйте профиль STM32 того же ядра (Cortex-M0 — `f030r8`, M3 — `f103c8`, M4 — `f411ce`
   или `at32f403a`) и замените `mcu`, `name`, `flash_start`, `flash_size`, поля шага 2, `jlink_device` или
   `openocd_target`. `fault_handlers`, `core_registers` и `[diagnostic_registers]` совпадают с ядром того же класса,
   если в векторной таблице прошивки те же имена обработчиков.
4. **Стенд.** Сервер и зонд — в файле стенда (`*.local.toml` или `<профиль>-<сервер>.remote.toml`, не в git).
   Для J-Link стенд не меняется; для OpenOCD с OpenOCD производителя укажите его `executable`, при другом зонде —
   `interface` и `transport` ([GDB-серверы](BACKENDS.md)).
5. **Сборка с CMSIS производителя.** Linker script и startup — от производителя или по его карте памяти; SDK держите
   вне репозитория и передавайте путь переменной CMake или окружения, как `AT32_SDK_ROOT` в проверочной прошивке.
6. **Без платы.** `python -B -m stm32_gdbtest doctor --stand <стенд>`, затем `run --prepare-only` первого
   сценария: проверяются профиль, стенд, manifest и ELF.
7. **На плате.** Сначала дым-сценарий: `boot()`, достижение `main`, чтение одного регистра периферии с известным
   значением после сброса. При ошибке identity сравните прочитанное значение с RM: обычно неверны маска или адрес.
   Затем — сценарии периферии по правилам раздела «Сценарии» и несколько повторов подряд, чтобы отсеять
   нестабильность стенда.

## Чего не проверено

Другие семейства совместимых МК, OpenOCD производителей и зонды вроде WCH-Link в режиме ARM — каждый требует
своей приёмки на плате.
