# Экспорт результатов и индекс свидетельств

[Документация](index.md) → Результаты · [English](../en/RESULTS.md)

Доступно в Unreleased. Это внешние host-команды: они читают сохранённые файлы, не запускают GDB,
не обращаются к MCU и не добавляют методов Target. Существующие сценарии менять не требуется.
Для сохранения журнала при запуске включите [захват](API.md#захват-журнала-результатов-unreleased).

## Что именно экспортируется

`record(name, data)` хранит **произвольные данные**, а не только измерения. `name` — метка автора,
без встроенного определения типа. `sequence` — номер записи, не время. Экспорт разделяет три роли:

| Роль | Содержание |
| --- | --- |
| Общий журнал | Все записи sequence/name/data с исходными типами |
| Проекция | Необязательная выборка полей по явному export.toml |
| Индекс | Запуски и файлы: пути, размеры, хеши и целостность, без толкования data |

```python
t.record("adc.sample", {"vdda_mv": 3295})
t.record("fsm.transition", {"from": "idle", "to": "running"})
t.record("diagnostic", {"message": "channel unavailable"})
```

Все три записи сохраняются в общем экспорте. Выбор adc.sample для проекции не удаляет остальные.
Ни единицы, ни время, ни смысл значений не угадываются из имени поля.

## Явный выбор кампании

Создайте selection.json. Пути файлов — относительно отдельно переданного корня свидетельств:

```json
{
  "schema": 1,
  "campaign_id": "board-bringup-001",
  "name": "Initial board checks",
  "runs": [
    {
      "result": "run-001/result.json",
      "stand": "f411-lab",
      "artifacts": {
        "elf": "run-001/firmware.elf",
        "junit": "run-001/junit.xml"
      }
    }
  ],
  "packages": []
}
```

Обязательны schema=1, name и runs; campaign_id без указания создаётся как UUID. packages необязателен;
каждый элемент — `{"path": "input.zip", "sha256": "<64 lowercase hex digits>"}`.
В run обязательны result и stand. artifacts необязателен, роли result/records зарезервированы.
report и сохранённый records.json включаются автоматически; остальные файлы выбираются явно.
Нет сканирования build. Допустимы только относительные POSIX-пути без `..`, обратной косой черты,
двоеточия и symlink в компонентах пути. stand — внешняя метка, не полученный из серийника адрес.

run_id берётся из отчёта. Для старого отчёта допускается `assigned_id` с пометкой identity_source=assigned;
при отсутствии ID строка сохраняется с null и диагностикой. Исходный отчёт не переписывается.
Назначенный ID не создаёт совместимый журнал, если его нет. Повторы case_id сохраняются;
повтор run_id отклоняет всю сборку, конфликт с assigned_id также отклоняется.

## Команды

```text
python -m stm32_gdbtest results export --root build/evidence --selection selection.json --output build/export-001
python -m stm32_gdbtest results export --root build/evidence --selection selection.json --output build/export-002 --config export.toml
python -m stm32_gdbtest results verify --root build/evidence --index build/export-001/index.json --output build/integrity-001.json
```

Каталог export и файл verify должны быть новыми. --config доступен только для export. Экспорт создаёт:

- `index.json` — индекс запусков и явно выбранных файлов;
- `export.json` — источники, общий журнал, проекции, диагностика, описания рядов;
- `records.csv` — run_id_json, case_id_json, sequence, name_json, data_json;
- `measurements.csv` — только при --config; исходное/преобразованное значение и состояние;
- `summary.json` — отдельные коды index/export, итог команды и пределы;
- `selection.json`, `source-hashes.json` и при выборе `export.toml` — параметры и происхождение обработки.

Корень исходных свидетельств не копируется в комплект. Пути индекса по-прежнему отсчитываются от --root,
не от расположения index.json. Это комплект обработки результатов, не замена `pack`.

## Явное описание проекций

```toml
schema = 1

[[series]]
name = "vdda"
record = "adc.sample"
path = ["vdda_mv"]
unit = "V"
scale = 0.001
```

Имя record сравнивается точно. path — массив ключей словаря; пустой массив выбирает весь data;
точка внутри ключа не означает вложенность. name должен быть уникален, unit задаётся явно.
Без scale/offset тип выбранного значения сохраняется, включая bool, строки и контейнеры.
Явная арифметика `value * scale + offset` допускает только int/float (не bool), defaults 1 и 0;
нечисловое значение или неограниченный результат дают error. Выражения Python/GDB не выполняются.

| Состояние | Значение |
| --- | --- |
| value | Значение найдено; raw_value и value присутствуют |
| null | Найден None/null; оба значения null |
| missing | Ключ отсутствует; значения отсутствуют |
| error | Путь проходит через не-словарь или преобразование не выполнено; причина сохранена |

Нет совпадающих записей — явная диагностика. missing/error дают код команды 2; null сам по себе допустим.
Ноль, false и null различаются. JSON сохраняет типы и большие целые. CSV-значения кодируются JSON-литералами;
пустая ячейка означает отсутствующее поле, `null` — явно записанный null. Все произвольные текстовые
ячейки кодируются JSON, включая строки с формулами. Автоконвертация Excel может менять значения;
roundtrip CSV требует JSON-декодирования ячеек. Гарантию сохранения типов даёт JSON, не Excel.
Никакой арифметики/агрегаций над временем и среднего/СКО эта команда не добавляет.

## Целостность и исходы

`ok` — совпадение с опорным хешем, `missing` — файл отсутствует, `changed` — не совпадает,
`unverified` — первый снимок файла без прежнего опорного хеша. Последний может стать baseline
для verify; это не доказательство неизменности до индексации. Хеши не удостоверяют автора.
Связь executed_from с пакетом берётся только из result.package.sha256 и сверяется с выбранными ZIP;
одинаковый ELF не доказывает запуск из пакета. Непрозрачная metadata capture хранится без интерпретации
смысла записей; сам журнал перед экспортом проверяется по схеме, ID и хешу.

Код утилиты — 0 или 2, **не общий вердикт кампании**. FAIL/ERROR сценария не запрещает экспорт исправного
журнала. status/command_code/capture отчёта сохраняются. prepare индексируется без экспорта журнала.
Ошибки источников не скрывают исправные источники; диагностический комплект публикуется с кодом 2.
selection_indices связывает позиции экспортёра с выборкой. Неизвестные сведения старого отчёта — null,
не выдуманные значения. SKIP только читается как отдельный исход; механизм пропуска теста не добавляется.
verify проверяет файлы, не отменяя старых ошибок индекса/сценария. unverified сам по себе не ошибка.

## Пределы и публикация

| Аргумент | По умолчанию |
| --- | ---: |
| --max-runs | 128 |
| --max-files | 2048 |
| --max-input-bytes | 268435456 (256 MiB) |
| --max-output-bytes | 67108864 (64 MiB) |
| --max-series | 32 |

Все значения — положительные целые. JSON входа максимум 16 MiB, export.toml — 64 KiB.
Файлы читаются с потоковым счётчиком; verify считает каждую файловую запись (включая повторы).
Перед проекцией консервативная оценка `bytes(records) * (4 + 3 * series_count)` может отказать раньше,
чем фактический вывод достигнет предела. Реальные записанные байты также ограничены. Это ограничения
внешней утилиты, не API сценария; данные обрабатываются в памяти, пределы не равны лимиту RSS процесса.

Индекс/экспорт читают временный снимок; перед публикацией исходные хеши проверяются повторно.
Обнаруженное изменение, превышение лимита или ошибка записи отменяет публикацию. Это не блокировка
входов: нельзя считать выборку транзакцией при конкурентном изменении всех исходников.
Комплект публикуется переименованием готового каталога на том же разделе; verify публикует готовый
файл hard link, отказывая при неподдерживаемой файловой системе. Прямой частичной записи в итог нет.
Команды используют `<output>.lock` с PID; другие писатели в этот путь не поддерживаются.
После аварийного завершения lock может остаться: убедитесь, что процесс завершён, затем удалите
именно его. Чужая блокировка автоматически не удаляется. Сохранность при отключении питания не гарантируется.
