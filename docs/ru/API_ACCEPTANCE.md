## Пакет 0.3.0

ТЗ API 0.3.6, общее ТЗ 0.68. `profile` (данные проекта, сведения о сборке, case, стенд, GDB) заменяет
`config`/`config_props`; одна `check` с сопоставителями и таблицей, `refused`, `write(rows)` с выражением
в значении, `symbol`, `memory`, `locals`/`arguments`, строки C, навигация (`reach`, `finish`, `step`,
`until`, `watch`, `Point`), `ret`, `call`, `reset`, `execute`. Общий каталог сценариев с девятью
сценариями-примерами; приёмы описаны в [каталоге техник](TESTING_TECHNIQUES.md).

Кампании 05.10.2026, пять плат (F030R8 и F401CC/F411CE/F429ZI — ST-Link/OpenOCD, F103C8 — J-Link),
полный набор: F030R8 48 сценариев, остальные по 50.

Во всех наборах единственный не-PASS — намеренная проверка `timeout` с ожидаемым ERROR. Прогоны на Linux-стенде

`HW_CI_WHO_WRITES`) и занятый порт сервера на хосте стенда (общее ТЗ 0.68). Проверка HAL-фикстуры F030
без платы — `python ci/run_checks.py hal` — PASS. Схемы с пакетом проверяют жизненный цикл: сборку, подготовку,
запуск, строгую идентификацию, полную и частичную прошивку, отказ проверки образа, тайм-аут и восстановление.

## Первый пакет: record/records и config

Историческая приёмка 0.2.0; `config`/`config_props` в 0.3.0 заменены `profile`.


record/records и RecordError дают журнал одного вызова сценария с копиями обычных
Python-значений и атомарным отказом по лимитам. config/config_props дают неизменяемый
снимок выбранных параметров и сведения об их происхождении. session.toml связывает
внешние файлы; SESSION_CONFIG выбирается явно. Старый режим сохраняется.
Экспорт журнала, новые операции стека/контекста и адаптивный планировщик не включены.

## Регрессия затрат журнала

Публичный [benchmark](../../tests/benchmarks/measure_records.py) использует только
реализацию ядра. Запуск из корня: `python tests/benchmarks/measure_records.py build/records-cost.json`.
Для GDB-Python импортировать модуль по пути и вызвать run с путём результата;
ELF, сервер и MCU не нужны. Результаты сохраняются локально.

13 форм: 10/128/1024 пары измерений, списки на 4096/32768 узлов,
текст 65536/524288 байт, Unicode около 65536 байт, словарь 4096 узлов,
глубины 8/32, целые 256/1024 бит. Проверяются также пять точных границ и
атомарное отклонение превышения. После прогрева выполняются 9 серий по 10 операций,
GC включён; сравниваются медианы средних серий записи/чтения. Сохранить базу
принятой версии в той же среде и сопоставить с новой реализацией; ухудшение >2×
расследуется по ТЗ API 6.5. Числа не являются обещанием worst-case latency или RSS.
tracemalloc и размер достижимых объектов измеряются отдельно, вход создан заранее.

Первоначальная интеграция проверена в CPython и GDB14/GDB16: 13 форм и пять границ
в каждом окружении, без выявленного ухудшения >2×. Это свидетельство интеграции,
а не перенос абсолютных времён на другую машину. Контрактные лимиты проверяются
штатными host-тестами records независимо от измерения времени.
