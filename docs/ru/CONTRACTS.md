# ELF/HAL-контракты

[Документация](index.md) → Контракты · [English](../en/CONTRACTS.md)

Сценарий объявляет имена контрактов литерально в `@case(..., contracts=("name",))`.
Определения находятся в `tests/contracts.json` каталога профиля. Незапрошенные
контракты дают `NOT_REQUESTED` в отчёте — это не доказательство совместимости и
не результат SKIP.

## Порядок и разделение ответственности

1. Runner копирует ELF и проверяет build manifest.
2. Загружает только запрошенные контракты. Неизвестное имя или схема — ERROR.
   Для `source_reviews` сравнивает хэши с входами проверенного build manifest.
3. Сохраняет выбранные декларации, SHA-256 реестра и `contract-request.json`.
4. Запускает отдельный batch GDB с этим ELF, выключенным auto-load, без сервера и
   без подключения к цели; внешний предел — 15 с. Проверки используют только
   Symbol/Type/Block и `list`, `info macro`, `macro expand`, `whatis` — без `parse_and_eval`,
   вызовов функций цели и записи памяти.
5. Принимает `contract-result.json` только при PASS, коде выхода 0 и совпадении
   SHA-256 ELF. Ошибка, отсутствие результата или timeout останавливают запуск до
   GDB-сервера.
6. После успешного preflight выполняется аппаратный сценарий с прежними проверками
   identity, Flash, reset, точек останова и завершения. Результаты preflight входят
   в `result.json` и JUnit; журнал — `contract-preflight.log`.

`run --prepare-only` выполняет шаги 1–5 без оборудования; CMake-тест `prepare.<ID>`
делает то же в offline-наборе CTest.

Механизм — [contracts.py](../../stm32_gdbtest/contracts.py); ожидания MCU и HAL — в
профиле, сценарии — у потребителя. Изменение контракта не требует пересборки
прошивки: это ожидание теста, его выбранный снимок сохраняется отдельно от сборки.

## Что задаёт schema 1

- `functions`: глобальные функции, тип возврата и **упорядоченный список** аргументов
  (`name`, `type`). Проверяются число и порядок типов, имена аргументов и их типы в блоке.
- `type_context`: функция из `functions`, в блоке которой разрешаются `fields` и `enums`.
- `fields`: обязательные поля структур и их типы; лишние поля допустимы.
- `enums`: обязательные константы enum и их значения; лишние значения допустимы.
- `macros`: `context` (функция) и `expressions` — см. [HAL-макросы](HAL_MACRO_GUIDE.md).
  Для каждого выражения проверяются определение, раскрытие и тип раскрытия (`whatis` по тексту
  раскрытия, без чтения памяти; макрос командной строки `-DNAME` тоже считается определённым). Если раскрытие ссылается на тип, которого нет в отладочной информации
  (`(DBGMCU_TypeDef *)…`, когда прошивка не использует DBGMCU), контракт даёт ERROR ещё до
  сервера; помогает сборка с `-fno-eliminate-unused-debug-types`. Statement-макросы
  (`do { } while (0)`) не выражения: для них в отчёте `type_note`, это не ошибка.
- `source_reviews`: файл, SHA-256 и `reason` ручного анализа используемого поведения.

Типы аргументов и возврата разрешаются в блоке самой функции. Глобальный
`lookup_type` давал ложное несовпадение `GPIO_TypeDef` между единицами компиляции
C и C++; сравнение строк не решает проблему, поэтому используется равенство GDB Type
в нужном контексте. Поддерживаются именованные типы, `const Type`, `Type *` и `Type * const`;
универсального разбора C/C++ для массивов, шаблонов и указателей на функции нет.

## Границы доказательства

- Перед NULL-инъекцией нужно изучить используемый исходник HAL и закрепить его хэш
  в `source_reviews`. Хэш не обновляется механически ради PASS.
- Наличие сигнатуры не доказывает семантику тела функции, транзитивных заголовков и
  действующих макросов.
- `force_return` пропускает тело функции: такой тест проверяет реакцию вызывающего кода.
- Сигнатура callback не доказывает маршрут IRQ; DWARF-аргумент не доказывает
  доступность значения при halt. Optimized-out и pending-точки проверяются в работе.
- Preflight раскрывает, но не вычисляет выражения макросов. `source_reviews` опираются
  на [build manifest](MANIFESTS.md).

CI проверяет механизм на CI-прошивках, включая 10 отрицательных вариантов
контрактов ([проверки и CI](testing.md)).
[Профильные контракты и offline-регрессия](https://github.com/ViacheslavMezentsev/stm32-hwtest-blackpill/blob/main/docs/HAL_CONTRACTS.md)
остаются у стенда.

## C++: квалифицированные имена и `this` (0.4.2)

В `functions` и `type_context` допустимы `Probe::add`, `Probe::twice` и
`demo::increment`, если `lookup_global_symbol` находит функцию в выбранном ELF.
Это область проверки контрактов, а не новая форма `Target.call()`.

Типы разбираются по уровням: `Probe * const` — константный указатель на изменяемый
объект; `const Probe *` — указатель на константный объект; `const Probe * const`
содержит оба квалификатора. Поддерживается также `Probe const`. Квалификаторы
не отбрасываются; typedef разворачивается при сравнении. Это ограниченный разбор
именованных типов, указателей (разделитель ` *`) и `const`, не общий парсер C++.

Скрытый аргумент `this` явно включается в упорядоченный список аргументов, как он
представлен в DWARF. В проверенном GCC `Probe::add(unsigned n)` требует:

```json
{"returns": "void", "arguments": [
  {"name": "this", "type": "Probe * const"},
  {"name": "n", "type": "unsigned int"}
]}
```

Для `unsigned Probe::read() const` ожидается `this: const Probe * const`;
у статического метода и функции пространства имён `this` отсутствует.
Проверяйте отладочную информацию конкретного ELF: другие компиляторы и оптимизация
могут менять представление. Отсутствующий inline-метод даёт ERROR, а не пропуск.

PASS preflight не доказывает готовность объекта, безопасность вызова или возможность
вызова через `Target.call()`. Для методов используется отдельная техника прямого GDB
на остановленном ядре с известным состоянием объекта. Перегрузки, наследование,
виртуальные вызовы, конструкторы и LTO этим примером не принимаются.

Повторяемая проверка: `tests/renode-startup/run_cpp.py --cxx <arm-g++> --gdb <gdb-py3>
--renode <renode>`. Сначала отдельный batch GDB без inferior, затем Renode;
результаты, отрицательные контракты и хеши входов — `build/cpp-preflight/<run>/`.
Опция `--module-root` позволяет сравнить то же ELF-описание с прежним ядром.
