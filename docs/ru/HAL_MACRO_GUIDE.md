# HAL-макросы в сценариях

[Документация](index.md) → HAL-макросы · [English](../en/HAL_MACRO_GUIDE.md)

Рекомендации основаны на просмотре Exported Macros в заголовках adc, gpio, rcc, tim,
uart пакета CubeF4 V1.28.3, проверке соответствующих определений F1 и опытах на ELF.
Установленные библиотеки не изменяются. Определение берётся из отладочной
информации собранного ELF, а не подставляется из текущего заголовка через
`macro define`.

## Выбор макроса

| Область | Кандидаты для наблюдения | Что учитывать |
| --- | --- | --- |
| RCC | `__HAL_RCC_*_IS_CLK_ENABLED()` | Предикат текущего состояния, не доказательство вызова ENABLE. Проверены GPIOB/C, ADC1, TIM2, DMA1/2. |
| TIM | `__HAL_TIM_GET_AUTORELOAD`, `GET_COUNTER`, `GET_IT_SOURCE`, `GET_FLAG` | ARR проверен на TIM2. CNT меняется во времени; обработчик IRQ может очистить SR к моменту остановки. |
| ADC | `__HAL_ADC_GET_FLAG`, `GET_IT_SOURCE` | Согласовать точку остановки и обработку EOC/OVR; наличие флага не доказывает корректность измерения. Пока каталог кандидатов. |
| GPIO | `__HAL_GPIO_EXTI_GET_FLAG`, `GET_IT` | Возвращают маску, не обязательно 1. Для MODER/CRL нужны поля CMSIS; HAL-предиката режима вывода нет. EXTI здесь ещё не проверялся. |
| UART | `__HAL_UART_GET_FLAG`, `GET_IT_SOURCE` | Учитывать последовательности SR/DR: по комментарию заголовка `CLEAR_PEFLAG` читает SR и DR, и такие чтения очищают состояние. UART в стендах пока не проверен. |

`ENABLE`, `DISABLE`, `SET`, `CLEAR`, `RESET_HANDLE_STATE`, генерация EXTI IRQ и
подобные макросы — действия, а не наблюдения; их допускают только специально
описанные сценарии изменения состояния. Имя `GET` само по себе не гарантирует
безвредности: просмотрите раскрытие, RM, аргументы и побочные эффекты чтения.
Statement-макрос `do { ... } while (0)` не является обычным C-выражением.

## Правила сценария

- Сначала достичь определённой функции или строки, затем вычислять макрос.
- **Контекст — функция из единицы компиляции, где макрос определён.** Макросы GDB
  берёт из отладочной информации конкретного `.c`-файла: если заголовок устройства
  подключён только в `board.c`, остановка в `app_loop` из `app.c` не увидит `RCC` и
  `GPIO_*`. Так ведут себя CI-прошивки: контекст макросов — `board_led_toggle`.
- `Target.evaluate()` использует `gdb.parse_and_eval`. Для масочного результата
  сравнивайте маску или нормализуйте через bool; не приравнивайте любую маску к 1.
- Отдельный `t.check` для каждого условия сохраняет понятную диагностику.
- Предпочитайте CMSIS `_Msk`/`_Pos` необъяснённым сдвигам и маскам; ожидаемые
  значения режима и делителя задаются профилем независимо.
- Не заменяйте физическое ожидание произвольной HAL-константой: на F411
  `ADC_CHANNEL_TEMPSENSOR` содержит служебный флаг, rank должен содержать 18.
- Не объявляйте покрытие периферии по проверке clock-enable: нужны запуск, IRQ/DMA,
  данные, ошибки и наблюдение последствий в приложении.

## Offline-контракт

В `tests/contracts.json` профиля (schema 1) контракт макросов выглядит так:

```json
{
  "macros": {
    "context": "loop",
    "expressions": ["__HAL_RCC_ADC1_IS_CLK_ENABLED()", "RCC_CFGR_HPRE_Msk"]
  }
}
```

Имя контракта указывается в `@case(..., contracts=("clock_macros",))`. Перед
сервером runner запускает отдельный GDB без подключения к MCU: находит функцию
`context` в ELF, выбирает её исходную позицию через `list *address`, проверяет
`info macro` и выполняет `macro expand`. В отчёте сохраняются context, выражение и
раскрытие. Ничего не вычисляется через `parse_and_eval`, регистры не читаются,
функции не вызываются. Отсутствие определения или раскрытия — ERROR до запуска
сервера. Контекст обязателен; наследовать контекст предыдущего контракта нельзя.

Это проверка наличия и раскрытия, **не** доказательство отсутствия побочных
эффектов, полной совместимости HAL или корректности аргументов и типов при
выполнении. Полная грамматика C не проверяется: разрешены имена и простые вызовы с
идентификаторами, числами, `&`, `*`, запятыми и пробелами. Произвольные команды GDB
в декларациях запрещены. Неизвестный вложенный идентификатор и корректность
итогового выражения могут потребовать дополнительных контрактов и аппаратной
проверки. Точное тело макроса не фиксируется как эталон: изменение раскрытия видно
в отчёте, но само по себе не запрещено.
