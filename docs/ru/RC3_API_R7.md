# rc3 R7: диапазоны и бюджет watchpoints

[Документация](index.md) · [English](../en/RC3_API_R7.md)

02.10.2026. Продолжение [R6](RC3_API_R6.md) после `435639d` в
`codex/rc3-api-r1`. Ядро, публичный API, ТЗ и прошивка не изменены.
Используется прежний ELF `7842e8ee9471ec777001a1fcc5be6e4a9625af3883eee7c8a1b15ebbcd6c5552`.
Перенос в ядро требует утверждения владельца.

## Измерения и техники

Стенд: F411CE/ST-Link/OpenOCD0.12.0 native DAP/SWD, Windows, GDB14 и GDB16.
Это ограничения проверенной связки, а не универсальные свойства всех STM32.
Сценарии используют только обычные CPU-доступы к объекту sample.

| Опыт | Наблюдение |
| --- | --- |
| WIDTH | Выровненные области1/2/4/8 байт дают аппаратные read-watchpoint события в sum_bytes. Невыровненные2/4 байта отклоняются при continue |
| CAPACITY | От1 до4 отдельных выровненных word write-watchpoints устанавливаются; пятая отклоняется. Статические слова не изменяются приложением, достижение sentinel подтверждает выполнение |
| SPLIT | Невыровненные2 байта разбиты на1+1, четыре — на1+2+1. Проверяются точное покрытие без лишних байт, hardware-типы, последовательность обращений и выход из sum_bytes |

[Измерения](../../tests/api-experiments/profile/tests/board/test_watch_limits.py),
[разбиение](../../tests/api-experiments/profile/tests/board/test_watch_split.py).

Адрес массива берётся из ELF: sample имеет размер40, bytes начинается по смещению29.
Нельзя считать массив выровненным по выравниванию всей структуры. Для WIDTH
выровненный диапазон может включать соседние поля sample; он всё равно целиком
лежит в этом объекте и пересекается с реально читаемым массивом.

SPLIT наблюдает только нужные байты и проверяет каждый доступ: последовательность
частей0,1 для двух байт и0,1,1,2 для четырёх. Sentinel ставится на process_packet,
до его повторных чтений массива. Такая техника расходует соответственно2 или3
точки вместо одной. Не объявляется универсальным алгоритмом разбиения диапазонов.
Бюджет измерен для отдельных word-точек; расход ресурсов на произвольные выражения,
перекрытия или большие диапазоны может отличаться. FPB, DMA и MMIO не исследовались.

## Отказы и восстановление

Первый FAIL — ошибочное предположение о выравнивании массива. Он произошёл до
установки watchpoints; после него адреса вычисляются из фактической раскладки ELF.
Во второй серии выровненные диапазоны прошли, но первая невыровненная область
дала ERROR: Python получил лишь `Command aborted.`, а причина была в выводе GDB.
Оба первоначальных результата сохранены, после серий прошёл firmware restore.

Теперь каждый continue имеет отдельный локальный журнал GDB. Только наличие
конкретной строки `Could not insert hardware watchpoint N.` позволяет записать
результат `insertion_rejected`; прочие ошибки передаются наружу. Сам `Command aborted.`
недостаточен для классификации. После удаления точек каждый WIDTH/CAPACITY
выполняет reset и положительный контроль: hardware watch на cycles, ожидаемый
идентификатор остановки и значение1. Это проверка очистки плюс reset, не гарантия
продолжения прежнего кадра после отказа.

Успешное создание Python-объекта и hardware-тип не доказывают установку в MCU:
ограничение проявляется при continue. PASS сценария означает, что наблюдения и
контроль восстановления корректны; он не означает поддержку отклонённых диапазонов.
Полные диагностические журналы остаются локально, без персональных путей в сводке.

## Воспроизведение

**Результаты:16/16 запусков WIDTH/CAPACITY и8/8 SPLIT**, по четыре повтора
каждого сценария на GDB14 и GDB16. Во всех WIDTH одинаковая матрица поддержки,
во всех CAPACITY граница4/5; отклонённые диапазоны и точки не объявляются PASS.
Оба исходных FAIL/ERROR сохранены. Все четыре серии завершили restore
HW_BOOT/HW_GPIO PASS. Windows/Linux build/host/prepare:40/40 PASS (38 prepare,
traceability,20 host-регрессий одной группой), документация3/3. Новый C-код не
добавлялся; прежний общий format FAIL не исправлялся. ELF совпадает с R6,
предыдущие аппаратные серии не повторялись. HLA, Linux HW и другие платы не проверялись.

К [команде R1](RC3_API_R1.md#воспроизведение) добавить `--suite r7 --native-stlink`.
Для отдельных серий указать `--test HW_R7_WIDTH --test HW_R7_CAPACITY` или
`--test HW_R7_SPLIT`; без `--execute` выполняется только prepare.
[Обезличенная сводка](../research/rc3-r7-results.json) содержит все попытки,
варианты исходников, конкретные отказы, события и восстановление прошивки.
Журналы — `tests/api-experiments/build/evidence/`.
