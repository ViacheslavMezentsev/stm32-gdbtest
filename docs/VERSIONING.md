# Версии и релизы

Предлагаемый формат — MAJOR.MINOR.PATCH по [SemVer2.0.0](https://semver.org/spec/v2.0.0.html).
Git-теги имеют префикс v. Первый кандидат: **v0.1.0-rc.1**, первый обычный релиз:
**v0.1.0**. До проверки отдельного репозитория/подмодуля теги не создавать.
Текущее 0.1.0.dev0 — версия разработки; export не является выпуском релиза.

Политика проекта до1.0: совместимые исправления →0.1.1; новые функции или изменения
API →0.2.0 с явной миграцией. PATCH не должен ломать API. После1.0: несовместимый
API →MAJOR, совместимые возможности →MINOR, исправления →PATCH. Версии0.x не
означают обещания стабильности1.0. Released tag не перемещается: исправления получают
новую версию. Gitlink потребителя фиксирует SHA, тег удобен для выбора этого SHA.

Источник Python-версии — __version__ в stm32_gdbtest/__init__.py. Для будущего
Python packaging соответствие tag v0.1.0-rc.1 → Python0.1.0rc1; обычный tag v0.1.0
→ Python0.1.0. API_VERSION и JSON/TOML schema номера независимы от версии релиза:
их меняют при изменении соответствующего контракта, не при каждом PATCH.

Перед релизом: проверить host/offline, consumer через настоящий Git submodule,
согласованные HW/recovery, документацию/migration, LICENSE и отсутствие локальных
артефактов. Указать фактическую матрицу проверки и известные ограничения. Обновить
__version__, открыть датированный раздел CHANGELOG, оставить Unreleased для будущего,
создать локальный commit/tag; публикация владельцем. Имя проверить перед публикацией.
