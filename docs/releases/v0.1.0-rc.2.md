stm32-gdbtest 0.1.0-rc.2 — expanded F030 regression and verifiable HAL contracts

DRAFT — do not publish before acceptance and final SHA verification.

stm32-gdbtest implements DDTT: Python scenarios drive GDB to check running firmware
on a separate board. It is neither an MCU simulator nor a firmware test-hook library.
Delivery is a pinned Git submodule.
Python version: 0.1.0rc2; API_VERSION: 1; specification: 0.42 (candidate acceptance pending).

Highlights:
- Fixed CMake 3.25 build manifests without output in compile_commands.json.
- HAL macro preflight checks type availability and expands macros correctly in C++
  and compiler command-line definitions.
- Added the STM32F103CBT6 J-Link device mapping.
- Expanded CMSIS F030 to 18 cases: TIM3/IRQ, ADC/DMA, numeric vectors, RTC,
  Sleep/WFI and selected failure paths.
- Preserved a separate 17-case HAL F030 fixture, negative offline contracts and
  a hardware restoration protocol.
- Added TECH-001…008. Owned directories use tests; legacy Tests remains readable.
  Reconfigure after renaming. Remote stands use remote.toml or *-remote.toml.

Final verification:
PENDING. Prior PASS results apply to revisions stated in their protocols.
Before publication replace this block with actual CI/HW, tested code SHA, backends
and limitations. Do not present rc.1 results as rc.2 acceptance.

Limitations:
F103/F411 CMSIS retain basic boot/GPIO cases; full peripheral migration is incomplete.
HAL F030 CI is GCC13-only; runtime depends on ELF, optimisation, GDB and backend.
RISC-V, QEMU/Renode, multi-node, external power control and pip delivery are not included.
The debugger affects execution; case counts do not measure code coverage.
