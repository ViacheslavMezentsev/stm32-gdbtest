stm32-gdbtest 0.6.0 — длительные сценарии, C++ и управляемые воздействия

Описание выпуска; публикация владельцем после CI итогового SHA и land.

- Журнал и отчёт: api schema 3 с квотами и политиками `error`/`truncate`, независимый учёт проверок,
  явная неполнота в читателях, экспорте и сводках; lossless result schema 2 и `console="summary"`.
- Первичные ошибки исполнения и MMIO отделены от аудита; cleanup подтверждает остановку независимо от журнала.
- `call` для C++: однозначные namespace/static, явный `this` и точная `signature`, квалификаторы объекта,
  `Pointer`/`Reference` с проверкой диапазонов SRAM, невиртуальные базы; отказы — до исполнения.
- Нейтральные примеры воздействий с подтверждением потребления: подмена в SRAM и через `ret`, модель GPIO,
  буфер пакета с вызовом обработчика; logical-time, counter-cost, stateful-buffer, external-capture.
- Офлайн-импорт ROS1 bag v2 с отдельным анализом опор времени.
- `run --interactive`: пошаговый проход сценария в VS Code (debugpy) без ограничения по времени; результаты
  отдельно в `interactive-runs`, сценарий и `timeout_s` не меняются.
- Навык отчётов в дизайне выпускных PDF, объяснения пакетов «правильно/неправильно», техники TECH-021–026.

Пакет 0.6.0; API_VERSION=3; api schema 3 (schema 1/2 совместимы), result schema 2, records 1/2,
target schema 1–3 без изменений. Общее ТЗ 0.123, ТЗ API 0.3.36. Переход с 0.5.x —
[VERSIONING](../ru/VERSIONING.md#переход-к-060): новое включается явно.

Приёмка A8 на кандидате `6530395`: офлайн Windows и Linux (host 879), Renode/QEMU и примеры A1–A6 на обеих ОС,
шесть MCU (MMIO 141/141, async и `call` 90/90, VTOR/FPB F411 12/12, HAL F030 41 этап, новый комплект C++/журнала/
подмены 48/48), CI-прошивки на пяти STM32 и пакет — локально и через удалённый стенд по SSH, потребители BluePill/BlackPill на
платах (72/72), интерактивный режим на F411/F103. Платы восстановлены по копиям Flash. Сводка и ограничения — [матрица A8](../development/release-060-acceptance.md).
Компактный обзор и технический отчёт кампании (PDF) приложены к выпуску.

Ограничения: эффект воздействий на реальных микроконтроллерах стендов — только программные входы (SRAM, `ret`); физические сигналы и модель
GPIO — Renode. Точка останова внутри `call` — Renode. AT32 в маршруте CI-прошивок не проверялся;
интерактивный режим — локальные стенды OpenOCD на Windows. ST-LINK GDB Server, SEGGER GDB Server и st-util
сохраняют прежнюю приёмку.

stm32-gdbtest 0.6.0 — long scenarios, C++ and controlled substitutions

Release description; the owner publishes after final-SHA CI and land.

- Journal and report: api schema 3 with quotas and `error`/`truncate` policies, independent check accounting,
  explicit incompleteness in readers, exports and summaries; lossless result schema 2 and `console="summary"`.
- Primary execution and MMIO errors are separated from the audit; cleanup confirms the stop independently of the journal.
- `call` for C++: unambiguous namespace/static functions, explicit `this` and exact `signature`, object qualifiers,
  `Pointer`/`Reference` with SRAM range checks, non-virtual bases; refusals happen before execution.
- Neutral substitution examples with confirmed consumption: SRAM and `ret` substitution, a GPIO model, a packet buffer
  with a handler call; logical-time, counter-cost, stateful-buffer, external-capture.
- Offline ROS1 bag v2 import with a separate analysis of time anchors.
- `run --interactive`: step through a scenario in VS Code (debugpy) with no time limit; results go to a separate
  `interactive-runs`, the scenario and its `timeout_s` are unchanged.
- The report skill follows the release PDF design; right/wrong explanations of the packages; techniques TECH-021–026.

Package 0.6.0; API_VERSION=3; api schema 3 (schemas 1/2 compatible), result schema 2, records 1/2,
target schemas 1–3 unchanged. General specification 0.123, API specification 0.3.36. Moving from 0.5.x:
[VERSIONING](../en/VERSIONING.md#moving-to-060) — new features are opt-in.

A8 acceptance on candidate `6530395`: offline Windows and Linux (879 host tests), Renode/QEMU and the A1–A6 examples on
both systems, six MCUs (MMIO 141/141, async and `call` 90/90, VTOR/FPB F411 12/12, HAL F030 41 stages, a new
C++/journal/substitution kit 48/48), CI firmware on five STM32 boards and a package — locally and through the remote SSH stand, the
BluePill/BlackPill consumers on boards (72/72), interactive mode on F411/F103. Boards were restored from Flash copies. Summary and limitations:
[A8 matrix](../development/release-060-acceptance.md) (Russian). The compact overview and the technical report of the
campaign (PDF) are attached to the release.

Limitations: substitution effects on real microcontrollers are verified for software inputs only (SRAM, `ret`); physical signals and the
GPIO model are Renode only. A breakpoint inside `call` is verified in Renode only. AT32 was not run on the CI firmware route; interactive mode is verified on local OpenOCD stands on Windows. ST-LINK GDB Server, SEGGER GDB Server and
st-util keep their earlier acceptance.
