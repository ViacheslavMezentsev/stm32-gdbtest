stm32-gdbtest v0.3.0-rc.1 — расширенный API сценариев

Локально подготовленный кандидат, ещё не опубликован.
Модуль проверяет работающую прошивку через GDB-Python. Поставка — закреплённый
Git-подмодуль. Python 0.3.0; API_VERSION=1; ТЗ API 0.3.0.

Главное:
- Навигация: reach с ожиданием, resume, step, until, finish и объект Point.
- Вызовы: ret с типизированным значением, call функций прошивки, reset и execute команд отладчика.
- Чтение: read/write объектов, evaluate выражений, registers кадра, frames с пределом.
- Представления: settings и sources как неизменяемые отображения config и config_props.
- Декоратор @test как алиас @case; сборщик принимает оба имени.
- Ключи api.toml: frames.limit, call.depth, call.args_max, execute.output_limit_chars, reset.command.

Аппаратная проверка (пять стендов проекта):
F030R8/OpenOCD, F103C8/J-Link, F401CC, F411CE, F429ZI — сценарии HW_CI_RET_VALUE,
HW_CI_CALL, HW_CI_EXECUTE, HW_CI_RESET, HW_CI_SETTINGS, HW_CI_EVALUATE,
HW_CI_REGISTERS, HW_CI_FRAMES, HW_CI_WATCH и HW_CI_TEST_ALIAS пройдены; регрессии
HW_CI_NAVIGATION, HW_CI_READ_WRITE, HW_CI_RET_RECEIVER и HW_CI_MEASUREMENT_SERIES зелёные.
Хост-набор: см. итог CI на коммите выпуска; полный набор включает firmware и hal.

Ограничения:
Указатели, объекты шире восьми байт и значения с плавающей точкой нельзя наблюдать.
Часть связок не передаёт событие остановки для точки наблюдения: остановка помечается
inferred. finish() не публикует промежуточную копию стека. Стенды с native DAP не
использовались. Результаты MCU не означают метрологическую калибровку.

stm32-gdbtest v0.3.0-rc.1 — extended scenario API

Locally prepared candidate, not published yet.
The module verifies a running firmware through GDB-Python. Delivered as a pinned Git
submodule. Python 0.3.0; API_VERSION=1; API specification 0.3.0.

Highlights:
- Navigation: reach with a condition, resume, step, until, finish and the Point object.
- Invocation: ret with a typed value, call of firmware functions, reset and execute of debugger commands.
- Reading: read/write of objects, evaluate of expressions, registers of a frame, frames with a limit.
- Views: settings and sources as the immutable mappings behind config and config_props.
- The @test decorator as an alias of @case; the collector accepts both names.
- api.toml keys: frames.limit, call.depth, call.args_max, execute.output_limit_chars, reset.command.

Hardware verification (five stands of the project):
F030R8/OpenOCD, F103C8/J-Link, F401CC, F411CE and F429ZI — the scenarios
HW_CI_RET_VALUE, HW_CI_CALL, HW_CI_EXECUTE, HW_CI_RESET, HW_CI_SETTINGS,
HW_CI_EVALUATE, HW_CI_REGISTERS, HW_CI_FRAMES, HW_CI_WATCH and HW_CI_TEST_ALIAS pass;
the regressions HW_CI_NAVIGATION, HW_CI_READ_WRITE, HW_CI_RET_RECEIVER and
HW_CI_MEASUREMENT_SERIES stay green. Host suite: see the CI result on the release
commit; the full set includes firmware and hal.

Limitations:
Pointers, objects wider than eight bytes and floating-point values cannot be watched.
Some combinations deliver no stop event for a watch point, so the stop is marked
inferred. finish() does not publish the staged stack copy. Native DAP stands were not
used. MCU results are not a metrological calibration.
