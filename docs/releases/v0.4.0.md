stm32-gdbtest 0.4.0 — результаты сценариев, SKIP и очищенный API

Черновик сообщения выпуска. Не использовать для тега или GitHub Release до замены
раздела «Итоговая проверка» фактической матрицей на выпускном SHA.

Python 0.4.0; API_VERSION 2; ТЗ API 0.3.12; общее ТЗ 0.77. Схемы TOML/JSON не изменены.

Главное:
- `skip(reason)` завершает неприменимый сценарий с причиной, сохраняет записи и даёт
  отдельный исход в JSON/JUnit/CTest. В `run_hw` пропуск принимается только по явному списку.
- Захват `records.json` включается через `session.toml`; внешние `results export`,
  `results verify` и `results report` создают переносимые свидетельства и автономную
  сводку JSON/HTML с переключением темы и подробности.
- Удалены `value`, `fields`, `set_value`, `force_return`. Для миграции применяются
  `read`/`evaluate`, `check(rows)`, `write`, `ret`; API_VERSION увеличен до 2.
- `evaluate(..., as_type=str)` читает массив `char[]` без известного размера по адресу
  до NUL с пределом 256 байт; исправлено сравнение кадра `reach` для C++-сигнатур
  с внешними одинарными кавычками GDB.
- Добавлены примеры событий и интервалов, ожидания watchpoint, инъекции и отдельный
  пример C++ Og/O2. Каталог техник поясняет ограничения цепочки кадров watchpoint
  и начального SP на границе SRAM.
- Проверочная прошивка содержит профиль AT32F403A; расширены настройки стенда,
  переносимость инструментов и соглашение об именах удалённых профилей.

Миграция с 0.3.0: прямые вызовы четырёх удалённых методов дают AttributeError;
пересмотрите типы результатов и эффекты записи при замене. Локальные файлы стендов
переименуйте в `<profile>-<backend>.remote.toml`; старые имена больше не покрываются
правилом `.gitignore`. `@case` и `@test` сохраняются.

Итоговая проверка: ОЖИДАЕТСЯ. Нужны SHA, CI Docs/Offline/Hardware, версии GDB/GCC,
матрица плат и backend, восстановление образов, а также проверка потребителя с
настоящим Git-подмодулем. Отдельные опыты на прежних SHA не являются приёмкой выпуска.

Ограничения: аппаратный CI проверяет жизненный цикл, а не полный набор сценариев;
SKIP не отменяет уже сделанных действий; запись внешним DMA не обнаруживается
точкой наблюдения ядра. Экспериментальные `bits`, `each`, `predicate`, SVD и дерево
зависимостей в этот выпуск не входят.

stm32-gdbtest 0.4.0 — scenario results, SKIP and a cleaned API

Draft release message. Do not use it for a tag or GitHub Release until the Final
verification section contains the actual matrix at the release SHA.

Python 0.4.0; API_VERSION 2; API specification 0.3.12; general specification 0.77.
TOML/JSON schema versions are unchanged.

Highlights:
- `skip(reason)` ends an inapplicable scenario with a reason, preserves records and
  reports a distinct JSON/JUnit/CTest outcome. `run_hw` accepts skips only by explicit ID.
- Opt-in `records.json` capture through `session.toml`, plus external `results export`,
  `results verify` and `results report` for portable evidence and standalone JSON/HTML
  summaries with theme and detail controls.
- Removed `value`, `fields`, `set_value`, `force_return`. Migrate to `read`/`evaluate`,
  `check(rows)`, `write`, `ret`; API_VERSION rises to 2.
- `evaluate(..., as_type=str)` reads a zero-sized GDB `char[]` from its address up to
  NUL within 256 bytes; `reach` now compares C++ frames correctly when GDB wraps
  a signature in single quotes.
- Event/interval, watchpoint-wait and injection scenarios and a standalone C++ Og/O2
  example. The techniques catalogue explains watchpoint frame and initial-SP limits.
- The check firmware has an AT32F403A profile; stand settings, tool portability and
  remote profile naming have been extended.

Migration from 0.3.0: direct calls of the four removed methods raise AttributeError;
review result types and write effects when replacing them. Rename local stand files
to `<profile>-<backend>.remote.toml`; older names are no longer covered by `.gitignore`.
`@case` and `@test` remain available.

Final verification: PENDING. Record the SHA, Docs/Offline/Hardware CI, GDB/GCC
versions, board/backend matrix, image recovery and a consumer using the real Git
submodule. Earlier experiments at other SHAs do not constitute release acceptance.

Limits: hardware CI exercises the lifecycle rather than the full scenario suite;
SKIP does not undo actions; core watchpoints cannot observe external DMA writes.
Experimental `bits`, `each`, `predicate`, SVD and dependency trees are excluded.
