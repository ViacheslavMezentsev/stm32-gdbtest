## stm32-gdbtest 0.6.1: порядок в документации и исправления

- Диагностика после FAIL сохраняет xPSR на любом GDB-сервере (`xPSR` или `xpsr`), значение регистра — без знака.
- Карта документации по разделам; свидетельства по платам и рецепты перенесены в `docs/evidence` и `docs/guides`, внешние ссылки на старые адреса сохранены указателями.
- Навыки согласованы с 0.6.0: report, coverage и renode в общей таблице и маршрутах; новая техника TECH-027 — контекст исключения через SCB.ICSR.
- Копия `tools/ddtt_coverage.py` без пакета `stm32_gdbtest` рядом сообщает об этом вместо трассировки.

API_VERSION=3, схемы и методы не меняются: сценарии и конфигурации 0.6.0 работают как есть. Ссылки на
перенесённые документы обновите при закреплении на теге. Проверено без плат на Windows и Linux;
диагностика после FAIL — на F103C8 с OpenOCD 0.12.0, сервер xPack (`xpsr`) отдельно не проверялся.

## stm32-gdbtest 0.6.1: documentation order and fixes

- Diagnostics after a FAIL keep xPSR on any GDB server (`xPSR` or `xpsr`); the register value is unsigned.
- The documentation map is organised by section; board evidence and guides moved to `docs/evidence` and `docs/guides`, with pointer pages kept at old addresses that are linked from outside.
- Skills aligned with 0.6.0: report, coverage and renode in the common table and routes; new technique TECH-027 — the exception context through SCB.ICSR.
- A copy of `tools/ddtt_coverage.py` without the `stm32_gdbtest` package next to it says so instead of printing a traceback.

API_VERSION=3, schemas and methods are unchanged: 0.6.0 scenarios and configurations work as they are.
Update links to moved documents when you pin the tag. Verified without boards on Windows and Linux;
diagnostics after a FAIL on F103C8 with OpenOCD 0.12.0; the xPack server (`xpsr`) was not checked separately.
