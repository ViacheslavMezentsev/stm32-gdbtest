stm32-gdbtest 0.5.0 — API 3: живое окно, MMIO/SVD, эмуляторы

Описание выпуска; публикация владельцем после CI итогового SHA и land.

- API_VERSION=3: единый диспетчер навигации; в `async def` навигация, `call`, `wait` и `halt`
  ожидаются через `await`, `resume(sync=False)` открывает живое окно. Обычные `def` сохраняют синхронную форму.
- Ограниченный `call` с таймаутом; скрытые вызовы функций в выражениях отклоняются.
- `Target.mmio.read/write`: регистры по снимку SVD (`[mmio] svd`) с проверкой прав и эффектов, без скрытых
  обращений; капсула конфигурации schema 2 переносит SVD в пакет.
- Backend Renode и QEMU (target schema 3) для опытов без платы.
- Офлайн-команда `inspect`; DDTT-экспорт HTML/LCOV/Cobertura и квалификация условий снимками допуска.
- Пример наблюдателя VTOR/FPB, навык квалификации HSE, навыки в формате Agent Skills и методология TTDD.
- README сокращён по новым правилам; страница стендов со схемами плат.

Пакет 0.5.0; API_VERSION=3, target schema 3 (аппаратные schema 1/2 совместимы), капсула конфигурации 1/2.
Общее ТЗ 0.114, ТЗ API 0.3.23. Переход с 0.4.x — [MIGRATION_050](../ru/MIGRATION_050.md).

Приёмка P5b на итоговом коммите и его предшественнике (правило 4 матрицы): офлайн Windows и Linux
(Docker 26/26), Renode/QEMU на Windows и Linux, шесть MCU (MMIO 141/141, async и `call` 90/90,
VTOR/FPB F411 12/12, HAL F030 41 этап), удалённый стенд по SSH (пять STM32 и пакет), потребители
BluePill и BlackPill на платах (72/72). Сводка и ограничения — [матрица P5](../development/release-050-acceptance.md).

Ограничения: точка останова внутри `call` проверена только в Renode; удалённый J-Link не проверялся (AT32 по SSH);
ST-LINK GDB Server, SEGGER GDB Server и st-util сохраняют прежнюю приёмку; сборка потребителей проверена на Windows.

stm32-gdbtest 0.5.0 — API 3: live window, MMIO/SVD, emulators

Release description; the owner publishes after final-SHA CI and land.

- API_VERSION=3: one navigation dispatcher; in `async def` navigation, `call`, `wait` and `halt` are
  awaited, and `resume(sync=False)` opens a live window. Ordinary `def` scenarios keep the synchronous form.
- Bounded `call` with a timeout; hidden function calls inside expressions are refused.
- `Target.mmio.read/write`: registers from an SVD snapshot (`[mmio] svd`) with access-right and effect checks
  and no hidden accesses; configuration capsule schema 2 carries the SVD into the package.
- Renode and QEMU backends (target schema 3) for experiments without a board.
- Offline `inspect` command; DDTT export to HTML/LCOV/Cobertura and condition qualification with tolerance snapshots.
- VTOR/FPB observer example, HSE qualification skill, skills in the Agent Skills format and the TTDD methodology.
- Shorter README under new rules; a stands page with board drawings.

Package 0.5.0; API_VERSION=3, target schema 3 (hardware schemas 1/2 compatible), configuration capsule 1/2.
General specification 0.114, API specification 0.3.23. Moving from 0.4.x: [MIGRATION_050](../en/MIGRATION_050.md).

P5b acceptance on the final commit and its predecessor (matrix rule 4): offline Windows and Linux
(Docker 26/26), Renode/QEMU on Windows and Linux, six MCUs (MMIO 141/141, async and `call` 90/90,
VTOR/FPB F411 12/12, HAL F030 41 stages), a remote SSH stand (five STM32 and a package), and the BluePill and
BlackPill consumers on boards (72/72). Summary and limitations: [P5 matrix](../development/release-050-acceptance.md) (Russian).

Limitations: a breakpoint inside `call` is verified only in Renode; remote J-Link is not verified (AT32 over SSH);
ST-LINK GDB Server, SEGGER GDB Server and st-util keep their earlier acceptance; consumer builds are verified on Windows.
