# A3.1 — строгая полнота

Согласовано 28.10.2026. Только строгий режим; on_limit/truncate отложены до A3.2.
Контракт: [API](../../ru/API.md#полнота-в-строгом-режиме-a31-кандидат-060).

## Проверки и ожидаемые результаты

Host: независимый FAIL без строки, перехваченный отказ журнала, исчерпание резерва,
валидация счётчиков/типов/границ, fallback без коллекций, полные старые файлы.
Renode Windows/Linux: длинные серии, штатный live timeout/halt, потеря records при
живом окне и VERIFIED cleanup; потеря строки FAIL; повтор после отказа.
Ожидаемые ERROR и FAIL не переименовываются в PASS; итог кампании проверяет именно их.
Без плат. Политика полного процесса/диска не обещает безусловного восстановления отчёта.

## Разделение лимитов

Настраиваемые budgets records отличаются от фиксированных защитных лимитов файлов,
читателей, коллекций и сводок. Перед A3.2 отдельно согласовать вынос пользовательских
квот, диапазоны и транспорт конфигурации; A3.1 не меняет численные лимиты.

## Статус

Host Windows/Linux, docs и 36 ожидаемых исходов Renode на каждой ОС проверены.
Последнее усиление проверки согласованности счётчиков проверяется на host и повторным
чтением сохранённых результатов Renode; сценарии/транспорт от этого не меняются.
Намеренные FAIL/ERROR сохранены, аппаратная приёмка и GitHub CI не подменяются.
