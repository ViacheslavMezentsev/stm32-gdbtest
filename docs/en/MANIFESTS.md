# Compatibility and build provenance metadata

[Documentation](index.md) → Manifest · [Русский](../ru/MANIFESTS.md)

The GDB API presence is checked before the client connects, ELF contracts before the
server. Both mechanisms check selected preconditions, not the whole MCU and HAL
compatibility.

## Runtime manifest (schema 1)

The `compatibility` block is added to `result.json` and the JUnit system-out for
PASS, FAIL and ERROR, including a refusal before the server starts. The older
top-level `gdb_version` and `python_version` fields are kept. The source of each value
is stated in `evidence`; an unavailable value is `null` with a reason, never a guessed
version. Only the server version, debugger firmware and API tokens are extracted from
`server.log`: whole lines, paths and serial numbers are not copied into this block.
Other diagnostic logs are not scrubbed of local data.

`scope: runtime-only` refers to the `compatibility` block; build information is in the
separate `build_manifest`. `compatibility.build.provenance` shows whether the manifest
passed the binding check against the ELF and `target.toml`. A `session.json` without a
manifest path is supported with an explicit `unavailable`; sessions generated by CMake
include the manifest. An unrecognized banner leaves the metadata unavailable and does
not change the scenario result; a missing required GDB API is an infrastructure ERROR.

## Build manifest (schema 1)

Linking the firmware target creates `build/<preset>/hwtest/build-manifest.json`. The
implementation targets Ninja and one firmware target and works on Windows and Linux
(compiler commands are split by the rules of the host OS). CMake enables
`compile_commands.json`; the POST_BUILD step reads `ninja -t deps`, requires the VALID
state and checks that inputs did not change after the object was compiled. For a plain
`.s` without dependencies the file itself counts; `.include`, `.incbin` and `#include`
in assembler are rejected for now. Changing the manifest script, `target.toml` or a
tracked input triggers a relink.

Contents:

- SHA-256 of the ELF and `target.toml`; hashes of objects and of the used C/C++
  sources and headers, startup, IOC, YAML and the profile linker script;
- compiler name, hash and version; selected define, ABI, optimization and debug flags;
  the hash of the full command without publishing personal paths;
- the STM32Cube package name separately from the numeric HAL and CMSIS version
  declarations with the source file and its hash — literals are read, the
  preprocessor is not run. When HAL and CMSIS do not come from an `STM32Cube_FW_*`
  package (for example Arduino Core STM32), the package list is empty and the
  versions hold only the literals found; this is not an error.

The runner copies the ELF and compares its SHA-256 and the current `target.toml` with
the manifest. A mismatch, a missing file or an unsupported schema gives ERROR before
`objcopy`, GDB and the server. The accepted manifest is copied into the run directory,
`result.json` and JUnit. Sources and STM32Cube are not re-read during the run: the
report describes the saved build. For new sessions run configure and build first.

Limits of the evidence: this is a post-link snapshot, not a provenance attestation of
the binary. It needs reliable timestamps, no concurrent editing and an unchanged
compiler installation between compilation and the snapshot; after replacing the
compiler do a clean rebuild. Not all linker flags or the contents of prebuilt libraries
are recorded. Effective conditional HAL macros are not evaluated. The IOC hash does not
prove the CubeMX generation matches it. The SHA check is not a digital signature.
Personal paths are not written to the manifest, but other logs may contain them.

## Image layout

The list of load sections is extracted from the verified ELF snapshot before the
server, passed to the agent and reflected in `image_verification`; the build manifest
schema does not change. Full mode additionally records `image_policy.source_sha256`,
`bin_sha256` and `program_elf_sha256`. The image policy is a separate input, not part
of the build manifest; the source ELF is not modified. See [images and CRC](IMAGES.md).
