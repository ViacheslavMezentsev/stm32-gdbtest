# A2.3 — проверяемые сводки и уровни представления

Контракт принят владельцем 28.10.2026; реализация к 0.6.0 в текущей накопительной ветке.

## Граница

Хранение full/compact не меняется. console=summary добавляет представление,
full/failures сохраняют смысл; default full. Полные исходные события обязательны.
Summary-only storage, выборочное удаление и truncate не входят в A2.3.

## Источники и интерфейс

`report_summary.build(result_path)` читает сохранённые result/records общими читателями,
проверяет источники и не обращается к GDB. `write` атомарно публикует summary.json,
`read` пересчитывает и сверяет его, включая JSON-типы. CLI `python -m
stm32_gdbtest.report_summary result.json [--verify]` строит или проверяет сводку.
Схема 1, derived=true, относительные ссылки и SHA-256 источников. При неудачном
перестроении старый файл не используется; источник нельзя перезаписать выходом.

## Смысл

Исход сценария, capture, cleanup, код команды и состояние анализа разделены.
Complete — источники доступны для представления; partial — нет records, есть аудит
или недостаточны сведения о generation. Unavailable — ошибка построителя/публикации,
отдельный summary_error и код команды 2; исход сценария не меняется. Ни одно из этих
состояний само по себе не даёт подтверждение DDTT. Проверка partial-сводки может
завершиться кодом 0, подтверждая корректность именно частичного представления.

Группы checks считают все записи, включая средний FAIL; разные ожидания помечены.
Группы отказов и ссылки на отказы приоритетны. Для прочих коллекций failed=null:
количество mutations не доказывает успешность действия или восстановления.
Отсутствующая коллекция — not_recorded. Пользовательские измерения не усредняются.
Вид операции, исход и поколение execution берутся из records, не из runtime-сводки;
неизвестное поколение не выдумывается, wait-timeout не закрывает окно. Opened=false
при closed явно означает отсутствие записанного начала, а не полное измеренное окно.

## Бюджеты

100 отображаемых групп на коллекцию, 20 ссылок на группу, 100 окон; точные общие
счётчики и числа omitted. Подписи/диагностика: preview 256 символов, тип, shortened и
хеш полного текста. Файл — 1 MiB, чтение источников по бюджетам A2.2. Эти пределы
ограничивают представление, не обещают постоянный RSS построителя. Переполнение
явно ошибочно, исходные данные не усекаются.

## Проверки без плат

Host: серии 10000, средний FAIL, разные ожидания, неизвестный исход, пропущенные или
повреждённые источники, поколения, пассивный timeout, устаревшая и изменённая сводка,
JSON-типы, лимиты, отказ публикации, импорт в отдельном процессе и защита источника.
Renode Windows/Linux: 26 ожидаемых исходов, сравнение полных коллекций всех уровней,
повтор после отказа, ошибка хранилища, проверка сводок через общий офлайн-путь.
Методы API и модель MCU не расширены; аппаратная приёмка этим не заменяется.

Публичные инструкции: [API RU](../ru/API.md#сводки-и-уровни-вывода-a23-кандидат-060),
[API EN](../en/API.md#summaries-and-output-levels-a23-060-candidate).

## Итог локальной приёмки 28.10.2026

Host Windows/Linux — 763 теста; 17 регрессий сводок. Renode 1.17 — 26 ожидаемых
исходов в каждой ОС. Намеренные FAIL/ERROR сохранены. Сопоставлены полные коллекции
result и выполнены 32 сравнения логических records для длинных серий и среднего
отказа: все совпали между уровнями вывода. Документы: strict оба ТЗ, ссылки,
переводы и фильтры Pages. Дизайн Pages не менялся, публикация не выполнялась.

Первый запуск выявил цикл импорта reports → report_summary → result_capture;
исправлен отложенным импортом построителя и закреплён проверкой импорта в новом
процессе. Исходные журналы отказов сохранены локально. Проблемы матрицы ТЗ устранены
до итоговой проверки. Это не аппаратная приёмка и не GitHub CI итогового SHA.
