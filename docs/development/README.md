## Три документа планирования

- ROADMAP — направления и крупные вехи примерно до конца 2026 года.
- TODO — компактная памятка текущих тактических действий. Единая таблица, явные
  критерии завершения; запись обновляется на месте, а не размножается по датам.
- TODO_ARCHIVE — история; прежние статусы не являются текущими поручениями.
  До подготовки 0.5.0 и завершённые записи подготовки разделены.

## Обязательный перевод

Шесть единиц документации поддерживаются RU/EN в одном изменении:

1. README.md ↔ README.en.md — фасад проекта.
2. CHANGELOG.md ↔ CHANGELOG.en.md — опубликованные изменения.
3. docs/ru/index.md ↔ docs/en/index.md — карта документов.
4. docs/ru/DDTT.md ↔ docs/en/DDTT.md — метод DDTT.
5. docs/ru/API.md ↔ docs/en/API.md — общий интерфейс, CLI/CMake и миграция.
6. Всё дерево docs/ru/api/ ↔ docs/en/api/ — **все** карточки и подстраницы API.

Список проверяет ci/doc_policy.py. При добавлении новой карточки перевод обязателен.
Объяснение публичного API нельзя спрятать в русскоязычный план: контракт/миграция
должны попасть в API и карточки на двух языках. ТЗ остаются русскими.

Остальное сопровождение можно вести на русском. Существующие английские версии
сохраняются как дополнительные материалы, но автоматически актуальными не считаются;
при расхождении источник — русская версия. Новые пары вне списка необязательны.
Для навыков вход SKILL.md остаётся русским по принятой структуре; перевод ресурсов
допустим по необходимости. Не удалять существующие переводы ради сокращения.

## Оформление README

README — фасад проекта; правила согласованы владельцем к выпуску 0.5.0.

1. Объём — до 110 строк в каждой языковой версии; RU и EN совпадают по разделам.
2. Только текущее состояние: прошлые выпуски, миграции и удалённые методы — в CHANGELOG,
   docs/releases и MIGRATION_*; в README допустима ссылка на версии и изменения.
3. Бейджи только живые: CI (Docs, Offline) и последний выпуск. Счётчики кейсов, даты прогонов
   и метрики кампаний не размещаются; результаты — ссылкой на STATUS и API_ACCEPTANCE.
4. Порядок разделов: что это (2–3 предложения) → как это работает (схема mermaid без смены
   стиля и примеры) → быстрый старт → возможности (до 6 строк) → ограничения (до 5 строк) →
   документация (одна строка-указатель) → лицензия.
5. Два примера: синхронный `def` и асинхронный `async def`, на текущем API, комментарий на
   каждой строке на языке версии, перед ними одна фраза о различии. Примеры выбираются из
   проверенных сценариев и могут быть укорочены; символы прошивки помечаются как условные.
6. Без деталей реализации: состав каталогов, модули пакета и параметры backend — в docs/*/index.md
   и API.md.
7. Ссылки — на карту документации, GETTING_STARTED, DDTT, навыки, стенды, STATUS, VERSIONING,
   CHANGELOG и ТЗ; остальное — через карту.

Объём, совпадение разделов RU/EN и отсутствие устаревших бейджей проверяет ci/doc_policy.py.

## Разделы docs и порядок переноса

Сейчас добавлен docs/development/ для правил сопровождения. Действующие пути
справочников/ТЗ сохраняются. Целевая группировка новых материалов:

| Каталог | Содержание |
| --- | --- |
| docs/ru/api, docs/en/api | Справочник API, обязательный перевод |
| docs/ru, docs/en | Устойчивые точки входа: API, DDTT, index; старые ссылки сохраняются |
| docs/development | Правила работы, планы приёмки и сопровождение на русском |
| docs/guides | Рецепты: стенды, GDB-серверы, CI, эмуляторы, сопровождение (RU/EN) |
| docs/evidence | Свидетельства по платам и сводки приёмки (RU/EN), без локальных данных |
| docs/releases | Выпускные материалы |
| docs/archive | История памятки и происхождение начального экспорта, не текущие инструкции |

Карта документации (docs/ru/index.md и docs/en/index.md) ссылается на каждую страницу своего
языка: страницы верхнего уровня — прямой ссылкой, вложенные (api/, backends/) — через ссылки
других страниц. Это проверяет ci/doc_policy.py. Страница-указатель по прежнему адресу имеет
заголовок «# <Название>: документ перенесён» (в EN «: document moved») и ссылку на новый адрес;
проверка её пропускает.

Пустые каталоги не создаются. Переносить одну тематическую группу за раз: обновить относительные
ссылки, индекс, навыки и проверки; для внешних ссылок оставить короткую страницу
по прежнему адресу. ТЗ остаются по текущим путям, чтобы не ломать нормативные ссылки.
Локальные исследования и песочницы сохраняют действующие правила игнорирования;
публичные документы на них не ссылаются. Сырые логи/снимки не переносить в docs.

## Актуальность руководств

Рабочие руководства описывают линию 0.5.x, без дневника подготовки прежних выпусков.
Краткие изменения и действия пользователя — в docs/ru/RELEASE_CHANGES.md (и EN).
Подробные ранние планы и срезы — docs/archive/pre-050; их статусы не являются текущими.
Версии появления/совместимости в справочнике и миграции, версии инструментов и собственные
ревизии DDTT/ТЗ сохраняются. При переносе обновляйте входящие ссылки и обе локализации.
