# P6a — навыки и маршруты потребителей для API 3

[Памятка](../../TODO.md) · [Навыки](../../skills/README.md) · [API](../ru/api/index.md)

Аудит 19.10.2026, кандидат 0.5.0 / API_VERSION=3. Пакет меняет инструкции,
не ядро. Аппаратных запусков нет; этот этап не заменяет P5 на итоговом SHA.

## Девять навыков

| Навык | Проверенный предмет и поправки |
| --- | --- |
| integrate | Закрепление SHA, компактный и разнесённый HIL, inspect до prepare, аппаратные schema 1/2/3 и эмуляторная schema 3, захват SVD |
| scenarios | Сохранение def, явный await в async и помощниках, ret без await, запрет скрытых calls; MMIO вместо обычного write для регистра |
| run | inspect → doctor → prepare → run; emulator отдельно от hardware; refused может дать PASS, необработанный отказ — ERROR |
| results | Происхождение, capture/cleanup, исходный verdict отдельно от допуска и DDTT UNKNOWN |
| stand-loop | Неизменяемый пакет, совместимость принимающего модуля с SVD-капсулой, допуск не продлевается циклом |
| develop | Исходный FAIL и повтор при равных условиях; квалификация платы отдельно от дефекта приложения; явное восстановление |
| coverage | Карта/ревизия/окружение, квитанция records, блокировка только зависимых утверждений без изменения raw verdict |
| renode | Штатный backend отдельно от внешнего probe; ограничение самодостаточного REPL, независимая модель MMIO, API 3 и cleanup |
| hse-qualify | Методика и ресурсы сверены: инженерный бюджет не универсальная точность; отдельные epoch, восстановление и физическая опора. Изменений не требуется |

Ресурсы artifacts, MMIO, peripherals и HSE также просмотрены. Исторические ссылки
API040 остаются указанием происхождения прежних проверок, а не текущей версией API.
Номера техники не означают аппаратную приёмку нового сценария.

## Маршруты без платы

1. Новый проект: закреплённый модуль → inspect исходного TOML → configure/build →
   inspect session.json → CTest с меткой host. Обычный CTest без фильтра не запускать:
   он может включать аппаратные случаи.
2. Старый потребитель: проверить gitlink и схему, собрать заново, подготовить все
   сценарии. Синхронные def остаются синхронными; prepare не выполняет их тела.
3. Живое окно: штатный `tests/renode-backend/run.py`, положительные и намеренные
   отрицательные исходы, повторный запуск и cleanup. Результаты emulator.
4. Периферия: `tests/mmio-renode` — внешний маршрут с моделью callbacks; не выдавать
   его за поддержку PythonPeripheral в штатном backend. Затем отдельная согласованная
   аппаратная приёмка. Ширина RSP-пакета не доказывает ширину физической транзакции.
5. DDTT: неизменяемые результаты + карта + снимок допуска → экспорт; отрицательный
   контроль условий оставляет raw verdict, зависимая точка UNKNOWN не попадает в LCOV.
6. Автономный стенд: pack/prepare и проверка совместимости до запуска. Этот аудит
   не запускает службу, аппаратную серию или удалённый стенд.

## Потребители

Проверены локальные исходники репозиториев:

| Проект | Ревизия проекта | Закреплённый модуль | Сценарии |
| --- | --- | --- | --- |
| stm32-hwtest-bluepill | d1ecb33 | eb085b3 | 28 def, 11 файлов |
| stm32-hwtest-blackpill | 5270270 | e9017ab | 22 def, 6 файлов |

В обоих текущих проектах компактный HIL: common/tests и каталог на MCU. Разнесённый
вариант сохраняется и проверяется host-регрессиями inspect/CMake. Обе структуры
равноправны; соглашение не требует переписывать каталог потребителя.

AST-аудит не обнаружил async-кейсов, t.call или t.execute в этих наборах. Это не
доказательство отсутствия любых вызовов в динамических GDB-выражениях. Сверка
выражений и периферии остаётся необходимой перед аппаратной миграцией.
inspect исходных F103CB/F411CE даёт configuration_valid=true, ноль ERROR и один
ожидаемый WARN stand.not_selected: стенд намеренно не выбран, SVD не настроен.

Старые runtime-каталоги не использованы как доказательство: обнаружены устаревшие
пути сценариев; попытка вынести out за project root корректно отвергнута. Проверки
повторяются на чистых экспортированных исходниках с текущим модулем, новым ELF и
каталогом сборки. Рабочие деревья и gitlink потребителей не изменяются.

### Что потребуется перед P5

- Закрепить принятый модуль в потребителях отдельным изменением и пересобрать.
- Проверить SVD и операции периферии. BluePill test_dma/test_dma_error и BlackPill
  test_adc_faults/test_sleep/test_ddtt_feedback используют прежний общий доступ;
  особенно важны NVIC ICER/ISER, DMA-флаги и SysTick CTRL с read-side effect.
  Синтаксическая совместимость не даёт этим операциям гарантий MMIO.
- Для перехода на mmio нужны точные имена SVD, эффекты, независимые проверки и
  восстановление. Не выполнять механическую замену выражения на имя регистра.
- Проверить заново тело сценариев на согласованных платах и сохранить recovery.
  Отсутствие async в текущих потребителях не подтверждает аппаратную приёмку async.
- Зафиксировать один кандидат и выполнить матрицу P5 Windows/Linux, Renode/QEMU,
  шести стендов и потребителей. debugpy остаётся отдельной парной работой.

## Проверки этого пакета

- Все 9 заголовков навыков прошли quick_validate и штатную host-проверку.
- Host-набор: 683 теста на Windows (14 пропусков) и Linux (4 пропуска), PASS.
- Linux docs/host: 6/6; strict обоих ТЗ и проверка ссылок PASS.
- Чистые копии потребителей с текущим модулем: configure/build/host на Windows
  и Linux. BluePill F103CB/F103C8 — по 29 CTest-проверок; BlackPill F411CE/F401CC —
  по 23. Это prepare и traceability, не исполнение 28/22 сценариев на плате.
- inspect runtime всех четырёх свежих сборок на обеих ОС: ноль ERROR;
  ожидаемый WARN stand.not_selected. Исходные TOML F103CB/F411CE также проверены.
- Штатный Renode 1.17 на Windows: 21 ожидаемый исход, включая ошибки и повторный
  запуск, приняты драйвером; GDB xPack 14.2.1. Этот пакет не повторял Linux Renode,
  QEMU, службу stand-loop или аппаратную матрицу: их приёмка остаётся в P5.
- Git blob EXPORT_MANIFEST до/после переноса идентичен. Пути внутри него исторические.

Локальный PASS, GitHub CI и аппаратная приёмка учитываются раздельно. Новых
аппаратных свидетельств нет; родительская ветка на момент начала работы ожидала CI.
