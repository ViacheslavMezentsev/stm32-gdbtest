# Технический долг исследования rc3 GDB Python

[Документация](index.md) · [English](../en/technical-debt.md)

02.10.2026: по решению владельца **RTOS и все оставшиеся аппаратные эксперименты
приостановлены**. Это общий реестр исследования R1–R18, а не план следующего
автоматического запуска. Возобновление — только по отдельному указанию владельца
с подтверждением актуального стенда и восстанавливаемой прошивки. Сроков нет.
Ни один пункт ниже не считается выполненным или подтверждённым HW PASS.

Приоритеты обозначают зависимость будущих обещаний, а не разрешение работать:
**A** — до обещания соответствующего API; **B** — до расширения покрытия;
**C** — отдельное исследование. До закрытия пункта допустим явно ограниченный
контракт, который не обещает непроверенную возможность.

| ID / приоритет | Долг и исходное свидетельство | Критерий закрытия после возобновления |
| --- | --- | --- |
| D1 / B | RTOS: задачи, PSP, context switch, фильтры; этап 9 очереди, R11 только basic MSP | Обычная RTOS-прошивка без hooks; идентификация текущей/прерванной задачи, смена стека, locals, фильтры и естественное продолжение; фиксировать RTOS/port/build |
| D2 / A | Надёжность композиций: shared address, чужие точки, predicate errors, scope, настройки, call budget, bounded replay; этап 10 | Отдельные положительные/отказные сценарии, ownership и восстановление, обе ошибки при cleanup failure, отсутствие ложного достижения цели и бесконечного ожидания |
| D3 / B | Переносимость: этап 11 F030/F103, другие backends/ОС; основные R1–R18 выполнены на F411/Windows | Согласовать фактические подключения; выбрать репрезентативный набор, зафиксировать MCU/GDB/backend/ABI; HW и restore на каждой заявленной комбинации. Linux prepare не зачесть как HW |
| D4 / A | Общий execution context: [проект](execution-context.md), R1 epoch не отслеживает любую запись без continue | Проверить обязательные поля, selected vs physical frame, revision на мутации/reset/reconnect, unavailable states, immutable/serializable snapshots, лимиты и отсутствие неявного MMIO |
| D5 / A | Forced aggregate return: R5, R18 Pair soft/hard и HFA soft FAIL; pinned sret обход узок | Либо явно исключить формы ABI, либо доказать доставку результата caller и естественный контроль на каждом поддержанном ABI/ELF; не скрывать FAIL fallback-ом |
| D6 / A | Backend-зависимые остановки: HLA watch R2 и native stepi timeout R4 | Локализовать различие и получить устойчивые отдельные контроли навигации/watch; сохранить исходные ERROR/FAIL и определить поддержанный backend для каждой операции |
| D7 / A | Ресурсы: R7 DWT ranges/4-word budget, R8 FPB6 и finish reserve | Проверить совмещение/перекрытия/выражения, физические locations, чужие точки и внутренние call/finish points; отказ до/при установке без утечки ресурсов |
| D8 / B | IRQ/FPU: PSP, вложенные IRQ, extended frame/lazy stacking; R11/R17 частичны | Доказать правильный interrupted context и естественный exception return с сохранностью заявленного FP/stack состояния; не подменять это scalar ABI PASS |
| D9 / B | C++ и типы: virtual/inheritance, constructors/destructors, lifetime, exceptions/RTTI, variadic, nontrivial aggregates, специальные float | Отдельная матрица требуемых возможностей и отказов на обычных прошивках; не расширять вывод R18 о const-перегрузках на весь C++ |
| D10 / B | Навигация/оптимизация: bare until, дополнительные recursion/inline/LTO случаи и исчезнувшие функции | Проверить фактическую причину каждой остановки, неоднозначность locations и доступность данных без зависимости от одного DWARF-расположения |
| D11 / B | Периферия/время: R12 DMA не виден watch, R13 не измеряет сон; MMIO эффекты чтения и полного rollback нет | Для конкретного контракта описать наблюдаемые сигналы, read effects, halt effects и при необходимости внешний измеритель; не заявлять глобальную атомарность/тайминги |
| D12 / B | Поведение приложения: R14 последовательные вызовы, не настоящий retry/backoff | Отдельная обычная реализация требуемого retry/deadline, конечные sinks, порядок, пределы попыток и естественный контроль |
| D13 / C | Универсальный power-cycle, orchestration нескольких плат, покрытие кода | Отдельное исследование с границами, стендом и критериями; не включать автоматически в rc3 |
| D14 / C | Динамическое дерево истории вызовов и статический граф возможных вызовов: отдельных инструментов нет, backtrace показывает только текущую цепочку | Только при отдельной потребности определить вид графа; для динамического учесть пропуски входов/выходов, recursion/IRQ, ограничения ресурсов и искажение времени; для статического — косвенные вызовы и оптимизацию. Не часть первого API |

Незакрытые D2/D4–D7 требуют обсуждения перед включением соответствующих обещаний
в API. Документирование исключений возможно сейчас; новые измерения остановлены.
Для каждого будущего закрытия нужны отдельный RU/EN отчёт, обезличенные результаты,
описание сборки/стенда, сохранённые отказы и проверка восстановления. Новый номер
серии присваивается по факту, R19 под RTOS заранее не зарезервирован.

контрактов. Исторические «далее» в R1–R18/TODO/CHANGELOG не отменяют эту паузу.
