# rc3 R17: скалярные типы и soft/hard-float ABI

[Документация](index.md) · [English](../en/r17.md)

02.10.2026, после `0fd9f8c`, ветка codex/rc3-api-r1. Ядро, публичный API и ТЗ
не изменены. Первый подэтап расширенной ABI-проверки; структуры и C++ ещё впереди.

## Прошивка и матрица

Добавлено обычное приложение [abi_main.c](../../../../tests/api-experiments/src/abi_main.c)
с отдельной единицей [abi_values.c](../../../../tests/api-experiments/src/abi_values.c).
Основной цикл вызывает обработку данных; результаты сохраняются в volatile-полях.
Hooks и ветвления для тестов отсутствуют. CMake выбирает приложение через
RC3_ABI_FIXTURE=ON, ABI через RC3_FLOAT_ABI=soft/hard. По умолчанию прежнее приложение
и soft; взаимоисключающие приложения и hard без FPU-инициализации отклоняются.

Hard-вариант использует -mfpu=fpv4-sp-d16. В main разрешаются CP10/CP11, затем DSB/ISB,
до первого вызова process_abi; это подтверждено дизассемблером. ELF hard содержит
Tag_ABI_VFP_args: VFP registers. affine получает double в d0/d1 и возвращает d0,
но считает через __aeabi_dadd; gain_adjust использует vadd.f32. Поэтому hard ABI
здесь не означает аппаратную double-арифметику. CPACR сохранён в результатах CALL.

[Три сценария](../../../../tests/api-experiments/profile/tests/board/test_abi_extended.py)
в каждом запуске проходят четыре типа:

| Функция | Естественный результат | Подмена return | Что дополнительно проверено |
| --- | --- | --- | --- |
| accumulate(3), void | accumulated +=3 | Пустой return, эффект пропущен | У finish нет скалярного результата; прямой call имеет тип void и сохраняет побочный эффект |
| affine(2.5,0.5), double | 5.5 | -2.25 | FinishBreakpoint, call, значение у вызывающего кода |
| gain_adjust(3.5f), float | 4.75 | -2.5 | То же, включая hard-float передачу |
| weighted_sum(1…6), uint32 | 654321 | 42 | Все6 аргументов из DWARF; при естественном входе SP%8=0, пятый/шестой по SP/SP+4 равны5/6 |

FINISH захватывает естественный результат; RETURN пропускает тело и передаёт
замену; CALL проверяет прямой результат и восстановление PC/SP. После каждой
операции обычный код потребляет результат, затем ещё одна естественная итерация
подтверждает восстановление поведения. Для void CALL отдельно наблюдаются +3 от
прямого вызова и +3 от последующего естественного: восстановление регистров не
откатывает побочные эффекты RAM.

**48/48 HW PASS:** две ABI × два GDB × три сценария × четыре прохода;24/24 на ABI.
Это48 сценариев, каждый содержит четыре типа, а не192 независимых запуска.
BlackPill F411CE/ST-Link/OpenOCD0.12.0 HLA/SWD, Windows, GDB14/16, GCC13.3.1,
-Og/-g3, без LTO. Неожиданных FAIL/ERROR нет. Baseline и итоговое восстановление
HAL HW_BOOT/HW_GPIO PASS в обеих матрицах; оставшихся GDB/OpenOCD процессов нет.
Все четыре fault guard сохранены, логи подтверждают hardware Z1 без Z0.

## Границы и воспроизведение

Стек наблюдался непосредственно для естественных FINISH/RETURN-входов. Для
dummy-call с6 аргументами проверены вычисленный результат и восстановление PC/SP,
а не снимок его промежуточного стека. Значения двоично точные; NaN/Inf, округление,
variadic, FPU lazy stacking и сохранность всех FP-регистров не проверялись.
Прежний FAIL принудительного возврата структуры из R5 остаётся открытым.
Структуры/HFA, C++, IRQ/RTOS и другие платы/ABI в этот подэтап не входят.

Собрать два отдельных каталога consumer с RC3_ABI_FIXTURE=ON и
RC3_FLOAT_ABI=soft/hard. Передать соответствующий hwtest/session.json в
[runner](../../../../tests/api-experiments/run_matrix.py) с --suite r17 --execute,
двумя прежними GDB и согласованной restore-сессией, без --native-stlink.
Без execute — подготовка; старым сценариям нужны их прежние ELF.

- Soft ELF: `d66fef86d1e0031659055b4a2d0a9a7d20e581c60ff3d8f144ecf75f51a7e90c`.
- Hard ELF: `5367944b31a8870dc183a475e1f9753bccf0d237c5efb84c454f39d14b1544d6`.
- Restore HAL: `1ff37ae10a007401de5e0eaf826764f60a2849c8b7821c123f12caa28c2e79c3`.
- Пересобранный прежний consumer сохранил ELF `7842e8ee9471ec777001a1fcc5be6e4a9625af3883eee7c8a1b15ebbcd6c5552`.
