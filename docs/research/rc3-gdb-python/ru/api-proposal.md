# Предложение состава API по результатам R1–R18

[Документация](index.md) · [English](../en/api-proposal.md)

02.10.2026. Статус: **черновик для обсуждения, решения не утверждены**.
Ветка `codex/rc3-api-r1`. Основание — [сводка отчётов](summary.md),
[классификация инструментов](scenario-tools.md) и [проект контекста](execution-context.md).
Здесь предлагается публичная поверхность, а не реализация. Действующий
[API_VERSION=1](../../../ru/API.md), ТЗ и код ядра остаются прежними.
HW, включая RTOS, приостановлено; [технический долг](technical-debt.md) сохраняется.

## 1. Рекомендуемый подход

Предлагаю расширять передаваемый сценарию `Target` небольшими операциями, которые
возвращают данные и явный результат остановки. Композиции остаются обычным Python.
Для класса, цикла или периферийного блока не нужен отдельный класс API: их
проверяют через выражения, кадры, точки и ограниченное управление исполнением.

Три пакета ниже — порядок обсуждения и возможной реализации, не обещание включить
всё в rc3. **A** — наблюдение; **B** — точки и навигация; **C** — вмешательство.
Новые имена и сигнатуры предварительные. Достаточная зрелость механизма в GDB
не означает готовности его общего контракта в stm32_gdbtest.

## 2. Сохранить действующий API

`check`, `value`, `fields`, `reach`, `breakpoint`, `set_value`, `force_return`,
`clear` сохраняют прежние значения параметров, типы результатов и обработку ошибок.
В частности, `value(expression)` остаётся integer-операцией; расширенное чтение
получает отдельное имя. `clear()` не переопределяется как удаление только новых
точек: его текущая семантика включает fault guards Target.

Новая навигация не меняет молча `reach()`. Старый сценарий должен проходить
регрессию на новой версии в прежней поддержанной конфигурации. Решение о номере
API_VERSION, схеме и миграции принимается при утверждении конкретного изменения,
а не этой документационной правкой. Новому сценарию нельзя обещать работу на
старом модуле только благодаря сохранению старых методов.

## 3. Пакет A: наблюдение и свидетельства

| Кандидат | Контракт для обсуждения | Основание |
| --- | --- | --- |
| `t.context(*, registers=(), max_frames=8)` | Неизменяемый снимок: `context['PC']`, SP, stop, frames, meta, availability; без continue и неявного MMIO | [R1](r1.md), [R11](r11.md), [R15](r15.md); общий контракт — D4 |
| `t.read(path, *, frame=None)` | Типизированный снимок символа/поля/индекса или local выбранного FrameRef; ограниченные глубина/размер, без вызова функций | [R1](r1.md), [R6](r6.md), [R18](r18.md) |
| `t.evaluate(expression, *, frame=None)` | Явный C/C++ evaluator, типизированный результат; не объявляется безопасным чтением, инвалидирует прежнюю актуальность при потенциальном эффекте | [R2](r2.md), [R3](r3.md); ограничения ниже |
| `t.resolve(location)` | Все конкретные адреса/символы/исходные позиции для функции, полной C++-сигнатуры, file:line или адреса; не выбирает первую location молча | [R15](r15.md), [R18](r18.md) |
| `t.disassemble(address, *, count=1)` | Ограниченная последовательность address/length/asm; машинные байты — явно запрашиваемое дополнение | [R2](r2.md), [R16](r16.md); распознавание self-branch остаётся техникой |
| `t.capabilities()` | Снимок доступности операций и ограничений текущей связки MCU/GDB/backend/ABI, с происхождением сведений | [R7](r7.md), [R8](r8.md), [R17](r17.md), [R18](r18.md); не только проверка версии GDB |
| `t.record(name, data)` | Публичная ограниченная запись материализованного свидетельства в отчёт, без доступа к внутреннему `t.report` | [R1](r1.md); сериализация, размер и повтор имён проверяются |

Минимальное обсуждаемое ядро A: **context, read, resolve, record**. Disassemble
полезен как малый самостоятельный примитив. Capabilities нужен до объявления
переносимых B/C: различать «механизм доступен», «проверено на этой конфигурации»,
«известный отказ» и «не проверено»; не подменять эти оси одним supported boolean.

`read` сознательно не принимает весь язык C. Для `evaluate` нельзя гарантировать
отсутствие побочных эффектов по строке или простому запрету `=`: возможны MMIO,
перегруженные операции и вызовы. Рекомендация — исключить inferior calls из обычного
evaluate, выделить их в `call`, а произвольный evaluator оставить явно продвинутой
операцией с документированными границами. Если запрет невозможно надёжно обеспечить,
такой контракт не публиковать. До решения можно пользоваться текущим `value` и raw GDB
с их действующими ограничениями. Базовый context не использует evaluate.

## 4. Пакет B: ресурсы и навигация

| Кандидат | Контракт для обсуждения | Основание |
| --- | --- | --- |
| `t.code_point(location, *, temporary=False, condition=None, ignore_count=0)` | Owned PointHandle с context manager и явным remove; hardware-only, одна разрешённая location по умолчанию; несколько — только явный выбор | [R2](r2.md), [R8](r8.md), [R15](r15.md) |
| `t.watch(address, size, *, access='write')` | Owned аппаратная точка на явный диапазон; read/write/access, выравнивание и фактическая установка проверяются; нет скрытого software fallback | [R3](r3.md), [R7](r7.md), [R12](r12.md) |
| `t.resume(*, timeout_s)` | Продолжить до первой остановки; вернуть StopResult, не обходить чужие точки автоматически | [R1](r1.md), [R9](r9.md), [R16](r16.md) |
| `t.run_to(location, *, timeout_s)` | Owned временная точка + продолжение, OperationResult отличает target_reached от другой остановки | [R2](r2.md), [R8](r8.md), [R16](r16.md) |
| `t.finish(*, frame=None, timeout_s)` | Естественно закончить выбранный вызов; ReturnResult с типизированным значением, если оно доступно; резерв служебной точки | [R5](r5.md), [R6](r6.md), [R17](r17.md), [R18](r18.md) |
| `t.step(*, unit='instruction', over=False, count=1, timeout_s)` | Ограниченное число шагов; остановка чужой точкой прерывает операцию и возвращается автору | [R2](r2.md), [R16](r16.md); native regression [R4](r4.md) остаётся D6 |
| `t.advance(location, *, timeout_s)` | Продолжение с границей текущего кадра; frame_exited отдельно от target_reached | [R16](r16.md); включать только если такая семантика нужна отдельно от run_to |

Начальный B: **code_point, resume, run_to, finish, instruction step**.
Watch — отдельная capability с backend-ограничениями. Source step и advance —
следующий объём обсуждения; bare until пока долг. Conditions первоначально —
выражения GDB, не callback, который может рекурсивно продолжить исполнение.
`ignore_count` считает пропущенные попадания, а не итерации программы.

PointHandle — владеющий ресурс, не snapshot: после удаления операции над ним
отклоняются; номер удалённой временной точки сохраняется в событии заранее.
Бюджет считает физические locations, fault guards и временные точки finish/call.
Успешное создание handle не доказывает установку на MCU до continue. Автоматическое
разбиение watch-диапазона и распределение слотов пока остаются техниками.

## 5. Пакет C: вмешательство с явными границами

| Кандидат | Рекомендация и ограничение | Основание |
| --- | --- | --- |
| `t.read_memory(address, size)` / `t.write_memory(address, data)` | Ограниченная RAM-область потребителя, журнал записи, проверка диапазона; не универсальный MMIO API | [R1](r1.md), [R4](r4.md) |
| `t.call(expression, *, timeout_s)` | Явно исполнить функцию прошивки; ReturnResult различает завершение и прерывание; только заявленные ABI и пределы | [R5](r5.md), [R9](r9.md), [R10](r10.md), [R17](r17.md), [R18](r18.md) |
| Типизированный forced return | Сначала определить допустимые формы рядом с существующим force_return; не менять его поведение молча | [R5](r5.md), [R18](r18.md): универсальные агрегаты не обещать |
| Запись регистров, PC/jump | Не включать в первый объём; нужна отдельная модель stack/control-flow эффектов и проверки | Наличие чтения/step не доказывает корректность произвольного переноса PC |

Call не является транзакцией: RAM/периферия могут измениться, даже если результат
не получен. После прерывания нельзя автоматически повторять вызов; нужно вернуть
управление сценарию с состоянием остановки. При внешнем timeout Python может не
вернуть ReturnResult вообще — host записывает ERROR и делает отдельно согласованное
recovery. Forced return не выполняет тело и не доказывает корректную доставку
агрегата caller. Hidden-sret обход по закреплённому ELF остаётся техникой потребителя.

## 6. Общие модели результатов

| Модель | Минимальное содержание и жизненный цикл |
| --- | --- |
| Context | Схема из [проекта](execution-context.md): immutable PC/SP, bounded frames, run/stop/revision, availability; снимок остаётся читаемым после resume |
| FrameRef | Ссылка на конкретный кадр в run/stop/revision с index/kind; не идентификация только именем/PC; при вмешательстве проверяется актуальность |
| ValueSnapshot | type, width, kind, value, availability, происхождение; структура/массив ограничены; void отличается от отсутствующего результата |
| StopResult | Фактическое событие, все номера точек, signal, Context; сам по себе не означает PASS сценария |
| OperationResult | requested operation, outcome, StopResult; completed/target_reached, interrupted и frame_exited различаются; свойство require_completed() может явно отвергать неполное выполнение |
| ReturnResult | OperationResult + ValueSnapshot; естественный finish и direct call сохраняют разные виды операции |

Названия типов тоже предварительные. Рекомендация: обычную непредвиденную точку
возвращать как interrupted для нового низкоуровневого API; fault, потерю соединения,
недоступную операцию и timeout не маскировать под нормальный completed. Исключение
операции должно нести доступные диагностику/StopResult. Несовпадение ожидания
сценария — FAIL; невозможность выполнить операцию — ERROR. Ожидаемый в исследовании
ERROR не превращается в PASS исходного запуска. Точная иерархия ошибок — решение Q3.

## 7. Пример композиции для обсуждения

**Псевдокод предлагаемого API; сейчас не исполняется.** Он ожидает естественный
вызов MX_SPI1_Init и выход из него, не вызывает функцию дополнительно.

```python
entry = t.run_to('MX_SPI1_Init', timeout_s=5)
entry.require_completed()
before = entry.stop.context
finished = t.finish(timeout_s=5)
finished.require_completed()
t.record('spi_init', {'entry_pc': before['PC'],
                      'return_pc': finished.stop.context['PC']})
# Consumer assertions must verify the required SPI configuration here.
```

Достижение выхода не означает правильную настройку SPI: ожидания и допустимые
чтения регистров задаёт потребитель. Пределы операций ограничиваются оставшимся
бюджетом case; два timeout по 5 секунд не продлевают его внешний watchdog.
Синтаксис example — предмет обсуждения Q1/Q3, не документация текущего API.

## 8. Что оставить техниками и шаблонами

Caller-is и фильтры рекурсии — helpers поверх frames; бесконечный self-branch —
распознавание инструкции; deadline по счётчику — выражение плюс наблюдение;
patch/restore — контекстная композиция RAM-операций; out-buffer/status — подмена
на входе и проверка caller; последовательность отказов/успеха — конечный автомат
ожиданий. Эти техники должны иметь примеры, предусловия, cleanup и ограничения.

Шаблоны «проверить ветвь ошибки», «сохранить принятое состояние», «проверить
периферийный обмен» строятся из этих техник. DMA/IRQ/WFI, MCU-регистры и будущие
RTOS-задачи остаются в профилях/библиотеках потребителя. Host recovery не переносится
в синхронный метод GDB. Универсальный `cmds('...; ...')` не нужен как основной API:
Python-композиция сохраняет отдельные результаты и точки отказа.

## 9. Вопросы и рекомендуемые решения

Все строки **открыты**; рекомендация не является решением владельца.

| ID | Вопрос | Рекомендация для обсуждения |
| --- | --- | --- |
| Q1 | Плоский Target или t.execution/t.memory/t.points? | Пока плоские методы и отдельные типы результатов; пространства имён вводить при реальной сложности |
| Q2 | Какой первый объём? | A: context/read/resolve/record/disassemble; B обсуждать следующим пакетом, C отдельно; capabilities до обещания поддержки B/C |
| Q3 | Неожиданная остановка: exception или result? | Низкий уровень возвращает interrupted, require_completed явно требует успеха; инфраструктурные/fault ошибки — исключение с диагностикой |
| Q4 | C-выражения и побочные эффекты? | Разделить bounded read, advanced evaluate и call; не обещать универсальный read-only evaluator |
| Q5 | Автоматически выбирать multiple locations/делить watch ranges? | Нет; явное разрешение/выбор, композиция в технике, учёт физического бюджета |
| Q6 | Утверждать context как dict? | Read-only Mapping с привычным ['PC']; вложенные структуры неизменяемы, экспорт отдельной копией |
| Q7 | Что делать с непроверенной конфигурацией? | Не заявлять поддержку; сохранить статус unverified и диагностировать ограничения до вмешательства, где возможно |
| Q8 | Включать aggregate forced return/RTOS сейчас? | Нет; known FAIL и приостановленный долг не позволяют общего обещания |

Первое обсуждение предлагается начать с **Q2 и Q6**: утвердить минимальный пакет
наблюдения и форму контекста, затем Q3 для навигации. Решения записывать здесь
с датой и формулировкой владельца, после чего уточнять проект контрактов.
Только отдельное разрешение на реализацию запускает изменения ядра, ТЗ, миграции
и необходимые регрессии. Разрешение обсуждать API не возобновляет HW-эксперименты.
