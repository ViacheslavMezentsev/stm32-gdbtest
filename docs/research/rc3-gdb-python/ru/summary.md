# Сводка исследования GDB Python: R1–R18

[Документация](index.md) · [English](../en/summary.md)

02.10.2026. Аппаратные эксперименты приостановлены по решению владельца.
RTOS и остальные проверки перенесены в [технический долг](technical-debt.md).
Обсуждение расширения API возможно сейчас, без выполнения этой очереди.
Перенос в ядро отдельно утверждает владелец; эта сводка не меняет публичный API.

Каждая выполненная серия имеет отдельный отчёт и JSON с результатами. Отчёты
сохраняют исходные FAIL/ERROR и исторические планы продолжения; актуальный статус
задают эта сводка и технический долг. Исходный обзор руководства и внешних подходов
остаётся в [плане](plan.md), пробы возможностей GDB14/16 — в [карте](index.md).

## Реестр выполненных исследований

| Отчёт | Проверенные средства и вывод | Граница доказательства |
| --- | --- | --- |
| [R1: данные и состояние](r1.md) | Типизированные снимки, кадры, ограниченный RAM patch с восстановлением, события и запись свидетельств | 48/48; consumer-адаптер, не публичный API; внешнее завершение требует отдельного recovery |
| [R2: навигация](r2.md) | Условные/временные точки, ignore count, caller, C-выражения, finish/return/call, дизассемблирование | 56/56 HLA, 8/8 native DAP; первоначальный watch FAIL на HLA сохранён |
| [R3: действия и прогресс](r3.md) | Команды при остановке, композиция команд, unsigned deadline с переполнением, C-макросы; watch отличается от awatch | 32/32 native DAP; доступ и изменение значения — разные события |
| [R4: выходные параметры](r4.md) | Подмена буфера и signed status, естественное продолжение и результат вызывающего кода | 32/32; отдельный ASM regression дал timeout ERROR на native, HLA 4/4 |
| [R5: возвращаемые типы](r5.md) | uint64/float/struct через finish/call; scalar forced return | 64/64 позитивных; struct return FAIL; ручной hidden-buffer приём 8/8 только на закреплённом ELF |
| [R6: стек и рекурсия](r6.md) | Фильтрация caller/контекста, выбор рекурсивного кадра, finish/return | 24/24; имя функции не идентифицирует конкретный рекурсивный кадр |
| [R7: диапазоны DWT](r7.md) | Выровненные watch-диапазоны, разбиение невыровненных, бюджет word-точек | 16/16 + 8/8; отклонённые диапазоны не поддержаны; 4 word-точки, пятая отвергнута на этом стенде |
| [R8: бюджет FPB](r8.md) | Физические locations и резерв для finish; освобождение точки и продолжение | HLA 16/16, native 8/8; 6 слотов, 4 заняты fault guards; не универсальный бюджет MCU |
| [R9: прерванный call](r9.md) | DUMMY_FRAME, подмена вложенного результата и продолжение | 16/16; восстановление регистров не откатывает RAM, исходное Python-выражение не возобновляется |
| [R10: fault/timeout](r10.md) | Классификация fault, свидетельства до call, внешнее recovery и контроль | 16 ожидаемых ERROR и 16/16 контролей PASS; finally после внешнего kill не гарантирован |
| [R11: IRQ](r11.md) | SysTick/TIM2, прерванный контекст и естественный exception return | 16/16; basic MSP, не PSP/RTOS/расширенный FP-кадр |
| [R12: DMA](r12.md) | Буфер изменён DMA без watch stop; отдельные положительные CPU-контроли | 16/16 native; отсутствие watch-события не доказывает отсутствие записи DMA |
| [R13: WFI](r13.md) | Остановка перед WFI, IRQ-пробуждение, естественный возврат, ход ticks | 16/16; не измерение энергии, времени сна или задержки IRQ |
| [R14: последовательности](r14.md) | Отказы/успех, сохранение принятого результата, порядок и число выбранных вызовов | 24/24; последовательные обращения main loop, не внутренний retry/backoff |
| [R15: оптимизация](r15.md) | O2/Os, inline-кадры, multiple locations, optimized_out, конечные приёмники | 32/32; доступность DWARF-значения не доказывает выполнение соответствующей инструкции |
| [R16: until/advance/nexti](r16.md) | Строки, граница кадра, прерывание шага посторонней точкой | 32/32; advance может завершиться до цели; out-of-scope отличается от optimized_out |
| [R17: scalar ABI](r17.md) | void/double/float/6 аргументов, soft/hard ABI, finish/return/call и приёмники | 48/48; hard ABI для double не означает аппаратное вычисление double |
| [R18: агрегаты и C++](r18.md) | Small/Pair/HFA, this, const-перегрузки и конечные приёмники | 72 PASS, 6 FAIL: forced Pair soft/hard и HFA soft; Small и HFA hard проходят |

Числа относятся к сериям и контролям, указанным в отчётах: суммировать их в
«процент поддержки API» нельзя. PASS проверки ожидаемого отказа не означает
поддержку отказавшей операции. Основной HW-стенд — F411CE, ST-Link, OpenOCD,
Windows, GDB14/16; HLA и native DAP различаются. Linux host/prepare PASS не является
Linux HW PASS. Точные ELF, сборки, повторы и восстановление указаны в каждом отчёте.

## Выводы для обсуждения

1. Наиболее обоснованная основа — типизированное наблюдение, причины остановки,
   явные ресурсы точек и ограниченная навигация. Нужны контракты отказов, а не
   только удобные оболочки команд.
2. Подмена результата полезна только вместе с проверкой вызывающего кода и
   естественного контрольного вызова. Универсальный forced aggregate return
   по текущим данным обещать нельзя.
3. Контекст MCU, кадр C/C++ и причина остановки — разные сущности. Один PC не
   идентифицирует inline/рекурсивный кадр и не объясняет остановку.
4. Периферийные техники требуют профиля потребителя: остановка CPU не превращает
   DMA/MMIO в атомарный снимок, а watchpoint не наблюдает любую запись в память.
