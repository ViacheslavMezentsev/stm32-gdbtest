# rc3 R15: O2/Os, inline и доступность значений

[Документация](index.md) · [English](../en/r15.md)

02.10.2026, после `77b6c4e`, ветка codex/rc3-api-r1. Ядро, публичный API и ТЗ
не изменены. Добавлены варианты consumer-сборки и отдельная обычная прошивка
[двухканального вычисления](../../../../tests/api-experiments/src/optimized.c):
два volatile-входа, общий множитель, inline scale_channel и два выхода. Hooks нет.

## Предварительные наблюдения

При сборке прежнего приложения с O2 линкер сообщил undefined memcpy/memset из
Reset_Handler: оптимизация преобразовала стартовые циклы в библиотечные вызовы.
Для startup оптимизированных вариантов добавлен -fno-tree-loop-distribute-patterns;
остальные единицы сохраняют O2/Os, исходник startup прежний. Первичный отказ
сохранён в [JSON](../results/rc3-r15-results.json). Первая Linux-команда также
отклонилась до конфигурации из-за quoting переменных bash в PowerShell; исправлена.

В прежнем приложении O2 имя walk_route больше не разрешается в точку: route_alpha
сведён к movs r0,124; bx lr. В Os walk_route сохранился. Это offline-наблюдение
GDB14, не аппаратная проверка этих двух прежних вариантов. Для исследования inline
использована новая прошивка с переменными входами, а не отключение оптимизации.

## Аппаратные результаты

[LOCATIONS и VALUES](../../../../tests/api-experiments/profile/tests/board/test_optimized.py)
выполнены на BlackPill F411CE/ST-Link/OpenOCD0.12.0 HLA/SWD, Windows,
GCC13.3.1, soft-float, -g3, без LTO. Две оптимизации × два GDB × два сценария ×
четыре прохода: **32/32 HW PASS**, по16/16 для O2 и Os. Неожиданных HW FAIL/ERROR
нет. Baseline и restore HAL HW_BOOT/HW_GPIO PASS после каждой матрицы;
оставшихся GDB/OpenOCD процессов нет.

| Наблюдение | O2 | Os |
| --- | --- | --- |
| scale_channel: две locations | 0x080000c2,0x080000ce | 0x0800009e,0x080000a8 |
| Первая инструкция | mul.w,4байта | muls,2байта |
| Кадры | INLINE_FRAME scale_channel → NORMAL_FRAME main, общий PC | То же |
| До умножения | input=11, multiplier=3, product=33 | То же |
| После одного stepi | input=optimized_out, multiplier=3, product=33 | То же |
| Выходы после итерации | output_a=40, output_b=76, iterations=1 | То же |

LOCATIONS проверяет остановки A→B→A по PC и номеру одного breakpoint, аргументы
11/23 и3, inline-кадры и конечные результаты. Перед этим Research.breakpoint
отклоняет имя с двумя locations и удаляет созданную точку. Затем raw GDB breakpoint
с двумя адресами занимает два физических слота, вместе с четырьмя guard — шесть.
Логи подтверждают Z1 без Z0. Это опыт вне ядра, не расширение контракта адаптера.

VALUES разрешает адреса, удаляет многолокационную точку, достигает первого адреса
отдельной точкой и выполняет один stepi. Проверяет следующий адрес по дизассемблеру,
INLINE_FRAME и изменение доступности locals; Research.freeze явно отклоняет
optimized_out. Продолжение по точным адресам подтверждает потребление результата
обычным кодом. RAM/регистры вручную не подменяются.

## Выводы для сценариев

- Бюджет считается по locations, а не объектам breakpoint. Номер события сообщает
  объект; конкретный экземпляр здесь определяется по PC. Адреса разрешаются из
  текущего ELF, не переносятся между O2 и Os.
- Inline-кадр имеет исходные аргументы, но не отдельный машинный вызов. Его тип
  нужно учитывать до попыток return/finish. Return/finish inline здесь не испытаны.
- product=33 доступен ещё до инструкции умножения. Значение из отладочной
  информации само по себе не доказывает выполнение операции; для этого проверены
  инструкция/PC и конечные volatile-выходы.
- Доступность зависит от конкретного PC: input пропадает после перезаписи регистра.
  Нельзя заменять unavailable нулём или использовать снимок предыдущей остановки
  как текущее значение. Проверен именно is_optimized_out; прочие виды недоступности
  не покрыты.
- Исчезновение функции — допустимый результат оптимизации. Не считать pending
  breakpoint рабочей точкой. LTO, tail-call-кадры, другие компиляторы/ABI/платы,
  Linux HW и native DAP не проверены; прежнее ограничение native stepi остаётся.

## Воспроизведение

В consumer CMake доступны RC3_OPTIMIZATION=Og/O2/Os (по умолчанию Og) и
RC3_OPTIMIZED_FIXTURE=ON (по умолчанию OFF). Для R15 создать отдельные build-каталоги
с ON и O2/Os, затем передать их hwtest/session.json в [runner](../../../../tests/api-experiments/run_matrix.py)
с --suite r15 --execute, двумя прежними GDB и согласованной restore-сессией,
без --native-stlink. Без execute — подготовка. Старые сценарии требуют своих ELF.

- O2 ELF: `0938392ab203e6ebe838f858bea69fa2a0139b116ebe111f60b5790a536b11f8`.
- Os ELF: `48e665fdb23bdcd838b55923e525323e17129869667736629243df4864f9901d`.
- Restore: `1ff37ae10a007401de5e0eaf826764f60a2849c8b7821c123f12caa28c2e79c3`.
- Пересобранный прежний Og сохранил ELF `7842e8ee9471ec777001a1fcc5be6e4a9625af3883eee7c8a1b15ebbcd6c5552`.
