# rc3 R16: until, advance, nexti и причины остановки

[Документация](index.md) · [English](../en/r16.md)

02.10.2026, после `d043fec`, ветка codex/rc3-api-r1. Ядро, публичный API,
ТЗ и прошивка не изменены. Использован прежний Og api_firmware.

## Сценарии и результаты

[Четыре сценария](../../../../tests/api-experiments/profile/tests/board/test_navigation_extended.py)
выполнены на BlackPill F411CE/ST-Link/OpenOCD0.12.0 HLA/SWD, Windows, GDB14/16.
Локации строк разрешаются через gdb.decode_line; требуются полное разрешение и
единственный PC. Инструкция BL sum_bytes и следующая инструкция определяются
дизассемблером внутри границ process_sample. Абсолютные адреса не зашиты в сценарии.

| Сценарий | Действие | Подтверждённая остановка |
| --- | --- | --- |
| UNTIL | Из первого тела цикла until app.c:28 | sum_bytes, PC0x080000d0, return total, сумма773 |
| ADVANCE | Из process_sample advance app.c:26 | Тело дочерней sum_bytes, PC0x080000c4 |
| ADVANCE, продолжение | Из sum_bytes advance *process_packet | Выход текущего кадра в process_sample, PC0x08000124; адрес process_packet ещё не достигнут |
| NEXTI | nexti на BL по0x08000120 | process_sample, PC0x08000124, r0=773 |
| INTERRUPT | Та же nexti с отдельной точкой sum_bytes | BreakpointEvent с номером этой точки внутри sum_bytes, PC0x080000bc; обход вызова ещё не завершён |

В INTERRUPT точка удаляется, затем отдельная навигация достигает инструкции после
BL. Каждый сценарий заканчивается контролем checksum=773 XOR0xffffff85 и cycles=0
на входе process_packet: результат действительно потреблён обычным вызывающим кодом.
RAM/регистры не подменяются, fault guard сохранены. Hardware override и логи
подтверждают Z1 без Z0, включая внутренние точки команд навигации.

**Итог исправленной матрицы:32/32 HW PASS** — четыре сценария × четыре прохода ×
два GDB. Baseline и восстановление HAL HW_BOOT/HW_GPIO PASS в обеих сериях;
оставшихся GDB/OpenOCD процессов нет.

## Сохранённый ERROR и выводы

Первый UNTIL остановился правильно: PC return, кадр sum_bytes и total773 прошли.
Затем сценарий ошибочно прочитал i после окончания её области видимости. Получен
ERROR `No symbol "i" in current context.`; серия остановлена, прошивка восстановлена.
Исходный ERROR и хэш версии сценария сохранены в [JSON](../results/rc3-r16-results.json).
Исправление проверяет отсутствие символа через lookup_symbol в текущем блоке;
итог цикла подтверждается total и потребителем. Повтор выполнен после исправления.

- Out-of-scope — отсутствие символа в текущем контексте; optimized_out из R15 —
  существующее значение, которое GDB не может восстановить. Сценарии должны
  различать эти состояния и не подставлять ноль.
- Возврат gdb.execute не доказывает достижение цели. advance завершился при выходе
  кадра; nexti — из-за другой точки. Проверяйте событие, PC и кадр совместно.
- Успешные until/advance здесь дают StopEvent без пользовательского номера точки.
  Нельзя требовать BreakpointEvent от любой команды или считать пустой список
  breakpoints ошибкой без проверки PC/контекста.
- После посторонней остановки продолжайте к явно выбранной границе. Повтор nexti
  внутри дочерней функции означал бы уже другую операцию.
- Проверены until с явной строкой, advance и nexti над одним естественным вызовом.
  Bare until, рекурсивная навигация, O2/Os, сигналы/fault во время этих команд,
  Linux HW и другие платы не проверялись. HLA PASS не отменяет native stepi ERROR R4.
