[Documentation](index.md) · [Русский](../ru/r11.md)

2026-10-02, after `7f06a5d`, branch codex/rc3-api-r1. Core/API/specification unchanged.
Instead of api_firmware, this series uses the **existing CMSIS F411 firmware**

researched mechanisms into the core requires owner approval.

## Technique and results

[Two scenarios](../../../../tests/api-experiments/profile/tests/board/test_irq_frames.py)
on F411CE/ST-Link/OpenOCD0.12.0 HLA, Windows, GDB14/16:

| Experiment | Check |
| --- | --- |
| SYSTICK | Natural SysTick, exception15; interrupted board_delay_ms(500), handler increments board_ticks_ms |
| TIM2 | Natural TIM2, exception44; interrupted board_delay_ms(500), handler increments board_timer_events |

Each experiment follows the same chain:

1. A conditional point selects delay_ms==500. A hardware address point stops the
   handler at **exact entry**, before its prologue. Verify PC and xPSR.
2. Skip SIGTRAMP_FRAME during stack walking; finding the required interrupted
   function is bounded by8 attempts. The final series needed only the first attempt.
3. Require LR EXC_RETURN=0xfffffff9: basic frame, thread mode, MSP. Read
   r0–r3/r12/LR/PC/xPSR from32 SRAM bytes. Compare PC and reconstructed SP with GDB
   unwind. The formula accounts for alignment, but the alignment bit was0 in all16
   experiments; the additional4-byte branch was not verified on hardware.
4. Temporarily select the interrupted frame: the C expression delay_ms yields500;
   read start or record optimized_out. Restore the previous selection in finally
   and check that restoration explicitly.
5. The owned entry point has been deleted. Set a new hardware point at the
   **saved PC in the exception stack**, not the handler LR. After natural return,
   check thread mode, function, SP and r0–r3/r12/LR/PC, then handler work and progress
   to the next app_loop.

Final series: **16/16 HW PASS**,8 per GDB14/16 — two scenarios, initial pass and
three predetermined repeats. HAL restored after all three series; HW_BOOT/HW_GPIO
PASS. Every research run confirms hardware insertion, RSP Z1 without Z0; four
fault guards stayed enabled. Scenarios do not modify MMIO.

## Preserved failures and findings

The first SYSTICK produced FAIL: delay_ms was2 instead of500. The stack showed
board_adc_init → board_delay_ms, matching the ordinary2ms ADC startup delay.
A call-selection condition was added: a function name alone is insufficient.

The next series produced SYSTICK PASS and TIM2 ERROR while converting start to int.
GDB reported optimized_out. The final snapshot records that distinct state without
substituting0. All8 final TIM2 runs saved PC=0x08000258, the first board_delay_ms
instruction. ELF disassembly places the counter load initializing start later,
at0x0800025a. Thus start is not initialized at this point; optimized_out does not
prove that the variable was eliminated or that unwinding failed. In8 SYSTICK runs,
start was available and equal to2.

Both initial outcomes are retained in [JSON](../results/rc3-r11-results.json).
They are not part of the final16/16. HAL restoration passed after both as well.

Halting the MCU changes IRQ arrival conditions; TIM2 can become pending during
halt. These tests verify context and return semantics, not timing/frequency or
the normal distribution of interrupted addresses. PSP, nested IRQs, extended FP
frames, tail chaining, finish/return from handlers and stepi across exceptions
were not separately tested. Do not apply this decoder to them.
Frame types/selection: [GDB Frames In Python](https://sourceware.org/gdb/current/onlinedocs/gdb.html/Frames-In-Python.html).
