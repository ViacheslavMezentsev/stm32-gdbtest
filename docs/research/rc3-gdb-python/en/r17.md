## Firmware and matrix

Added an ordinary application [abi_main.c](../../../../tests/api-experiments/src/abi_main.c)
with a separate unit [abi_values.c](../../../../tests/api-experiments/src/abi_values.c).
The main loop processes data and saves results in volatile fields. No hooks or
test branches. CMake selects it through RC3_ABI_FIXTURE=ON and chooses the ABI with
RC3_FLOAT_ABI=soft/hard. Defaults retain the previous application and soft ABI;
conflicting applications and hard ABI without FPU initialization are rejected.

The hard variant uses -mfpu=fpv4-sp-d16. main enables CP10/CP11, then executes DSB/ISB
before calling process_abi, confirmed by disassembly. Its ELF declares
Tag_ABI_VFP_args: VFP registers. affine receives double in d0/d1 and returns d0
but computes through __aeabi_dadd; gain_adjust uses vadd.f32. Thus hard ABI here
does not imply hardware double arithmetic. CALL results retain CPACR.

[Three scenarios](../../../../tests/api-experiments/profile/tests/board/test_abi_extended.py)
each exercise four types:

| Function | Natural result | Forced return | Additional checks |
| --- | --- | --- | --- |
| accumulate(3), void | accumulated +=3 | Empty return skips effect | Finish has no scalar result; direct call has void type and retains its side effect |
| affine(2.5,0.5), double | 5.5 | -2.25 | FinishBreakpoint, call and caller-visible result |
| gain_adjust(3.5f), float | 4.75 | -2.5 | Same, including hard-float transfer |
| weighted_sum(1…6), uint32 | 654321 | 42 | All6 DWARF arguments; natural-entry SP%8=0, fifth/sixth at SP/SP+4 equal5/6 |

FINISH captures the natural result; RETURN skips the body and supplies a replacement;
CALL verifies the direct result and PC/SP restoration. After each operation ordinary
code consumes the result, then another natural iteration confirms normal behavior.
Void CALL separately observes +3 from direct invocation and +3 from subsequent
natural execution: register restoration does not roll back RAM side effects.

**48/48 HW PASS:** two ABIs × two GDBs × three scenarios × four runs;24/24 per ABI.
These are48 scenarios, each covering four types, not192 independent runs.
BlackPill F411CE/ST-Link/OpenOCD0.12.0 HLA/SWD, Windows, GDB14/16, GCC13.3.1,
-Og/-g3, without LTO. No unexpected FAIL/ERROR. Baseline and final HAL restoration
HW_BOOT/HW_GPIO PASS in both matrices; no remaining GDB/OpenOCD processes.
All four fault guards retained; logs confirm hardware Z1 without Z0.

## Limits and reproduction

The stack was inspected directly at natural FINISH/RETURN entries. For the
six-argument dummy call, the computed result and PC/SP restoration were checked,
not its intermediate stack. Values are exactly representable; NaN/Inf, rounding,
variadic calls, FPU lazy stacking and preservation of every FP register were not
tested. The earlier forced-structure-return FAIL from R5 remains open.
Structures/HFA, C++, IRQ/RTOS and other boards/ABIs are outside this substage.

Build separate consumer directories with RC3_ABI_FIXTURE=ON and
RC3_FLOAT_ABI=soft/hard. Pass the corresponding hwtest/session.json to the
[runner](../../../../tests/api-experiments/run_matrix.py) with --suite r17 --execute,
both previous GDBs and the agreed restore session, without --native-stlink.
Without execute only preparation runs; earlier scenarios require their original ELF.
