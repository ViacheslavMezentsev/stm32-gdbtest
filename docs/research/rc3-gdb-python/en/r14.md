observe process_packet and read_packet simultaneously using two hardware breakpoints.
Each stop is checked against breakpoint identity and exact PC before being passed
to [CallOrder](../../../../tests/api-experiments/lab/sequence.py). Checks cover
alternating functions, cycles iteration, caller, output pointer and capacity.
This observes the selected functions, not a complete trace of all calls.

Substitution writes eight bytes into the validated output buffer, then GDB return
passes a signed status to the caller. The next process_packet entry is the boundary:
the previous value has been consumed and the next one has not yet been obtained.
Checks cover saved status, bytes and last accepted total. Fields format and
destination remain intact. SEQUENCE/RETAIN observe exactly9 selected events across4
iterations; ORDER observes3 across1. After removing points, one more natural iteration
confirms status8 and total770.

## Techniques and limits

- A finite action list provides different responses from one function without
  hooks or dummy calls. Here repeated calls come from the main loop; an internal
  retry algorithm, backoff and stopping retries after success were not tested.
- Two simultaneously active points detect unexpected order among the selected
  calls. Sequential run_until for the expected name alone could miss an extra
  call to another name. A CallOrder error does not consume the expectation; missing
  and extra events are separately rejected by host regression.
- After errors, check retention of a previously accepted result instead of always
  expecting zero. In this firmware the buffer and signed status change while total stays.
- Two points plus four fault guards occupy six code slots. No FinishBreakpoint
  is needed here; adding one without freeing a slot is not a verified operation.
  Logs confirm Z1 without Z0. Waiting is bounded by external timeout and a finite plan.
- RAM substitution intentionally remains visible to the caller; this is not a
  transactional rollback. Once interception is removed, read_packet naturally
  repopulates the buffer. Other ABIs, IRQ/RTOS concurrency, Linux HW and other boards
  were not tested.
