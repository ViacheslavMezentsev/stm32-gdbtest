## Scenarios and results

[Four scenarios](../../../../tests/api-experiments/profile/tests/board/test_navigation_extended.py)
ran on BlackPill F411CE/ST-Link/OpenOCD0.12.0 HLA/SWD, Windows, GDB14/16.
Source locations are resolved through gdb.decode_line, requiring complete resolution
and one PC. The BL sum_bytes instruction and its successor are identified by
disassembly within process_sample bounds. Scenarios do not hard-code absolute addresses.

| Scenario | Action | Verified stop |
| --- | --- | --- |
| UNTIL | From first loop body, until app.c:28 | sum_bytes, PC0x080000d0, return total, sum773 |
| ADVANCE | From process_sample, advance app.c:26 | Child sum_bytes body, PC0x080000c4 |
| ADVANCE, continued | From sum_bytes, advance *process_packet | Current frame exits to process_sample, PC0x08000124; process_packet address not reached |
| NEXTI | nexti at BL0x08000120 | process_sample, PC0x08000124, r0=773 |
| INTERRUPT | Same nexti with a separate sum_bytes point | BreakpointEvent identifying that point inside sum_bytes, PC0x080000bc; call traversal incomplete |

INTERRUPT removes the point and explicitly navigates to the instruction after BL.
Every scenario finishes by checking checksum=773 XOR0xffffff85 and cycles=0 at
process_packet entry: ordinary caller code actually consumed the result.
No manual RAM/register substitution; fault guards retained. Hardware override and
logs confirm Z1 without Z0, including internal navigation points.

**Corrected matrix:32/32 HW PASS** — four scenarios × four runs × two GDBs.
Baseline and HAL restoration HW_BOOT/HW_GPIO PASS in both series;
no remaining GDB/OpenOCD processes.

## Retained ERROR and implications

The first UNTIL stopped correctly: return PC, sum_bytes frame and total773 passed.
The scenario then incorrectly read i after its scope ended, producing ERROR
`No symbol "i" in current context.` The matrix stopped and firmware was restored.
The original ERROR and scenario-version hash remain in [JSON](../results/rc3-r16-results.json).
The fix verifies symbol absence through lookup_symbol in the current block;
total and caller consumption confirm loop completion. The rerun followed this correction.

- Out-of-scope means no symbol in the current context; optimized_out from R15 is
  an existing value GDB cannot reconstruct. Distinguish these states instead of
  substituting zero.
- gdb.execute returning does not prove arrival. advance completed on frame exit;
  nexti stopped on another breakpoint. Check event, PC and frame together.
- Successful until/advance here produce StopEvent without a user breakpoint number.
  Do not require BreakpointEvent from every command or treat an empty breakpoint
  list as failure without checking PC/context.
- After an unrelated stop, continue to an explicit boundary. Repeating nexti inside
  the child would perform a different operation.
- Coverage is until with an explicit line, advance and nexti over one natural call.
  Bare until, recursive navigation, O2/Os, signals/faults during these commands,
  Linux HW and other boards were not tested. HLA PASS does not cancel the native stepi ERROR from R4.
