## Verified techniques

[Two scenarios](../../../../tests/api-experiments/profile/tests/board/test_interrupted_calls.py)
exercise calls from halted thread mode on F411CE/ST-Link/OpenOCD0.12.0 HLA.

| Experiment | Actions and independent checks |
| --- | --- |
| RESUME | Call `sum_bytes(sample.bytes, 8, 5)` through parse_and_eval and stop at an owned hardware point. Check event identity, seed=5 and one DUMMY_FRAME. Delete the point and continue; check PC/SP/LR/r0–r12, disappearance of dummy and the original process_sample frame. Sample RAM is unchanged; a fresh uninterrupted call returns775 and natural execution produces the expected checksum |
| INTERCEPT | Call `process_packet()`, stop in its read_packet, execute `return -7` after the stop, then continue. Checked registers are restored, but packet_status=-7 persists in RAM; packet and packet_total are unchanged. A normal call then produces status=8 and total=770; the natural checksum is also correct |

This tests a caller's error path on demand, without waiting for a natural event
or modifying firmware. Substitution runs after the GDB callback returns, on the
main thread. Call selection, known initial state and caller postconditions remain
necessary: a successful return command alone does not replace them.

## Recognizing the stop

Interrupted parse_and_eval raises gdb.error: expression evaluation is abandoned.
The scenario retains the full message as an expected observation and also checks
its own breakpoint number, stopped function and frame.type()==gdb.DUMMY_FRAME.
An arbitrary exception is not evidence of a successful interception.

In these experiments the dummy frame's name() returns **Reset_Handler**.
The name alone therefore implies neither a reset nor a normal Reset_Handler call;
classification needs the frame type. After continue, a plain StopEvent arrives
without a user breakpoint number. Completion is recognized by dummy disappearance,
return to the original frame and equality of the saved registers.

The Python expression has already raised an exception and does not resume with
the MCU. This technique does not recover the original parse_and_eval return value.
RESUME obtains775 from a separate fresh call; it must not be attributed to the
interrupted call. INTERCEPT checks an independent RAM sink in the calling code.

Register restoration **does not roll back RAM**. The persistent packet_status=-7
is an intentional assertion. Comparing PC/SP/LR/r0–r12 does not prove preservation
of all RAM, stack contents, xPSR, FPU, peripherals or IRQ state.

predetermined repeats per version. This series has no unexpected FAIL/ERROR;
expected interruption messages are retained in [JSON](../results/rc3-r9-results.json).

JSON includes actual GDB/Python versions, source hashes, snapshots and assertions.

The four fault guards stayed enabled. OpenOCD hardware override was enabled;
RSP contains Z1 and no Z0 in all16 scenarios, and server logs confirm hardware
insertion. The internal dummy point also needs headroom: these tests use one user
point plus the internal call mechanism, without extra persistent points.
Dummy-call resource exhaustion was not separately tested. Requested speed1000kHz;
OpenOCD reset configuration requests2000, actual1800kHz, as in preceding series.

20 host regressions in one group); documentation3/3. Linux HW, native DAP, other
boards, signal/fault/timeout during calls, async and RTOS were not tested here.
No full R1–R8 HW regression was run; previous limitations remain.
