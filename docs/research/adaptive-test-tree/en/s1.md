# S1: simulated failures, pruning and recovery

[Documentation](index.md) · [Русский](../ru/s1.md)

2026-10-02. Simulation only. No MCU measurements or debugger servers. The model is
outside stm32_gdbtest and is not an approved API/runner.

## Example and expected transitions

```text
board
├── latch: release
│   └── keys: key1, key2
├── comm: handshake
│   └── protocol: exchange
├── temperature: sample
├── recovery: recover
└── disabled: never
```

Keys requires input.keys=true, protocol input.link=true. Latch/comm forward current
shared facts to children. Their separate ok field aggregates own results; recovering
link never erases handshake FAIL. Parent outputs do not depend on child results.

| Step | Executed | Facts keys/link | Expected next behavior |
| --- | --- | --- | --- |
| 0 | — | UNKNOWN / UNKNOWN | keys/protocol BLOCKED, release next |
| 1 | release PASS | TRUE / UNKNOWN | keys active, key1 next |
| 2 | key1 FAIL | FALSE / UNKNOWN | key2 BLOCKED, proceed to handshake |
| 3 | handshake FAIL | FALSE / FALSE | protocol BLOCKED, proceed to sample |
| 4 | sample PASS | FALSE / FALSE | Independent temperature checked, recover next |
| 5 | recover PASS | TRUE / TRUE | keys/protocol active again, key2 next; key1 remains FAIL |
| 6 | key2 PASS | TRUE / TRUE | exchange next; never repeat key1 |
| 7 | exchange PASS | TRUE / TRUE | No eligible tests; never remains DISABLED |

Seven simulated executions: five PASS, two **deliberately scripted FAILs**, one
DISABLED. These are fictitious scenario results, not failing engine checks.
Model verification succeeds by reproducing this exact history including failures
and temporary blocking. At step5 keys is active=true but output.ok=false: hardware
availability and test success are visibly distinct.

## Oracle and checks

[expected.json](../../../../tools/research/adaptive_tree/fixtures/bringup/expected.json)
was authored independently of Engine from the table: eight complete states,
including every node field, queue, history and fact provenance. run never updates
it. The runner records actual snapshots and compares types, keys, values and list
order; the first difference includes its JSON path. Object-key order is irrelevant;
eligible/array order matters.

**14 behavioral model checks pass on Windows:** full oracle; All/Any truth table;
inactive ancestor with true leaf condition; Any activation after FAIL/PASS; ERROR
to UNKNOWN plus independent work; reset invalidation/diagnosis; terminal BLOCKED;
DISABLED with descendant; detached snapshots; invalid input/budget; invalid paths/
JSON; corrupted snapshot; deliberate engine mutant ignoring input conditions;
HTML data embedding and script-termination escaping.

The mutant really executes key2 immediately after key1 despite blocking, and the
oracle detects the difference. This is a negative control of verification, not a
substitute for the main run. Full Windows host suite:112 tests, eight platform skips,
no unexpected FAIL/ERROR.

## Viewing

[player.html](../results/player.html) is standalone, without CDN/network requests;
open it directly in a browser. Actual [snapshots.json](../results/snapshots.json)
is embedded, and HTML contains no scheduler logic. Slider, First/Previous/Next,
Play/Pause and playback interval remain available; clicking a card shows its full
JSON. The static skeleton runs left to right: rectangular cards are connected by
parent-input edges. Positions remain fixed between steps. Green marks ACTIVE,
inactive cards are gray; separate badges show PASS/FAIL/ERROR results. Recovery
can make a card ACTIVE while retaining a FAIL. A gold outline marks the last
execution, an outer green outline marks selection. Narrow screens scroll the
graph. Completion concerns the node’s own tests, not the entire subtree.

Browser checks covered initial state, gray keys/protocol at step3, recovery at
step5, retained FAIL/key2 PENDING, manual start/end, backward step, node selection
and Play automatically stopping at step7.

## Reproduction

From repository root using Python standard library:

```text
python -B -m unittest tools.research.adaptive_tree.test_engine -v
python -B tools/research/adaptive_tree/run.py --out build/adaptive-tree
python -B tools/research/adaptive_tree/player.py build/adaptive-tree/snapshots.json build/adaptive-tree/player.html
```

For another set use `run.py --fixture <directory>` containing facts.json,
tree/node.json and independently authored expected.json. run exits0 on match,1
on difference; model errors also exit nonzero. Never turn differences into PASS
by automatically overwriting the oracle. Normal host discovery includes the model
through the [test adapter](../../../../tests/host/test_adaptive_tree_research.py).

## Conclusion and next discussion

For a finite sequential set the model demonstrates pruning after each test,
independent work continuing and reactivation without repeated execution. Complete
JSON verifies intermediate decision reasons, not only execution order. This does
not prove real hardware behavior.

Before extending agree ERROR aggregation, traversal order, fact mutation authority,
fact lifetime after reset, terminal blocked state and final reporting. Recovery is
currently an explicit ordinary scenario in an independent branch, not automatic
retry or an external asynchronous signal. Possible follow-ups are in the [plan](plan.md).
