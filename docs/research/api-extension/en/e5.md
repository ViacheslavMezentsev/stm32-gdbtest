# E5: conventions conformance and acceptance readiness

[Research](index.md) · [Русский](../ru/e5.md)

2026-10-03. Reviewed implementation at `1e3d25c` and E1–E4 evidence.
This is analysis, not API approval or a new hardware run.
Source drafts: [api-evolution](../../rc3-gdb-python/en/api-evolution.md),
[api-proposal](../../rc3-gdb-python/en/api-proposal.md),
[execution-context](../../rc3-gdb-python/en/execution-context.md).
An agreed clarification for this study makes record a runtime journal; export
and adapters are out of scope. Departing from the older report-writing proposal
is not inherently a defect. Other differences cannot silently become accepted.

## 1. Evidence and rating criteria

Operations: R — record/records, V — read, C — capture/stack/caller, F — finish.
“Conforms” applies to the verified experimental scope, not the entire originally
proposed API. “Partial” means incomplete implementation; “differs” means observed
semantics differ; “untested” means no evidence. “Not applicable” needs a reason.
Passing host tests does not establish hardware behavior.

- R: [E1](e1.md), [paired comparison](e1-comparison.md), evidence.py/test_record.py,
  test_scenario_variants.py. Snapshots, order, limits, queries and statistics checked.
- V: [E2](e2.md), typed_read.py/test_typed_read.py: global RAM objects, F411.
- C: [E3](e3.md), stack_context.py/test_stack_context.py: SysTick/WFI, F411.
- F: [E4](e4.md), natural_finish.py/test_natural_finish.py: top frame, void/integer, F411.

All implementations are in [tests/api-extension](../../../../tests/api-extension).
Final host suite: 44/44 PASS; corrected HW series each separately 4/4 PASS.
Original E3/E4 errors and restorations remain in the registry. This is not one
regression of a future integrated API. Core, current API RU/EN and system specification
are unchanged from `b3d19e0`; the full legacy API suite was not rerun.

## 3. Methods and models against the other drafts

| Method / model | Source | Status | Specific difference / action |
| --- | --- | --- | --- |
| record/records | api-proposal §3, api-evolution E5/E8 | Partial | Owner clarified runtime purpose; copies protect journal but remain mutable. Explicitly choose this contract rather than equating it with immutable context. Provenance is only name/sequence within an instance |
| read / ValueSnapshot | api-proposal §3 and §6 | Partial | Type/size/value exist, snapshot lacks kind/availability/provenance, frame/local unsupported; separate width/signedness undefined. Explicitly approve smaller contract or extend |
| Context | execution-context “Proposed shape” | Differs | __getitem__ is not a full Mapping; no stop/meta/availability, requested registers or selected_index; stack instead of frames. ['PC'] verified, full schema not |
| StackSnapshot/caller | api-proposal §3.1 and §6, execution-context conclusion | Partial | Frames/complete/reason exist but metadata only on parent Context; no FrameRef, frame/arguments/locals/find_caller. Exact depth/unknown work; None caller needs explicit handling or bool(None) hides uncertainty |
| Historical snapshots | execution-context freshness/consistency, items 1–4 | Partial | Immutability and post-resume access verified; run_id is instance ID, current ignores thread/inferior/image. Thread switch without event can yield false current |
| Events/interventions | execution-context items 2, 6 | Partial | Draft allows explicit invalidation for raw GDB, but integration with Target.set_value/force_return/reset is incomplete and not all lifecycle paths tested |
| MCU consistency | execution-context item 5 | Conforms | No atomic DMA/MMIO claim; V takes explicit RAM ranges, C does not read peripheral memory |
| ReturnResult/StopResult | api-proposal §4, §6 | Differs | F has no common StopResult/Context or ValueSnapshot, only breakpoint IDs and signal. Connection loss/fault lack an agreed diagnostic model |
| finish and timeout | api-proposal §4, §7; api-evolution E8 | Partial | Case deadline preserved, no separate timeout_s or selected frame; scalar/void HW PASS does not establish general finish |

Inspection findings without dedicated failure tests yet:

- C.close can stop cleanup and mask a primary with-body error if disconnect raises.
  The successful “0 handlers” check does not cover this.
- F.cleanup_errors stays in the backend instead of automatically entering
  ReturnResult/system diagnostics. Killing GDB externally may prevent Python finally;
  host recovery, not this prototype, handles restoration.
- F uses return address and SP as evidence, without tracking invocation identity
  for every recursive or unusual control transfer.
- E3's missing constant and E4's expired breakpoint exposed gaps in initial host
  models; added regressions do not substitute for a GDB configuration matrix.

## 4. Recommendations, not accepted API

| Candidate | Recommendation | Before acceptance |
| --- | --- | --- |
| record/records | First small package | Agree on runtime-only scope, copies, limits, error hierarchy and run/scenario ownership; do not require export now |
| read | Retain after data-model refinement | Agree on RAM/global scope or expand it; link provenance, availability and convenient extraction |
| frames/context + caller technique | Retain after model unification | Mapping/keys, shared StackSnapshot, thread/inferior/revision, unknown end/caller and cleanup |
| finish | Keep experimental | Fault/exit/timeout, ABI/capabilities, locations, selected frame and cleanup/context integration; then new acceptance |

The first three recommendations do not authorize copying current code into core.
Research utility is established; conformance to the full proposal is not. Reduced
code volume is unproven; current benefits are journaling, typed data and separating
GDB mechanics from scenario techniques.

## 5. Open questions and E6 order

Q1–Q12 at the [end of the plan](plan.md) remain open. Added Q13–Q16 cover cleanup
failures, full context model, unknown results and versions. Recommendations are
not recorded as agreed answers.

Under the [current version policy](../../../en/VERSIONING.md), new pre-1.0 features
belong in 0.2.0; the rc3 research name does not override this. Recommend retaining
package SemVer and independence of API_VERSION/schemas/specification revisions.
API_VERSION number and change criteria need a separate decision; do not bump it
automatically with the package.

E5 is complete as a conformance review, not successful acceptance of every method.
Next E6 requires owner decisions on initial scope, versions and questions, followed
by contracts/specification and separate integration authorization. Until then,
core, existing scenarios and versions remain unchanged. No new E5 hardware runs.
