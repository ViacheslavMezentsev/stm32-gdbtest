## Experimental boundary

`finish(backend)` is an isolated natural-return technique for a normal Cortex-M
top frame, void or integers up to 32 bits. It is not the full proposed
Target.finish(frame, timeout_s). It uses a temporary hardware breakpoint at the
caller's PC, a single continue and PC/SP checks at the stop.
It does not force a return or modify arguments/registers. Integer results are read
from r0 under AAPCS and cast to the return type; typedefs are stripped.
Floats, aggregates, wide integers, arbitrary frames, tail calls/inline and other
ABIs are rejected or outside the verified scope. An ARM architecture name alone
is insufficient for general ABI capability detection.

ReturnResult is materialized and immutable: outcome, value_state, value, type_name,
breakpoints, signal. Only the owned point hit with matching PC/SP gives returned.
A foreign/coincident point, signal, missing event or position mismatch gives
interrupted, without retrying continue. Classification is coarse: fault/exit do
not yet have separate outcomes. value_state is available, void, unavailable or
not_returned; None does not silently replace zero.

Before creating a point, profile headroom is checked against all enabled GDB
breakpoints, including foreign ones; no software fallback. This conservatively
counts objects, not all locations of multi-location breakpoints.
Only the owned temporary point is cleaned up. Cleanup failure alone propagates;
with a primary failure, it is retained in backend.cleanup_errors without masking
the primary exception. Physical execution effects are not rolled back.

There is no independent timeout_s yet: the rc2 external case deadline applies
(20 s in this experiment). Host timeout/cleanup checks do not establish hardware
interruption of a hung finish. No live frame handles escape; integration with E3
context revision tracking remains pending.

## Results

Host 44/44 PASS overall, including 8 E4 tests: scalar/void, foreign/coincident
points, signal/missing stop, PC/SP mismatch, unavailable result, no capacity,
primary/cleanup failures and temporary breakpoint expiry.

Windows/F411CE/ST-Link/OpenOCD HLA 1 MHz/GDB14.2.90.20240526-git,
GCC13.3.1 -Og soft ABI, existing CMSIS ELF. First attempt: baseline PASS,
experiment ERROR (reading a temporary breakpoint number after deletion), both
restores PASS. Fixed by retaining the number before continue and adding a host
regression; original failure retained.

Corrected attempt: preparation 4/4 PASS, baseline/experiment/restore 4/4 PASS:

- app_step: returned/available, unsigned long, value 1; subsequent caller
  publication in app_state.ticks was independently checked.
- board_led_toggle: returned/void.
- app_loop: foreign board_led_toggle point → interrupted/not_returned; foreign point preserved.
- Four fault guards plus two points exhausted the six-slot budget: refused before continue.
- Cleanup left exactly the original fault guards; HAL restored, HW_BOOT/HW_GPIO
  and reset_run/image_verified confirmed on both attempts.

## Conclusion and debt

The mechanism checks the return point and later caller publication separately.
Combining those assertions requires coverage analysis. gdb.FinishBreakpoint from
the first study offers other return capture facilities; this experiment uses an
explicit hardware breakpoint for resource control. Implementation comparison is
still needed; this choice is not approved for core integration.

The bounded E4 experiment is finished; full finish acceptance is not complete.
E5 debt includes per-operation timeout_s and hardware timeout/recovery, distinct
fault/exit outcomes, HAL variant on F030, signed/other ABIs on hardware,
multi-location points and invalidation integration. Q9–Q12 are appended to the
plan. Next is E5: conventions review explicitly accounting for these unverified
parts. The core is unchanged.
