## Experimental contract

`contexts.capture(max_frames=8)` returns immutable Context:
`context['PC']`, `context['SP']`, stack, run_id, stop_id, revision.
PC/SP come from newest_frame independently of selected_frame; missing mandatory
registers do not become zero. Unknown keys raise KeyError.
stack.frames is a tuple of index/kind/function/pc snapshots, without live gdb.Frame.
None function means unknown name, not missing frame.
max_frames is an integer 1–64. This is not the final Target.frames/context interface.

Termination: stack_end only for a confirmed end, depth_limit for truncation,
unwind_error for errors/unconfirmed termination, with a reason string.
`caller_is(stack, name, depth=1)` checks exact depth, counting all frames:
True/False with sufficient evidence, None for incompleteness or unknown names.
Interrupted-frame selection (skipping up to four signal frames after the handler)
remains a separate technique. These tools are not a historical call tree.

run_id currently identifies a Contexts instance, not a runner execution;
stop_id counts events since its creation. revision advances on continue, stop,
exited, new_objfile, memory_changed/register_changed and explicit invalidate().
`current(snapshot)` checks ownership, counters, stopped state and open lifetime.
Invalidated snapshots remain historically readable. Event handlers connect and
disconnect within with; hardware confirmed 0 handlers remaining after close.
Raw monitor/reset/reconnect and changes outside the facade require explicit invalidate;
complete detection of interventions and thread/inferior/core changes is not promised.

## Checks and observations

Host: 36/36 PASS overall, including 7 E3 tests. Coverage includes immutability,
caller selection, incompleteness, depth limit, unwind errors, historical access,
another owner, closing, running, limits and a GDB adapter without FIRST_ERROR.

Windows/F411CE/ST-Link/OpenOCD HLA 1 MHz, GDB14.2.90.20240526-git, GCC13.3.1 -Og
soft ABI; existing ELF. First attempt: baseline PASS, experiment ERROR because
gdb.FRAME_UNWIND_FIRST_ERROR was missing, restore HW_BOOT/HW_GPIO PASS.
This was prototype compatibility failure, not board failure; evidence is retained.
[Current GDB documentation](https://sourceware.org/gdb/current/onlinedocs/gdb.html/Frames-In-Python.html)
describes the constant but the installed build does not expose it. Verified offline
with dir(gdb); the correction uses OUTERMOST rather than a different version's numeric threshold.

After correction: preparation 4/4 PASS, baseline/experiment/restore 4/4 PASS.
The existing SysTick/WFI scenario remains intact. The experiment confirmed WFI
(0xBF30), exception 15, delay progress and retained ADC state; additionally PC/SP,
selection independence, exact caller depth, truncated→unknown, invalidation and cleanup.
Stack: SysTick_Handler → unnamed signal → board_delay_ms → app_loop → main.
The interrupted function is at depth 2, not 1. The name at depth 1 is unknown.

At main, GDB returned older=None with “no reason”. The stack is conservatively
incomplete (unwind_error); this does not prove corruption. Better classification
is tracked as Q8 at the end of the plan. An exact captured frame can still be
checked, but a deeper caller cannot be ruled out. HAL restored on both attempts.

## Conclusions and limits

E3 is complete for minimal context and the F411 SysTick/basic Cortex-M scenario.
Raw GDB traversal moved into the adapter; the technique retains bounded attempts
and instruction checks. No whole-test line reduction is claimed: this experiment
adds control assertions. RTOS/PSP/FPU, other boards and inferior/thread changes
remain unverified. Full availability/provenance and read integration are pending,
tracked as Q3–Q5/Q8. Next is E4: natural finish with return versus other-stop classification.
