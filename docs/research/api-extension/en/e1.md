## Prototype contract

Implementation: [evidence.py](../../../../tests/api-extension/evidence.py).
`RecordingTarget` is a separate facade over the existing Target, instantiated once
per scenario invocation. The core is unchanged. `record(name, data)` returns None
and appends a snapshot; `records(name=None)` returns a list of independent deep
copies with sequence/name/data. Numbering starts at 1; duplicate names are allowed.
Filtering preserves global order and original numbers. No matches means an empty
list. Export and adapters are outside this experiment: the journal is in memory only.

Accepted exact built-in types are None/bool/int/float/str/list/dict; dictionary keys
must be strings and floats finite. Arbitrary objects, subclasses, cycles and invalid
Unicode are rejected. Shared child lists are allowed but copied independently.
RecordError does not append partial evidence or consume budget.

Configurable experimental limits: 128 records, 4096 nodes and 65536 UTF-8 text bytes
across the journal, data depth 8, integers up to 256 bits by bit_length. Names and
keys count too; root depth is 0. These are logical limits, not exact Python memory
accounting. No lazy reader: queries copy matching entries. Journals are not shared
test state and do not change check outcomes; Target exceptions propagate unchanged.
Do not call record in finally in a way that masks an original exception.

## Queries and measurements

[Host tests](../../../../tests/api-extension/test_record.py) cover where/select
through comprehensions, any/all, first through next, last and take/skip through
slices. Filtering before slicing differs from slicing before filtering. `all([])`
is True; require `bool(entries)` too when observations are mandatory.

[measurement_series.py](../../../../tests/api-extension/measurement_series.py)
provides `f411_measurement_series(target, count=10)`, callable from a scenario.
It uses existing CMSIS F411 symbols board_adc_sequences and board_adc_reading.
Stops at board_adc_sample → board_delay_ms provide a post-publication checkpoint.
Checks cover sequence increment by 1 including uint32 wrap, quality=2 and existing
VDDA/temperature ranges. These are F411 profile assumptions, not universal MCU rules.

```python
samples = [r['data'] for r in t.records('mcu.measurement')]
temperatures = [s['temperature_mdeg_c'] / 1000.0 for s in samples]
voltages = [s['vdda_mv'] for s in samples]
# After validating at least two unique, valid-quality observations:
from statistics import mean, stdev
t.record('temperature.summary', {
    'mean_c': mean(temperatures), 'stdev_c': stdev(temperatures),
})
```

The full example records both statistics in mcu.summary, observation count, units
and ddof=1 (N−1 divisor). Original temperatures remain in m°C, statistics use °C;
VDDA uses mV. This is observation standard deviation, not standard error of the mean
or sensor accuracy. Ordinary Python inside GDB performs the calculation, not C
expressions or MCU functions. No deviation PASS threshold is invented without a
consumer requirement. Empty/singleton series, duplicate sequence numbers and invalid
quality produce explicit errors.

## Results and limits

2026-10-03: Windows host, `python -B -m unittest discover -s tests/api-extension -v`:
19/19 PASS. Independent numerical anchors: VDDA 3200/3300/3400 mV → mean 3300,
sample deviation 100 mV; temperature 24000/25000/26000 m°C → mean 25 °C, deviation
1 °C. Tests include skipped/repeated observations, sequence wrap, invalid quality
and insufficient observations. [Registry](../results/registry.json).

No hardware or GDB runs yet; the scripted host Target does not model ADC/DMA timing.
Halt changes observation conditions; freshness and stable reads need real-ELF
validation. Original scenarios remain intact; full ADC/HAL paired comparison and
code reduction assessment are pending. Statistics is a consumer technique, not a
new core method. Next E1 step: run the example inside GDB on F411 after verifying
the current bench, then paired comparison before proceeding to E2.
