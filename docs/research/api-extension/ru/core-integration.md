# Перенос первого пакета в ядро

[Исследование](index.md) · [English](../en/core-integration.md)

03.10.2026. Владелец разрешил перенос record/records, RecordError, config/config_props и session.toml в текущей ветке. Контракт сохранён; рабочая версия 0.2.0.dev0, цель 0.2.0, API_VERSION=1, api.toml schema=1. ТЗ API 0.2.2 и общее ТЗ 0.62. Выпуск, push и слияние не выполнялись.

## Реализация

- records.py содержит независимый от GDB журнал; Target владеет отдельным журналом каждого вызова. Публичный RecordError импортируется из корня пакета без GDB.
- configuration.py захватывает выбранные TOML один раз, валидирует чистые данные профиля, строит неизменяемые views. Известные пределы проверяются, неизвестные api-поля сохраняются.
- SESSION_CONFIG выбирается явно в CMake. session.json сохраняется; profile выводится из TOML. Конфликт PROFILE или image override и устаревший выбор target отклоняются.
- runner использует захваченные профиль/image и хеш профиля для проверки manifest. agent получает base64/SHA256 капсулу, сверяет defaults/профиль/image до подключения. Исходные TOML в GDB повторно не читаются. Если выбранный TOML также попал в --include, пакет использует те же захваченные байты; это проверено после изменения оригинала.
- Новый pack хранит капсулу и захваченный профиль; распаковка повторяет проверки, исходные пути не требуются. Старые JSON/пакеты сохраняют legacy-правила и реальные config_props. Для нового пакета требуется новый инструмент на принимающей стороне.
- TECH-010 остаётся техникой Python. TECH-011 при интеграционной приёмке использует настоящий Target и его config/record/records; историческая оболочка сохранена для сравнения.

## Проверки и границы

Host: Windows 161 тест (150 PASS, 11 платформенных skips); Linux Docker 161 (157 PASS, 4 skips). Включены независимые границы, ошибки/атомарность/копии, actual Target, CMake old/new/conflict, transport и package без исходников, legacy, отказ до инструментов/lock. Начальный прогон выявил две устаревшие заглушки чтения профиля и затем один оставшийся импорт исследовательской оболочки в перенесённом тесте; тесты исправлены, последующий прогон PASS. Намеренные ERROR/FAIL отрицательных тестов не являются аппаратными сбоями.

Docker format+host: 2/2 PASS; host+firmware GCC13 для F030/F103/F411: 4/4 PASS. Firmware-проверки включают build/preflight, full-image и отрицательные контракты. Финальная проверка docs+host+HAL: 6/6 PASS. Новый SESSION_CONFIG с full-image на реальном F030 ELF: prepare PASS. Настоящий CLI pack F030 ADC_UNITS и run --package --prepare-only: PASS. Удаление исходных TOML и перенос дат/unknown проверены host-тестами. Новый Orange Pi/SSH запуск в этом этапе не выполнялся.

Аппаратная приёмка: Windows, GCC13, GDB14/Python3.11.4; F030/OpenOCD/ST-Link, F103/J-Link CE, F411/OpenOCD/ST-Link. На каждом стенде 7/7 prepare и 7/7 HW: baseline ADC, native RTC/TIM2/ADC, табличная пара, прежняя серия, серия actual Target, два восстановления BOOT/GPIO. Всего 21 аппаратный PASS; отдельная предварительная подготовка F030 не прибавляется к этому числу. F030/F103 CMSIS и F411 HAL восстановлены, image_verified/reset_run подтверждены. F103: профиль Flash 64 КиБ, обнаружено 128 КиБ; предупреждение сохранено, образ помещается в оба диапазона.

[Обезличенные результаты](../results/core-three-boards.json) содержат ELF/manifest/restore hashes, checks, записи и статистику. Табличные checks совпадают целиком; серия сохраняет исходные проверки и добавляет четыре проверки конфигурации/GDB-арифметики. На каждом MCU 10 измерений и 11 записей. integrated_api=true подтверждает путь actual Target. Это не метрологическая калибровка VDDA/температуры и не полный аппаратный прогон всех сценариев проекта.

## Затраты

Повторено по 13 форм данных и 5 границ в CPython, GDB14 и GDB16. Все PASS. Наибольшие отношения медиан операций write_batch/read_all/read_missing к сохранённой базе для сред CPython/GDB14/GDB16: 1.23 / 1.25 / 1.13 соответственно; порог 2x не превышен. Версии Python совпадают с базой: 3.11.9 / 3.11.4 / 3.13.12. Логические лимиты не являются гарантиями RSS/latency.

Результаты: [host](../results/core-records-cost-host.json), [GDB14](../results/core-records-cost-gdb14.json), [GDB16](../results/core-records-cost-gdb16.json). Исторические результаты прототипа сохранены отдельно.

## Далее

Первый пакет перенесён и проверен в указанном объёме. Дальнейшая миграция остальных сценариев выбирается по пользе: простые проверки не обязаны заводить журнал. read/context/caller/finish и RTOS остаются вне пакета. Подготовка выпуска и удалённая аппаратная приёмка — отдельные этапы.
