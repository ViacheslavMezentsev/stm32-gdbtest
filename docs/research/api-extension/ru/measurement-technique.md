## Подготовка пары

Контроль — [исходная серия E1](../../../../tests/api-extension/measurement_series.py).
Новый вариант configured_series получает параметры из api.toml:

```toml
schema = 1
[records]
max_records = 128
[user.measurement]
count = 10
expected_quality = 2
```

expected_quality=2 относится к соответствующему варианту калибровки, не ко всем MCU.
Секция user не интерпретируется API; count проверяет сам сценарий (2…100 для этой
пары). Лимит журнала учитывает и итоговую запись: для N отсчётов нужно минимум
N+1 записей, а также достаточные бюджеты узлов/текста. Отказ не скрывается усечением.

Порядок сохранён: reach board_adc_sample → reach board_delay_ms → счётчик →
поля quality/vdda_mv/temperature_mdeg_c → record → проверки. Между соседними
отсчётами ожидается приращение uint32-счётчика ровно 1. Повтор, пропуск, неверное
качество или диапазон останавливают сценарий. Неверный отсчёт сохраняется перед
проверкой, но summary не создаётся. Номер записи журнала не заменяет счётчик MCU.

Граница согласованности задаётся протоколом публикации приложения: в точке
остановки поля должны уже быть опубликованы и не изменяться DMA/другим ядром.
Один halt или один счётчик сам по себе не гарантирует атомарный снимок.
При другом приложении нужна его схема согласованного чтения; MMIO FIFO/read-to-clear
не переносится в эту технику автоматически. Остановки меняют временной ход измерений.

## Расчёты

После завершения сбора records читается один раз. Чистые Python-данные позволяют
вычислять mean/stdev/min/max, фильтровать или сравнивать каналы без новых чтений MCU.
Пример отделяет единицы, count и выборочное СКО (ddof=1, N≥2); для СКО всей
совокупности используется pstdev с другим смыслом. Малая дисперсия не доказывает
точность калибровки датчика. Температура кристалла не является температурой воздуха.

```python
from statistics import mean, stdev

samples = [r['data'] for r in t.records('mcu.measurement')]
if len(samples) != expected_count or len(samples) < 2:
    raise ValueError('incomplete measurement series')
vdda_mv = [s['vdda_mv'] for s in samples]
temperature_c = [s['temperature_mdeg_c'] / 1000 for s in samples]
t.record('mcu.summary', {
    'count': len(samples),
    'vdda_mean_mv': mean(vdda_mv),
    'vdda_stdev_mv': stdev(vdda_mv),
    'temperature_mean_c': mean(temperature_c),
    'temperature_stdev_c': stdev(temperature_c),
    'ddof': 1,
})
```

Перед этим фрагментом проверяются свежесть/качество, как в парном варианте.
Если допускается отбраковка, правило задают заранее, сохраняют причины/число
отброшенных точек и проверяют минимальное число принятых. Нельзя незаметно
отфильтровать неуспешные измерения ради PASS. Отсутствующие данные не заменяют нулём.

### Операция GDB над сохранёнными данными

mean_in_gdb передаёт сумму/число целых отсчётов в convenience variables и вычисляет
фиксированное выражение `(double)$ddtt_tech011_sum / $ddtt_tech011_count`.
Оно не содержит адресов MCU, вызовов firmware или continue. Значения передаются
как gdb.Value, не вставляются в текст произвольной команды. Служебные переменные
сохраняются и восстанавливаются в finally; вызов — только в основном потоке GDB.
Для этой реализации сумма ограничена signed64, непустой набор содержит только int.
Double может округлять большие целые. Для обычного среднего проще использовать Python.

Это пример GDB-арифметики, а не универсальный исполнитель GDB-команд по журналу.
Если результат нужен для set_value/вызова функции/изменения регистров, это отдельная
явная фаза вмешательства со своими проверками и восстановлением. Сохранённые
отсчёты не становятся актуальным состоянием MCU при такой операции.

## Свидетельства и границы

[Пять парных случаев](../../../../tests/api-extension/test_measurement_technique.py):
обычная серия, wrap uint32, повтор, пропуск, неверное качество. Следы reach/value/check
и результаты совпадают с исходной E1. Исторические численные опоры E1:
3200/3300/3400 мВ → mean 3300, stdev 100; 24/25/26 °C → mean 25, stdev 1.
Дополнительно проверены восстановление GDB-переменных при ошибке и отказ невалидных
агрегатов без обращения к GDB.

Настоящий GDB14 и GDB16: по четыре численных набора, включая отрицательные значения
и дробное среднее; восстановление служебных переменных подтверждено.
[GDB14](../results/series-gdb14.json), [GDB16](../results/series-gdb16.json).
Здесь нет ELF/MCU: это не повтор аппаратного сбора. Предыдущие аппаратные результаты
— [E1](e1.md), [F0/F1](portability.md); они не доказывают новую интеграцию.
Windows: 88 тестов, 87 PASS/1 CMake skip.
Linux Docker: 88/88 PASS; документация CI: 4/4 PASS.
