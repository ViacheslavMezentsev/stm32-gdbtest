## Метод

[Скрипт](../../../../tests/api-extension/measure_records.py) выполняется в CPython
и GDB-Python без ELF, сервера и MCU. На Windows x64 проверены CPython 3.11.9,
GDB 14.2.90.20240526-git / Python 3.11.4 из xPack 13.3.1-1.1 и
GDB 16.3.90.20250906-git / Python 3.13.12 из xPack 15.2.1-1.1.

13 форм данных: измерения, границы узлов/текста/глубины/int, Unicode, словарь
и увеличенные бюджеты. После прогрева — 9 серий по 10 операций, GC включён.
Время записи включает создание/заполнение и освобождение журнала; чтение — весь
результат и его освобождение. Медиана относится к средним сериям, не отдельным
вызовам. В JSON сохранены все серии; максимум серии не является worst-case latency.

Память измерена отдельным запуском tracemalloc с заранее созданным входом:
retained/peak — новые выделения, а graph_bytes — размеры достижимых Python-объектов
с устранением повторных ссылок, включая входные неизменяемые значения. Ни одна
метрика не является RSS. Строки/int не дублируются физически при копировании;
общие неизменяемые значения безопасны, контейнеры независимы.

## Результаты

Все 13 случаев и 5 проверок границ прошли в каждом из трёх окружений.
Проверены точное допустимое значение и превышение nodes/text/depth/integer_bits;
после отказа журнал пуст и следующая запись получает sequence=1. Для records
128 записей принимаются, 129-я отклоняется с сохранением первых 128.

| Данные | Запись GDB14 / GDB16, мкс | Чтение GDB14 / GDB16, мкс | Объекты журнала GDB14, байт |
| --- | ---: | ---: | ---: |
| 10 пар VDDA/температура | 18.7 / 14.9 | 7.2 / 5.0 | 5107 |
| 128 пар | 245.0 / 202.1 | 91.2 / 64.3 | 52703 |
| Список, 4096 узлов | 818.0 / 534.1 | 217.7 / 182.4 | 148661 |
| Словарь, 4096 узлов | 1053.6 / 794.1 | 160.3 / 155.6 | 217674 |
| Текст, бюджет 65536 байт | 3.1 / 2.6 | 0.7 / 0.4 | 66705 |
| 1024 пары | 2218.6 / 1667.7 | 731.5 / 516.4 | 415295 |
| Список, 32768 узлов | 6440.5 / 4366.0 | 1686.4 / 1448.7 | 1195765 |

Десять удерживаемых чтений 128 пар дают пик новых выделений около 0.48 МБ,
1024 пар — 3.86 МБ. Небольшой журнал не ограничивает число копий у вызывающего кода.
UTF-8 кодирование Unicode заметно дороже ASCII: около 18 мкс вместо 3 мкс при
близком текстовом бюджете в GDB14. Это также показывает влияние формы данных.

Исходные результаты: [CPython](../results/records-cost-host.json),
[GDB14](../results/records-cost-gdb14.json), [GDB16](../results/records-cost-gdb16.json).
JSON содержит SHA256 исходного прототипа, версии, серии и память; личных путей нет.

## Рекомендация для согласования

Сохранить умеренные defaults прототипа; разрешить увеличение параметрами api.toml
в пределах первого профиля ограничений:

| Параметр records | Default | Предлагаемый максимум |
| --- | ---: | ---: |
| max_records | 128 | 1024 |
| max_nodes | 4096 | 32768 |
| max_text_bytes | 65536 | 524288 |
| max_depth | 8 | 32 |
| max_integer_bits | 256 | 1024 |

Все значения — положительные целые, bool исключён. Лимиты действуют одновременно:
1024 записи не гарантированы, если раньше исчерпаны узлы/текст. Увеличенные значения
проверены по отдельным формам, не как доказательство максимальных затрат всех
комбинаций. Это консервативный первый профиль, расширяемый по новым измерениям.
Верхние границы пока не проверяются загрузчиком: их реализация следует после принятия.

Для интеграционной приёмки предлагается повторить этот набор в целевых GDB и
расследовать ухудшение медианы более чем вдвое относительно этой базы в сопоставимом
окружении. Это порог пересмотра, не временная гарантия API. Для полных ресурсных
гарантий нужны другие требования, включая RSS и лимит удерживаемых потребителем копий.

Практика сценария: читать один раз и повторно использовать локальный результат;
применять `records('name')` до Python-фильтрации. `records()[:3]` сначала копирует
весь журнал. Частые измерения MCU отдельно влияют на бюджет сценария; данный
эксперимент измеряет только Python-операции, не ADC или GDB-чтение памяти.
