## Экспериментальный контракт

`Reader.read(path, *, fields=None, count=None)` читает глобальный C-объект
в явно заданной RAM. fields — непустой tuple уникальных имён, count — положительное
число элементов от индекса 0. Параметры взаимоисключающие. Для структуры fields
обязателен, для массива count обязателен; скаляр читается без них.
Путь допускает имя, `.field` и `[index]`. Нельзя вызовы, присваивания, арифметику,
разыменование, `->`, convenience variables или отрицательные индексы.
Используются lookup_global_symbol и доступ к дочерним gdb.Value, не parse_and_eval.

Получаем глубоко неизменяемый Snapshot с path/type_name/size_bytes/value.
Для агрегата value — tuple пар (имя/индекс, дочерний Snapshot); для скаляра —
int/bool/float. Размер агрегата — размер типа, не число прочитанных байт.
Поддержаны int/bool/enum/конечный float, массив и выбранные поля структуры;
указатели, union и C++ не поддержаны. Вложенный скаляр доступен полным путём;
рекурсивный выбор вложенных агрегатов пока отсутствует.

Лимиты на запрос: 64 узла, 256 байт скалярных значений, глубина 4; настраиваются
keyword-only. Диапазоны RAM задаёт потребитель, F411: [0x20000000, 0x20020000).
Весь выбранный объект должен попадать в диапазон; перед извлечением скаляра
проверяются адрес, тип, доступность и бюджет. Плата должна быть остановлена.
Нет continue/call/записи/неявного обхода указателей. Чтение нескольких значений
последовательное; halt не делает DMA атомарным. Частичный успешный результат
при ошибке не возвращается, но предыдущие чтения в этом запросе уже могли состояться.

ReadError содержит code/path: invalid_path, invalid_fields, invalid_count,
conflicting_selection, wrong_selection, fields_required, count_required,
array_bounds, outside_ram, unsupported_type, unsupported_path, optimized_out,
missing_symbol, not_stopped, nonfinite, limit, unreadable. Неверная конфигурация
Reader даёт ValueError. Отсутствующее поле пока попадает в unreadable через GDB;
это известная недостаточная детализация, не окончательный контракт ошибок.

## Применение и сравнение

```python
snapshot = reader.read('board_adc_reading',
                       fields=('vdda_mv', 'temperature_mdeg_c', 'quality'))
values = {name: field.value for name, field in snapshot.value}
buffer = reader.read('board_adc_buffer', count=2)
raw = [field.value for _, field in buffer.value]
```

Старый вариант массива: `[t.value(f'board_adc_buffer[{i}]') for i in range(2)]`.
Новый вариант сохраняет типы и границы, но с извлечением значений не короче старого.
Типизированная модель и эргономика требуют отдельного решения; пока нет оснований
обещать сокращение строк. Snapshot напрямую не принимается E1 record: для записи
нужно явное преобразование в разрешённые данные. Автоматический экспорт не добавлен.

## Проверки и границы результата

Windows host: 29/29 PASS всего, включая 7 новых тестов E2. Проверены пути и запрет
выражений до lookup, выбор полей/массива, неизменяемость, отсутствие символа,
ошибка памяти, optimized-out, запрет MMIO/указателей, running и лимиты.
Полное поведение GDB эти подставные объекты не моделируют.

Windows/F411CE/ST-Link/OpenOCD HLA 1 МГц/GDB 14.2.90.20240526-git,
GCC 13.3.1 -Og soft ABI, тот же ELF: подготовка 4/4 PASS, baseline/опыт/restore
4/4 PASS. Исходный ADC-тест пройден; значения каждого поля и буфера совпали с value
на той же остановке. VDDA 3302 мВ, температура 27035 м°C, quality 2; raw [941,1512].
Типы: uint32_t/int32_t/uint32_t. Вызов функции отвергнут как invalid_path,
отсутствующий символ — missing_symbol, count=3 — array_bounds. Снимок сохранился
после resume. HAL восстановлен; HW_BOOT/HW_GPIO, image_verified и reset_run PASS.

E2 завершён в ограниченном объёме глобальных объектов RAM. Float/enum не проверены
на HW; locals/frame, полная provenance (run/stop/revision), availability по полям,
специальные float, вложенные выборки, signedness/ширина как отдельные атрибуты,
неоднозначные/статические символы и удобный доступ остаются вопросами E3/E5.
Нет обещания универсального read(path, frame=...). Исследовательский Snapshot
исторический; для управления MCU у него нет подтверждённой актуальности.
Следующий этап E3 — frames и минимальный context, включая происхождение и время
жизни снимков; затем E5 проверит согласованность всех экспериментальных контрактов.
