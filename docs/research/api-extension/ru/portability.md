# E1–E4: переносимость на F0 и F1

[Исследование](index.md) · [English](../en/portability.md)

03.10.2026 выполнено расширение опытов перед принятием API. Ядро прежнее;
изменены только исследовательские сценарии и runner. База исходников — 6da79d5
с изменениями переносимости из сопровождающего коммита.
[Обезличенные результаты](../results/portability-f0-f1.json) содержат SHA ELF/manifest,
проверки, снимки, измерения и предупреждения. Raw-журналы остаются локально.

Проверки сопровождающих изменений: Docker docs/host 5/5 PASS; host 114 тестов
(4 платформенных skips); исследовательские host 44/44 PASS. Два теста адаптера
проверяют текущую ревизию и отказ при смене третьего компонента без истории.

## Стенд и результат

| Плата / профиль | Подключение | Prepare | Аппаратные запуски |
| --- | --- | --- | --- |
| Nucleo-F030R8 / STM32F030R8T6 | Windows, ST-Link/OpenOCD, SWD 1000 kHz | 8/8 PASS после пересборки | 8/8 PASS |
| WeAct BluePill-Plus / STM32F103C8T6 | Windows, J-Link CE/J-Link, SWD 1000 kHz | 8/8 PASS | 8/8 PASS |

Оба запуска: GDB 14.2.90.20240526-git из xPack GCC 13.3.1, существующая CMSIS
прошивка tests/firmware. Восемь запусков — два baseline (ADC units, Sleep/SysTick),
четыре опыта (измерения, read, context, finish), два восстановления (BOOT/GPIO).
Везде подтверждены образ и reset_run. На обеих платах оставлена проверенная
CMSIS-прошивка. F411 заново не запускалась; её результаты остаются в E1–E4.

Первый prepare F0 завершился ERROR до подключения: старый ELF не содержал
adc_convert_f030. После пересборки существующих проектов F0/F1 проверки прошли;
ошибка сохранена в JSON. На F1 во всех HW-запусках есть предупреждение:
профиль Flash 64 KiB, прочитано 128 KiB, образ помещается в оба диапазона.
PASS не доказывает точную маркировку кристалла и не расширяет профиль.

## Что пришлось параметризовать

| Факт потребителя | F0 | F1 | F411 (ранее) |
| --- | --- | --- | --- |
| Верхняя граница RAM | 0x20002000 | 0x20005000 | 0x20020000 |
| Банки NVIC для опыта | 1 | 2 | 2 |
| quality измерения | 3: одноточечная калибровка | 1: типовые параметры | 2: заводская калибровка |
| Бюджет аппаратных точек / guards | 4 / 1 | 6 / 4 | 6 / 4 |

Это параметры техники в board_config.py и профиле, а не универсальные свойства
record/read/context/finish. Сценарий исчерпания точек теперь заполняет оставшийся
бюджет профиля. F0 не обращается к несуществующему второму банку NVIC.
Парное сравнение ADC E1 остаётся отдельным опытом F411, не входит в `--case all`.

## Наблюдения

| 10 измерений за один сценарий | F0 | F1 |
| --- | --- | --- |
| VDDA: среднее / выборочное СКО, mV | 3307.4 / 0.966092 | 3313 / 0 |
| Температура: среднее / выборочное СКО, °C | 33.6172 / 0.115013 | 24.1802 / 0.097083 |

СКО использует N−1. Нулевое СКО квантованных значений не означает нулевую
погрешность; сравнивать абсолютную точность температуры между quality нельзя.

Read сохранил типы/историю снимков и совпал с обычным чтением. Context на обеих
платах дал SysTick → signal → board_delay_ms → app_loop → main. Конец стека
остался неполным: `older=None`, `NO_REASON`, текущая метка `unwind_error`.
Это подтверждает актуальность Q8, а не повреждение стека. Обработчики после close — 0.

Finish на обеих платах вернул unsigned long=1 и void; чужая точка дала interrupted
без результата. Отказ при исчерпании бюджета и сохранение guards прошли проверки.
Другие ABI, signed/float/aggregate, fault и отдельный timeout операции не проверены.

## Вывод для E5/E6

Три проверенные связки дают больше свидетельств переносимости ограниченных
прототипов, но не устраняют замечания [E5](e5.md). Матрица E5 остаётся применимой;
теперь её аппаратная база включает F0/F1 с указанными ограничениями.
Рекомендация принять сначала record/records остаётся предложением.

Следующий шаг — обсудить Q1–Q16 и контракты расширения относительно отдельной
[спецификации API 0.1.0](../../../TECHNICAL_SPECIFICATION_API.md), которая описывает
только текущий rc.2. Версия документа трёхкомпонентная, API_VERSION пока 1.
Перенос методов в ядро и миграция сценариев по-прежнему требуют решения владельца.
