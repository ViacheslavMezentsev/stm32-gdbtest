# E1: журнал runtime и статистика измерений

[Исследование](index.md) · [English](../en/e1.md)

## Контракт прототипа

Реализация: [evidence.py](../../../../tests/api-extension/evidence.py).
`RecordingTarget` — отдельная оболочка существующего Target, создаваемая на один
вызов сценария. Ядро не изменено. `record(name, data)` возвращает None и добавляет
снимок; `records(name=None)` возвращает список независимых глубоких копий записей
`sequence/name/data`. Нумерация начинается с 1; одинаковые имена разрешены.
Фильтрация сохраняет общий порядок и исходные номера. Нет записей — пустой список.
Экспорт и адаптеры не входят в эксперимент: журнал находится только в памяти.

Допустимы точные встроенные типы None/bool/int/float/str/list/dict; ключи словаря —
строки, float — конечные числа. Произвольные объекты, подклассы, циклы и неверный
Unicode отклоняются. Ссылки на общий дочерний список допустимы, но копируются.
Ошибка RecordError не добавляет частичную запись и не расходует бюджет.

Экспериментальные настраиваемые лимиты: 128 записей, 4096 узлов и 65536 байт
UTF-8 текста на весь журнал, глубина данных 8, целые до 256 бит по bit_length.
Имя записи и ключи тоже учитываются; корень имеет глубину 0. Это логические
ограничения, не точная оценка потребления памяти Python. Итератор ленивого чтения
не реализован: запрос копирует выбранные записи. Журнал не является общим
состоянием разных тестов и не меняет исходы check; исключения Target проходят
без подмены. Не вызывать record из finally так, чтобы новая ошибка скрыла исходную.

## Запросы и измерения

В [host-тестах](../../../../tests/api-extension/test_record.py) проверены where/select
через включения, any/all, first через next, last, take/skip через срезы. Порядок
фильтрации и среза имеет значение. `all([])` равно True; для обязательной выборки
проверять также `bool(entries)`.

[measurement_series.py](../../../../tests/api-extension/measurement_series.py)
содержит вызываемый из сценария пример `f411_measurement_series(target, count=10)`.
Используются существующие символы CMSIS F411: board_adc_sequences и
board_adc_reading. Остановки board_adc_sample → board_delay_ms дают точку после
публикации. Проверяются прирост последовательности на 1 с переполнением uint32,
quality=2 и прежние диапазоны VDDA/температуры. Это предпосылки именно профиля F411,
не универсальные требования к другим MCU.

```python
samples = [r['data'] for r in t.records('mcu.measurement')]
temperatures = [s['temperature_mdeg_c'] / 1000.0 for s in samples]
voltages = [s['vdda_mv'] for s in samples]
# После проверки минимум двух уникальных качественных измерений:
from statistics import mean, stdev
t.record('temperature.summary', {
    'mean_c': mean(temperatures), 'stdev_c': stdev(temperatures),
})
```

Полный пример сохраняет обе статистики в mcu.summary, число наблюдений, единицы
и ddof=1 (делитель N−1). Исходная температура сохраняется в м°C, статистика —
в °C; VDDA — в мВ. Это стандартное отклонение измерений, не ошибка среднего
и не точность датчика. Расчёт выполняет обычный Python внутри процесса GDB,
не выражения C и не функция MCU. Нет порога PASS для СКО без требования потребителя.
Пустая/одиночная серия, повтор номера и неверное качество дают явную ошибку.

## Результат и пределы

03.10.2026: Windows host, `python -B -m unittest discover -s tests/api-extension -v`:
19/19 PASS. Численные независимые опорные данные: VDDA 3200/3300/3400 мВ →
среднее 3300, выборочное СКО 100 мВ; температура 24000/25000/26000 м°C →
среднее 25 °C, СКО 1 °C. Проверены пропуск/повтор измерения, переполнение номера,
неверное качество и недостаточное число наблюдений. [Реестр](../results/registry.json).

Аппаратный и GDB-прогоны ещё не выполнены; управляемый host Target не моделирует
тайминги ADC/DMA. Halt меняет режим наблюдения, свежесть и стабильность чтения
должны быть подтверждены на реальном ELF. Старые сценарии сохранены; полное
парное сравнение ADC/HAL и оценка сокращения кода ещё впереди. Статистика — техника
потребителя, не новый метод ядра. Следующий шаг E1: проверка примера внутри GDB
на F411 после сверки текущего стенда; затем парное сравнение, до перехода к E2.
