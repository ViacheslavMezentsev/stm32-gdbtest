# M5: требования первого пакета

[Исследование](index.md) · [English](../en/m5-contract.md)

03.10.2026 владелец принял состав и версии первого пакета (Q16).
[ТЗ API 0.2.0](../../../TECHNICAL_SPECIFICATION_API.md) сохраняет базу rc.2
и добавляет нормативные требования; [общее ТЗ 0.60](../../../TECHNICAL_SPECIFICATION.md)
определяет загрузку и перенос конфигурации. Ядро остаётся rc.2.

## Принято и где зафиксировано

| Решение | Требования |
| --- | --- |
| record/records: копии, типы, последовательность, фильтры, время жизни | ТЗ API 3.3, 4.9–4.10 |
| Публичный RecordError, code/limit, отказ без изменения журнала | ТЗ API 4.9.3, 5.3–5.4 |
| config/config_props: неизменяемые значения/defaults и свойства источников | ТЗ API 4.11–4.12 |
| Настраиваемые лимиты, учёт и измерение затрат | ТЗ API 6.3–6.5; числа открыты |
| Схема api.toml, unknown/user, независимость версий | ТЗ API 7.1–7.5 |
| session.toml, CMake/JSON, конфликты, захват, перенос, legacy | Общее ТЗ 5.20 |
| Цель модуля 0.2.0, API_VERSION=1, api.toml schema=1 | Общее ТЗ 8.48 |

Точный prerelease определяется перед выпуском. read, context/stack/caller и finish
не включены в первый пакет. Принятие требований не разрешает перенос в ядро.

## Статус проверки

M5 — этап оформления требований, без новых HW-прогонов. В обеих спецификациях
добавлены критерии приёмки и матрицы требований. Предыдущие свидетельства:
[E1](e1.md), [F0/F1](portability.md), [M2/M3](config-loader.md),
[M4 transport](config-transport.md), [M4 pipeline](config-pipeline.md).
Их результаты относятся к исследовательским прототипам.

Проверки M5 в Docker CI: docs 4/4 PASS (обе спецификации в strict-режиме,
ссылки, пары RU/EN); регрессия проверки трёхкомпонентной ревизии — 2/2 PASS.
Изменений runtime и новых аппаратных запусков нет.

RecordError.code/limit ещё предстоит реализовать даже в прототипе. Legacy views,
изоляция журнала и взаимодействие с lifecycle будущего Target требуют интеграционной
проверки. Публичный путь импорта и базовый класс исключения пока не определены.
Формат внутреннего конверта и алгоритм сравнения defaults уточняются при интеграции;
перенос исходных TOML+SHA256 и отказ при несовместимости уже приняты.

## Следующие шаги

1. Измерить затраты record/records на обычных и граничных данных в Python/GDB,
   обосновать defaults и верхние границы; представить решение по Q6/Q19.
2. Закрыть детали публичного импорта/базового класса RecordError; отдельно получить
   разрешение на интеграцию принятого объёма.
3. После разрешения выполнить M6: перенести реализацию, проверить старый режим,
   новые контракты и переработанные сценарии; сохранить отдельный отчёт приёмки.

Числа 128/4096/8/65536/256 остаются параметрами прототипа. До согласования затрат
и интеграционной регрессии приёмка первого пакета не завершена.
