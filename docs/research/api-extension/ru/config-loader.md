# M2/M3: host-прототип конфигурации сессии

[Исследование](index.md) · [English](../en/config-loader.md)

03.10.2026. После принятия владельцем [M1](session-migration.md) реализован
изолированный прототип [session_config.py](../../../../tests/api-extension/session_config.py).
Ядро, CLI/CMake и нормативное ТЗ API 0.1.0 не менялись; MCU не подключались.

## Что проверено

- session.toml выбирает target/api/image; ссылки относительно его каталога.
- target обязателен; отсутствующий api даёт defaults, отсутствующий image — None.
  Явно выбранный отсутствующий/невалидный файл отклоняется без fallback.
- Известные поля records проверяются: положительные целые, не bool. schema=1
  обязательна при наличии api.toml. Числа defaults из E1 всё ещё экспериментальные;
  верхние границы не утверждены и не проверены как ресурсные гарантии.
- Неизвестные поля/секции сохраняются, включая вложенные массивы и TOML date/time.
  Локальное сохранение типов не означает проверенный перенос через JSON.
- config содержит defaults; config_props.data их не содержит. SHA256 относится
  к исходным байтам, reference — исходная ссылка. Обе структуры неизменяемы:
  словари представлены MappingProxyType, массивы — tuple.
- Каждый выбранный исходный файл читается один раз в рамках загрузки. Изменение
  файла после чтения не меняет полученный снимок; новый вызов получает новые данные.
  Это не обещание атомарного снимка файловой системы из нескольких файлов.
- Явные PROFILE/image-policy и переменная политики образа отклоняются до чтения
  конфигурации в новом режиме. Режим без TOML этим прототипом ещё не реализован.

Схема session.toml пока узкая: только [config] и target/api/image. Разрешение
неизвестных полей применяется к api.toml, не к системному селектору файлов.
Коды ConfigError — исследовательская диагностика; это не принятие RecordError Q18.

## Связь с существующей валидацией

Image проверяется существующим validate_policy; target — существующим load_profile.
Чтобы не перечитывать исходный target и не менять ядро, его захваченные байты
записываются во временный файл, который читает штатный валидатор. Этот адаптер
служит только эксперименту. При интеграции следует выделить чистую валидацию
словаря и убрать временный файл; повторная реализация схемы target не создавалась.

## Проверки и границы

[12 новых тестов](../../../../tests/api-extension/test_session_config.py) используют
независимые текстовые fixtures, временные файлы и отрицательные случаи. Вместе
с E1–E4 — 56 тестов. Первый Windows-прогон: 55 PASS, 1 FAIL — ожидание хеша в тесте
использовало LF, тогда как файл был записан с CRLF. Проверка исправлена на хеш
фактических исходных байтов; после исправления 56/56 PASS. Код хеширования не менялся.
Это дефект тестового ожидания, не аппаратный ERROR; история сохранена в реестре.

Итог: Windows 56/56 PASS, Docker CI Linux 56/56 PASS; docs 4/4 PASS.

M2 завершён, M3 выполнен в указанной локальной host-области. M4 впереди: CMake/
prepare, устаревший manifest, пакет и удалённый перенос, старый режим. В частности,
MappingProxyType/date/time нельзя просто передать через текущий JSON — требуется
отдельный эксперимент переноса с проверкой сохранения типов и неизвестных полей.
Установка атрибутов на настоящий Target и проверки интегрированного ядра не выполнены.
Перед окончательной приёмкой также остаются Q6/Q19 (ресурсы), численные границы
и конфликты будущих имён API с пользовательскими секциями. Перенос в ядро не разрешён.
