Проверены все текущие CMSIS-сценарии пяти профилей, HAL F030 и минимальный
пример потребителя. Ядро, C-прошивки и ТЗ API 0.2.2 в этом этапе не менялись.

## Что изменилось

Просмотрены 29 Python-файлов штатных сценариев и их помощников. В 16 файлах
44 группы из 282 проверок переведены на TECH-010: таблица троек
`(название, C-выражение, ожидаемое значение)` и локальная `_check_values`.
Строковое ожидаемое значение означает второе C-выражение. Сначала читается
actual, затем expected, затем выполняется check. Ошибка прекращает обход.
Помощник локален, поэтому сценарии сохраняют самостоятельность при упаковке.
Комментарии между проверками, одиночные проверки, инъекции, навигация и
диагностические поля отчёта сохранены. Новый метод ядра для таблиц не нужен.

Пять CMSIS-профилей используют `session.toml` → `target.toml` + `api.toml`.
Добавлен `HW_CI_ADC_SERIES` с настоящими `Target.config`, `record/records`:
пять последовательных публикаций ADC, проверка номера публикации/качества/
диапазона, среднее и выборочное СКО (`ddof=1`) VDDA в мВ и температуры в °C.
Количество задаётся внешней конфигурацией (2..20), журнал ограничен 32 записями.
Это проверка измерительной цепочки и Python-статистики, не метрологическая
калибровка. Журнал остаётся runtime-данными; новый экспорт не добавлен.
GDB-арифметика по сохранённым данным описана в прежнем
[TECH-011](measurement-technique.md); этот штатный вариант использует statistics.

HAL и минимальный пример сохраняют legacy-конфигурацию как проверку
совместимости. Проверки full-image в CI и `run_hw.py` используют отдельный
legacy-дескриптор: image override нельзя совмещать с выбранным SESSION_CONFIG.

## Аппаратная кампания

Windows, xPack GCC 13.3.1-1.1, GDB 14.2.90/Python 3.11.4.
F103 — J-Link CE/SWD; остальные — ST-Link/OpenOCD/SWD.
Каждому запуску предшествовал prepare; ELF/manifest проверены.

| Профиль | Штатные HW cases | Дополнительные положительные прогоны | Ожидаемый timeout ERROR |
| --- | ---: | ---: | ---: |
| CMSIS F030R8 | 19/19 | 5 | 1 |
| CMSIS F103C8 | 21/21 | 5 | 1 |
| CMSIS F401CC | 21/21 | 5 | 1 |
| CMSIS F411CE | 21/21 | 5 | 1 |
| CMSIS F429ZI | 21/21 | 5 | 1 |
| HAL F030 | 22/22 | 4 | 1 |
| Minimal consumer / F411 | 1/1 | 2 | 0 |

Итого 126 штатных сценариев: CMSIS 103, HAL 22, пример 1. Отдельно 31
положительный повтор/восстановление и 6 ожидаемых ERROR. Повторы не увеличивают
число уникальных сценариев. Во всех шести timeout проверены вход в сценарий,
TimeoutExpired, host recovery и успешный следующий сценарий. ERROR сохранён
в отчётах. После инъекций повторены положительные ADC/RTC (HAL — ADC runtime).

В конце F030/F103/F429 оставлены проверенные CMSIS-прошивки, F401/F411 —
проверенные HAL-прошивки потребителя. BOOT/GPIO после восстановления PASS,
`image_verified` и `reset_run` подтверждены. Серийные номера и локальные пути
не публикуются. F103: профиль Flash 64 КиБ, обнаружено 128 КиБ; образ помещается
в оба диапазона, предупреждение сохранено. В выводе macro preflight встречается
предупреждение GDB о конвертации CP1252 → UTF-32; оно не исключено из свидетельств.

[Машиночитаемый протокол](../results/scenario-migration.json) содержит статусы
каждого шага, проверки, хеши исходников/ELF/manifest/сырых отчётов, предупреждения
и восстановление. Сырые отчёты находятся в локальных build-каталогах.
Скрипт воспроизведения — `tests/api-extension/run_suite.py`; обязательны явные
`--session`, `--restore-session`, `--stand`, для аппаратного запуска `--execute`.
`--timeout-recovery` включает отдельный отрицательный опыт. Без execute выполняется
только prepare. Несовпадение MCU или flash-политика, отличная от if-different,
отклоняются; неожиданный результат прекращает набор с попыткой восстановления.

## Границы и следующий шаг

Это единая локальная кампания рабочей копии, не проверка удалённого main.
Внешний проект потребителя целиком не мигрировался: использованы только его
ранее согласованные прошивки восстановления. Linux HW, GCC15, новый удалённый
запуск Orange Pi, RTOS и исторические PoC не повторялись. Аппаратные full-image
этапы `run_hw.py` в этой кампании не запускались; соответствующий prepare есть в CI.

Первый пакет пригоден для штатных сценариев на пяти проверенных MCU.
Следующий шаг — обсуждение результата и подготовки версии 0.2.0; добавлять
другие исследовательские методы в ядро по этому результату не требуется.
