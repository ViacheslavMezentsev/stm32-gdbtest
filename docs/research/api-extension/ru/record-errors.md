# RecordError: структурированные отказы

[Исследование](index.md) · [English](../en/record-errors.md)

03.10.2026. Реализована диагностика по ТЗ API 0.2.0, п. 5.3–5.4, в изолированном
[evidence.py](../../../../tests/api-extension/evidence.py). Ядро не изменено.
Это выполнение ранее принятого контракта Q18, не изменение требований.

## Контракт и проверки

| code | Причина / проверка |
| --- | --- |
| invalid_name | Пустое имя, неверный тип или подкласс str; неверный фильтр records |
| unsupported_type | Неподдержанные объекты, bytes/tuple, подклассы, нестроковые ключи |
| invalid_text | Непарный суррогат в имени, ключе или значении |
| non_finite | NaN, положительная/отрицательная бесконечность |
| cycle | Циклический список; прежняя проверка общих нециклических ссылок сохранена |
| limit_exceeded | limit=records/nodes/depth/text_bytes/integer_bits |

В прототипе limit=None для остальных ошибок. Публичный класс наследует ValueError,
как прежде; точный путь импорта и базовый класс будущего production API остаются
вопросом ТЗ API 10.2.5. Тексты сообщений и порядок выбора ошибки при нескольких
нарушениях не являются контрактом.

[Новые проверки](../../../../tests/api-extension/test_record_errors.py) подтверждают:

- Все коды, оба пути превышения текста (число символов и UTF-8 байты), каждый limit.
- После отказа сохранены предыдущие записи; следующая получает очередной sequence.
- Отказ не расходует узлы/текст: последующие допустимые записи заполняют точный бюджет.
- Перехваченная ошибка позволяет явно записать диагностику и продолжить сценарий.
- Инъекция MemoryError в копирование выходит тем же объектом исключения; журнал цел.

Это не исчерпывающая инъекция отказов аллокатора. Системная классификация
необработанного исключения агентом как ERROR и check как FAIL не изменялась;
её интеграционную проверку предстоит выполнить после разрешения переноса.

## Результаты и воспроизведение

- Windows: 73 теста исследования, 72 PASS / 1 CMake skip из-за отсутствия компилятора в PATH.
- Linux Docker: 73/73 PASS; документация CI: 4/4 PASS.
- GDB14/Python 3.11.4 и GDB16/Python 3.13.12: по 18/18 PASS без skips, ELF и MCU.
- [GDB14 JSON](../results/record-errors-gdb14.json), [GDB16 JSON](../results/record-errors-gdb16.json): версии, хеш прототипа, полный журнал тестов.

Host: `python -B -m unittest discover -s tests/api-extension -q`.
В GDB из корня репозитория: `python import sys; sys.path.insert(0, 'tests/api-extension'); import run_record_errors; run_record_errors.run('<result.json>')`.
Запускать с `-nx -batch -q -iex "set auto-load off"`, Python-команду передать через `-ex`.

Прежний отчёт M5 и приложение F ТЗ описывают состояние прототипа на момент M5;
это свидетельство закрывает его доработку code/limit, но не production-интеграцию.
Измерения Q6/Q19 относятся к прежнему хешу прототипа и не перезаписаны новым запуском.
Численные пределы остаются предложением для согласования.
