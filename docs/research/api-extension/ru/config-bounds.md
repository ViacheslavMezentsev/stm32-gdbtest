# Верхние границы конфигурации records

[Исследование](index.md) · [English](../en/config-bounds.md)

03.10.2026. Реализованы согласованные ограничения ТЗ API 0.2.1 в исследовательском `session_config.py`. Контракт и ядро не изменены.

| Параметр | Default | Допустимый диапазон |
|---|---:|---:|
| max_records | 128 | 1–1024 |
| max_nodes | 4096 | 1–32768 |
| max_text_bytes | 65536 | 1–524288 |
| max_depth | 8 | 1–32 |
| max_integer_bits | 256 | 1–1024 |

Принимаются только целые числа, не bool. Ошибка известного параметра даёт `ConfigError` с кодом `api_parameter`, именем и диапазоном до запуска MCU. Это ошибка конфигурации, а не runtime `RecordError`. Неизвестные поля и секции сохраняются в config/config_props; одноимённые ключи пользовательских секций не получают ограничения records.

Проверки используют независимую таблицу ожиданий: 45 недопустимых значений (девять на параметр), 15 допустимых значений (минимум/default/максимум), три способа получить defaults (без api.toml, без records, пустой records). Проверено сохранение неизвестных значений. При передаче снимка проверяются пять максимумов и пять превышений с корректно пересчитанными SHA256: получатель повторяет семантическую проверку; внешняя ошибка transport сохраняет причину api_parameter.

Windows: 91 тест, 90 PASS и один платформенный CMake skip. Linux Docker CI: 91/91 PASS, включая старый режим и прежние парные сценарии. Defaults не изменились. Аппаратные прогоны не повторялись: этот этап проверяет конфигурацию до подключения. Предыдущая аппаратная приёмка описана в [отчёте трёх стендов](techniques-three-boards.md).

Ограничения применяются загрузчиком конфигурации. Прямой приватный конструктор исследовательского Journal не становится публичным интерфейсом и не дублирует верхние пределы конфигурации. При переносе нужен единый путь проверки конфигурации. Отпечаток транспортного формата проверяет defaults, а не все правила валидации; получатель применяет собственные актуальные правила.

Следующий этап — обсуждение переноса первого пакета в ядро по [матрице готовности](readiness.md), затем отдельная реализация и повторная приёмка на настоящем Target. Перенос пока не разрешён.
