# TECH-010: проверка удобства таблиц

[Исследование](index.md) · [English](../en/table-checks.md)

[Аппаратные пары TECH-010/011 на F030/F103/F411](techniques-three-boards.md): по 7/7 HW и 7/7 prepare; исходные проверки сохранены, восстановление PASS. Предупреждение Flash F103 сохранено. Это исследовательские оболочки, не интеграция ядра.

03.10.2026. Техника применима часто: [обзор исходников](../results/table-survey.json)
нашёл 47 последовательных блоков минимум по 3 проверки, 301 проверку в 20 файлах
CMSIS-сценариев пяти профилей. Это структурные кандидаты, не 47 независимых задач:
учтены похожие варианты плат. HAL и прочие каталоги этим обзором не охвачены.

Критерий обзора консервативен: check с постоянной меткой, value с постоянным
C-выражением, ожидание — целочисленная константа/битовая арифметика или value
постоянного C-выражения. Динамические имена, Python-предикаты и вычисления с
переменными исключены. AST-разбор не доказывает безопасность чтений MMIO.

## Парное сравнение

Подготовлены [явные таблицы](../../../../tests/api-extension/table_variants.py)
и [helper](../../../../tests/api-extension/table_checks.py), исходные сценарии сохранены.
Начальные строки таблиц перенесены из AST исходников однократно; при выполнении
таблицы не генерируются и не читают исходники. Независимый путь сравнения исполняет
оригинальные функции непосредственно.

| Сценарий | Проверки | Динамические ожидания |
| --- | ---: | ---: |
| F030 rtc_init | 13 | 1 |
| F411 adc_init | 16 | 3 |
| F103 timer_init | 8 | 1 |

[Парные тесты](../../../../tests/api-extension/test_table_checks.py): 3 успешных
прогона, 37 остановок на каждом check, 42 отказа каждого чтения (включая ожидаемые
выражения). Итого 82 парных случая; сравниваются полные следы reach/value/check,
имя и тип исключения. Два дополнительных теста: пустая таблица и отсутствие
преждевременного вычисления последующего ожидания. Отказы check инъецируются в
модель; это проверка последовательности Python, не новое испытание MCU/регистров.

Windows-регрессия: 84 теста, 83 PASS/1 CMake skip. Новых HW-прогонов нет.
Linux Docker: 84/84 PASS; документация CI: 4/4 PASS.
Исходные настройки сохранены: у F030 PRER содержит 311, вектор RTC 18;
значения F4 из примера пользователя на F030 не перенесены.

## Вывод

Рекомендуется как [TECH-010](../../../ru/TESTING_TECHNIQUES.md#tech-010),
потребительская функция поверх текущих value/check, без включения в пакет API.
Польза — отделение данных от механизма и единообразный просмотр регистров.
Число проверок и обращений к GDB не уменьшается; число строк с оформлением таблицы
может даже вырасти. Ускорение выполнения не заявляется.

Предпочтительны обычные tuple-строки и for, без comprehension с побочными эффектами,
map или all: check не возвращает логическое значение для агрегации. Строковое
ожидание здесь означает C-выражение; это подходит int-результату текущего value,
но не является соглашением для будущего типизированного чтения строк.

Таблица объединяет только соседние проверки в одном контексте. reach, инъекции,
ожидание события, изменение Python-данных и зависимые вычисления остаются между
отдельными таблицами. В момент построения таблицы допустимы только безвредные
константы/вычисления; вызов value в строке таблицы преждевременно прочитает MCU.

Следующий шаг адаптации — использовать таблицы для статических блоков в парных
сценариях принятого пакета. Для MCU-приёмки повторить реальные сценарии на выбранном
стенде, сохранив preflight, контекст, baseline/restore и идентификаторы case/contracts.
Штатные сценарии и ядро этим исследованием не изменены.
