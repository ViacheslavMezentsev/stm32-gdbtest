# TECH-010/011: парные прогоны на трёх стендах

[Исследование](index.md) · [English](../en/techniques-three-boards.md)

03.10.2026. По разрешению владельца выполнены реальные прогоны подготовленных
вариантов. Ядро и штатные сценарии не изменены; конфигурация и record/records
подключены исследовательскими оболочками. Это HW-подтверждение техник, не приёмка
интегрированного расширения API.

## Стенды и порядок

| Плата / MCU | Отладчик / backend | TECH-010 | Prepare | HW |
| --- | --- | --- | ---: | ---: |
| Nucleo-F030R8 / STM32F030R8T6 | ST-Link / OpenOCD 0.12.0 | RTC init | 7/7 PASS | 7/7 PASS |
| WeAct BluePill-Plus / STM32F103C8T6 | J-Link CE / J-Link GDB Server 8.32 | TIM2 init | 7/7 PASS | 7/7 PASS |
| WeAct BlackPill / STM32F411CEU6 | ST-Link / OpenOCD 0.12.0 | ADC/DMA init | 7/7 PASS | 7/7 PASS |

Windows, SWD 1000 kHz, xPack GCC 13.3.1; GDB 14.2.90.20240526-git, Python 3.11.4.
CMSIS firmware из tests/firmware. Подключения сверены с локальными TOML и ранее
согласованным стендом; USB-наличие не использовано как доказательство модели MCU.

Семь HW-запусков на каждой плате: исходный ADC units, исходный блок RTC/TIM2/ADC,
его табличный вариант, исходная E1-серия, конфигурируемая серия TECH-011, затем
BOOT/GPIO восстановления. Перед ними те же семь prepare; отдельный предварительный
prepare также прошёл на всех платах, но не прибавлен к таблице. Каждая серия
содержит 10 измерений. GDB-серверы запускались штатным runner с блокировкой,
flash=if-different, без mass erase/option bytes/shared mode. После каждого HW-запуска
подтверждены image_verified и teardown=reset_run.

На F030/F103 оставлены проверенные CMSIS-прошивки. На F411 восстановлена исходная
HAL-прошивка потребителя; HW_BOOT/HW_GPIO PASS. Оставшихся GDB-серверов после опытов
не обнаружено. Хеши экспериментальных ELF/manifest и восстановленных ELF сохранены
в [обезличенном JSON](../results/techniques-three-boards.json); локальные пути,
серийные номера, ELF и полные логи не коммитятся.

## Сравнение пар

[Проверяющий экспорт](../../../../tests/api-extension/summarize_techniques.py) сравнил
реальные отчёты: у TECH-010 список checks полностью совпал с исходным вариантом
на каждой плате. Это включает имена, порядок, actual/expected и passed.

У TECH-011 сохранены все исходные checks серии. Добавлены четыре проверки:
соответствие MCU конфигурации, качество измерения и согласие Python/GDB для двух
средних. В каждом журнале 10 исходных записей плюс summary. Сравнение средних
Python/GDB выполняется на одних сохранённых отсчётах с допуском 1e-9 в итоговых
единицах. Измерения между двумя последовательными прогонами не обязаны совпадать.

| MCU | quality | Среднее VDDA, мВ | Выборочное СКО, мВ | Средняя температура, °C | Выборочное СКО, °C |
| --- | ---: | ---: | ---: | ---: | ---: |
| F030 | 3 | 3307.2 | 1.032796 | 33.6014 | 0.128971 |
| F103 | 1 | 3313.4 | 0.843274 | 24.3798 | 0.107481 |
| F411 | 2 | 3302.2 | 1.135292 | 27.2132 | 0.182975 |

Это результаты новой конфигурируемой серии, ddof=1. quality имеет разный смысл:
F030 — одноточечная калибровка, F103 — типовые параметры, F411 — заводская.
Сравнивать по этой таблице абсолютную точность датчиков нельзя. Остановки GDB
влияют на темп/температуру; это не непрерывная запись с частотой ADC.

## Ограничения и следующий шаг

На F103 каждый HW-запуск сохранил известное предупреждение: профиль Flash 64 КиБ,
наблюдается 128 КиБ, образ помещается в оба диапазона. Профиль не расширен;
проверки не подтверждают точную маркировку кристалла.

Аппаратных ERROR/FAIL в этом цикле нет. Отказные проверки таблиц, пропусков,
качества и RecordError остаются ранее выполненными host-проверками; аппаратные
неисправности не инъецировались. TECH-011 пока читает TOML из исследовательской
обвязки в GDB: штатный перенос единого снимка через runner/agent ещё не внедрён.
Доступность путей на этом Windows-стенде не доказывает переносимость по SSH.

Перед HW: Docker docs/host 5/5 PASS, исследовательские тесты 88/88 PASS.
Следующий шаг — реализовать и проверить согласованные верхние границы api.toml
в прототипе, затем свести оставшиеся интеграционные проверки. Перенос в ядро
требует отдельного разрешения; парные сценарии теперь имеют аппаратную базу
для последующего сравнения с настоящим расширенным Target.
