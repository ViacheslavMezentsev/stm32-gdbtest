## Экспериментальная граница

`finish(backend)` — изолированная техника естественного возврата для обычного
верхнего кадра Cortex-M, void или целого до 32 бит. Это ещё не полный предложенный
Target.finish(frame, timeout_s). Используется аппаратная временная точка по PC
вызывающего кадра, единственный continue и проверка PC/SP после остановки.
Возврат принудительно не выполняется, аргументы и регистры не изменяются.
Целое читается из r0 по AAPCS и приводится к типу возврата; typedef разворачивается.
Float, агрегаты, широкие целые, произвольный кадр, tail-call/inline и другие ABI
отклоняются либо вне подтверждённой области. Одного имени архитектуры ARM
недостаточно для будущего общего определения поддержки ABI.

ReturnResult материализован и неизменяем: outcome, value_state, value, type_name,
breakpoints, signal. Чистое попадание только в служебную точку плюс совпадение
PC/SP даёт returned. Другая/совпавшая чужая точка, сигнал, отсутствие события или
несовпадение позиции даёт interrupted, без повторного continue. Это грубая
классификация: fault/exit пока не выделены в самостоятельные исходы.
value_state: available, void, unavailable либо not_returned; None не маскирует ноль.

Перед постановкой точки проверяется запас профильного бюджета с учётом всех
включённых GDB-точек, в том числе чужих; software fallback не используется.
Это консервативный подсчёт объектов, не полноценный учёт нескольких locations.
Удаляется только собственная служебная точка. Ошибка cleanup без первичной ошибки
поднимается; при первичной она сохраняется в backend.cleanup_errors без подмены.
Физические периферийные эффекты исполнения не откатываются.

Отдельного timeout_s пока нет: действует внешний timeout сценария rc2 (20 с в опыте).
Host-модель проверяет исключение timeout и cleanup, но не подтверждает аппаратное
прерывание зависшего finish. Raw frame handles наружу не возвращаются; связь с
счётчиками контекста E3 ещё не интегрирована.

## Результаты

Host 44/44 PASS всего, включая 8 тестов E4: scalar/void, чужие и совпавшие точки,
signal/пустая остановка, PC/SP mismatch, недоступное значение, отсутствие ресурса,
первичная/cleanup ошибки и истечение срока жизни временной точки.

Windows/F411CE/ST-Link/OpenOCD HLA 1 МГц/GDB14.2.90.20240526-git,
GCC13.3.1 -Og soft ABI, прежний CMSIS ELF. Первая попытка: baseline PASS,
ERROR эксперимента (номер временной точки прочитан после её удаления), оба restore PASS.
Исправлено сохранением номера до continue, добавлена host-регрессия; исход сохранён.

Исправленная попытка: подготовка 4/4 PASS, baseline/опыт/restore 4/4 PASS:

- app_step: returned/available, unsigned long, значение 1; затем подтверждена
  публикация app_state.ticks в вызывающей функции.
- board_led_toggle: returned/void.
- app_loop: чужая точка board_led_toggle → interrupted/not_returned; чужая точка сохранена.
- Четыре fault guards + две точки исчерпали бюджет 6: отказ до continue.
- После cleanup остались ровно исходные fault guards; HAL восстановлен,
  HW_BOOT/HW_GPIO и reset_run/image_verified подтверждены в обеих попытках.

## Вывод и долг

Механизм позволяет проверить момент возврата и затем отдельно публикацию результата
вызывающим кодом. Объединять эти проверки без анализа покрытия нельзя.
gdb.FinishBreakpoint из первого исследования предоставляет другие средства
захвата результата; здесь выбран явный аппаратный breakpoint для контроля ресурса.
Сравнение реализаций ещё нужно, этот выбор не утверждён для ядра.

Ограниченный опыт E4 завершён; полная приёмка finish не выполнена. В долг E5
переданы операция timeout_s и её HW timeout/recovery, отдельные fault/exit исходы,
HAL-вариант на F030, signed/другие ABI на HW, многоадресные точки и интеграция
инвалидации. Соответствующие Q9–Q12 добавлены в конец плана. Следующий этап — E5,
проверка соглашений с явным учётом этих непроверенных частей. Ядро не изменено.
