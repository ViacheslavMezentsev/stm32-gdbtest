Цель — оценить небольшое расширение API относительно v0.1.0-rc.2 на существующих
сценариях плат: уменьшить служебный код, сохранив проверки и улучшив диагностику.
Это отдельное исследование, продолжающее [GDB Python R1–R18](../../rc3-gdb-python/ru/index.md).
Исторические отчёты первого исследования не изменяются.

Разрешены исследовательские прототипы в отдельном пространстве экспериментов.
Перенос в `stm32_gdbtest`, изменение публичного API, API_VERSION и нормативного
ТЗ требуют отдельного решения. Создание ветки не утверждает проект соглашений.
Аппаратные этапы и RTOS первого исследования остаются на паузе; новый HW-прогон
планируется отдельно с подтверждённым актуальным стендом.

[Продолжение E1–E4 на F0/F1](portability.md): 8/8 HW на каждой плате, ограничения и сохранённый prepare ERROR. [ТЗ API 0.1.0](../../../TECHNICAL_SPECIFICATION_API.md) фиксирует текущий rc.2, без переноса расширений. Следующий этап — разбор Q1–Q16 и согласование E6.

[E6: проект первого пакета](e6-proposal.md) — контракты record/records, предложения по Q1–Q16, версиям и приёмке. Новые Q17–Q19 добавлены в конец очереди; перенос в ядро не утверждён.

[Q20: план внедрения session.toml](session-migration.md) — CMake/CLI, единый снимок, конфликты, совместимость и host-проверки M1–M6. Пока проект, не разрешение переноса в ядро.

[M2/M3: host-прототип конфигурации](config-loader.md) — 12 новых тестов, Windows 56/56 с E1–E4, сохранён первоначальный FAIL тестового ожидания CRLF. Далее M4; ядро прежнее.

[M4: транспорт и CMake](config-transport.md) — Linux 64/64, Windows 63 PASS/1 skip; JSON/config-ZIP, реальные configure old/new/conflict, старый prepare PASS. M4 частичен: production пакет/агент ещё не интегрированы.

[M4: сквозной pipeline](config-pipeline.md) — настоящий F030 ELF prepare PASS, штатный пакет, GDB-Python 6/6 без MCU; Linux 68/68, Windows 67 PASS/1 skip. Далее согласование оставшихся контрактов перед M5.

[Q6/Q19: время и память журнала](records-cost.md) — 13 форм данных и 5 границ в CPython/GDB14/GDB16; пределы предложены, согласование открыто.

[RecordError: структурированные отказы](record-errors.md) — code/limit реализованы в прототипе, GDB14/GDB16 по 18/18 PASS; далее legacy config/config_props.

[Legacy config/config_props](legacy-config.md) — старые JSON/пакеты, приоритет image, захват и неизменяемость; GDB14/GDB16 по 6/6. Далее итоговая матрица готовности.

[TECH-010: табличные проверки](table-checks.md) — 47 блоков-кандидатов, 82 парных случая; техника поверх rc.2, без нового API/HW.

[TECH-011: накопление и расчёт](measurement-technique.md) — конфигурируемая пара VDDA/температура, Python mean/СКО и GDB-арифметика по сохранённым числам; без новых HW-прогонов.
