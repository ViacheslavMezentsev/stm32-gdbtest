сценариях плат: уменьшить служебный код, сохранив проверки и улучшив диагностику.

Разрешены исследовательские прототипы в отдельном пространстве экспериментов.
Перенос в `stm32_gdbtest`, изменение публичного API, API_VERSION и нормативного
ТЗ требуют отдельного решения. Создание ветки не утверждает проект соглашений.
Аппаратные этапы и RTOS первого исследования остаются на паузе; новый HW-прогон
планируется отдельно с подтверждённым актуальным стендом.

[Продолжение E1–E4 на F0/F1](portability.md): 8/8 HW на каждой плате, ограничения и сохранённый prepare ERROR. [ТЗ API 0.1.0](../../../TECHNICAL_SPECIFICATION_API.md) фиксирует текущий rc.2, без переноса расширений. Следующий этап — разбор Q1–Q16 и согласование E6.

[E6: проект первого пакета](e6-proposal.md) — контракты record/records, предложения по Q1–Q16, версиям и приёмке. Новые Q17–Q19 добавлены в конец очереди; перенос в ядро не утверждён.

[Q20: план внедрения session.toml](session-migration.md) — CMake/CLI, единый снимок, конфликты, совместимость и host-проверки M1–M6. Пока проект, не разрешение переноса в ядро.

[M2/M3: host-прототип конфигурации](config-loader.md) — 12 новых тестов, Windows 56/56 с E1–E4, сохранён первоначальный FAIL тестового ожидания CRLF. Далее M4; ядро прежнее.
