# Changelog

Все заметные изменения в этом проекте документируются в этом файле ([English](CHANGELOG.en.md)).
Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.0.0/).
Версии: [политика](docs/ru/VERSIONING.md).

## [Unreleased]

- Уточнены обозначения версий: версия пакета stm32-gdbtest отделена от версии интерпретатора Python, API_VERSION и ревизий ТЗ.

- Редакционно согласованы выпускные документы, текущая матрица и ограничения; общее ТЗ 0.89, ТЗ API 0.3.15. Контракты не менялись.

- Бюджет сценария ADC_INVALID для F401/F411/F429 увеличен до120с: полный набор проверок через SSH/st-util может занимать более60с; проверки и общий тайм-аут runner не изменены.

- Исправлено распознавание фактической строки st-util `Listening at *:порт...`; регрессия использует завершающее многоточие.

- st-util ожидает Listening перед recovery и idle перед завершением; helper выполняет ограниченное
  ожидание и при потере SSH. Неподтверждённый idle остаётся ERROR даже при exit0 сервера.

- SSH helper сохраняет фактический код сервера после cleanup; runner выявляет аварии и принудительную остановку, сохраняя исходный статус и проверки сценария.

- Добавлен backend `st-util`: секция schema 2, serial, doctor, общий lock ST-Link и SSH;
  factory-регистры F4 доступны через настройку карты памяти GDB без ослабления identity.

- Исправлен относительный путь подмодуля в offline-проверке минимального потребителя;
  имя каталога контрактов теперь соответствует `tests` на файловой системе с учётом регистра.
- Исправлена миграция reset schema 1/2: `monitor reset init` старого профиля снова действует в OpenOCD;
  удалён остаточный fallback api.reset.command, исправлен origin, команды recovery независимы от override.
- Артефакты CI и run_hw разделены по попыткам; прежние FAIL/ERROR сохраняются. Hardware CI выводит
  отдельные коды doctor/run_hw по профилям, чтобы отказ раннего стенда был виден после последнего PASS.
- При тайм-ауте команды локального CI сохраняется частичный вывод; отказ verify-only без данных
  о прошивке больше не описывается как доказанная запись Flash.

## [0.4.0] - 2026-10-09

Кандидат выпуска: публикация после итоговой аппаратной приёмки и CI выпускного SHA.

- Профиль цели `target.toml` переведён на схему 2: диалект GDB-сервера живёт в секции `[openocd]`,
  `[jlink]` или `[stlink]`, а без секции действует встроенное значение сервера. Команда сброса
  разрешается один раз при подготовке прогона и публикуется сценарию как `stand.reset_command`;
  ключ `api.toml` `reset.command` удалён. Схема 1 читается для уже поставленных профилей.
- `run_hw.py` прекращает аппаратные шаги и повторы после отказа `build`, чтобы не использовать
  старый `session.json` и прошивку из прежней сборки.

- TECH-017: разделены допустимый начальный SP на конце RAM и границы чтения памяти; проверено на шести стендах.

- TECH-013: кадр watchpoint не обязательно является писателем; описаны запаздывание, возврат функции и неполная раскрутка. Проверено на шести стендах.

- `evaluate(..., as_type=str)` читает `char[]` с нулевым размером в GDB по адресу до NUL/256 байт:
  устранены ValueError в GDB 15/16 и ложное успешное чтение пустой строки в GDB 14. Известная граница
  `char[N]` сохранена; массив без размера и адреса даёт `read_failed`. ТЗ API 0.3.11, п. 4.18.

- Добавлен skip(reason): причина, журнал, JUnit/CTest SKIP, код77, явный допуск в run_hw; миграция обработчиков кодов.

- Удалены устаревшие методы Target `value`, `fields`, `set_value`, `force_return`;
  используйте `read`/`evaluate`, `check(rows)`, `write`, `ret`. `API_VERSION` повышен до 2; схемы TOML/JSON не меняются.

- Исправлен ложный FAIL в reach для C++-сигнатуры с внешними одинарными кавычками GDB; исходная location сохраняется, проверки точки и кадра остаются.

- Добавлены сценарии событий/интервалов, watchpoint-ожидания и инъекции; отдельный собираемый пример C++ Og/O2 и TECH-019. Используется существующий API без изменения контрактов.

- HTML-отчёт: кнопки тем и обычного/экспертного режима; без JavaScript доступны все подробности.

### Добавлено

- `results report`: автономная сводка JSON/HTML, свежая проверка целостности, отдельные исходы, все попытки и темы auto/light/dark.


- Внешние команды `results export` / `results verify`: произвольные записи JSON/CSV, явные проекции, индекс кампании и проверка целостности; лимиты и публикация без замены прежних результатов.


- Опциональный захват records.json через session.toml: отдельный итог команды и инфраструктурная ошибка JUnit при отказе артефакта.


- Cortex-M-совместимые МК других производителей ([описание](docs/ru/COMPATIBLE_MCU.md)): профиль `at32f403a`
  проверочной прошивки (WeAct AT32F4 Core Board, AT32F403ACGU7, J-Link) — порт на CMSIS Artery и 20 сценариев
  периферии через битовые поля SDK; на плате 44/44 вместе с общими сценариями. SDK Artery закреплён в
  `ci/dependencies.lock.json`, `tools/vendor_sdk.py` ставит его локально; build manifest записывает пакет Artery.
- Документация совместимых МК: README называет AT32F403ACGU7 и границы проверки, [совместимые МК](docs/ru/COMPATIBLE_MCU.md)
  дают пошаговое подключение своего кристалла; [памятка](docs/ru/HOWTO.md) — порядок push веток, bundle и
  cherry-pick, стенд CTest, регистры только для записи, сбои CI последних изменений.

### Изменено

- Удалённые стенды называются `<профиль>-<backend>.remote.toml` (`openocd`, `jlink`, `stlink`), без `.local`;
  `.gitignore` исключает `*.local.toml` и `*.remote.toml` вместо `remote.toml` и `*-remote.toml`. Загрузчик имя
  файла не проверяет, но файлы со старыми именами больше не исключены из Git — переименуйте их.
- Переносимость (без изменения поведения существующих стендов и профилей): binutils берутся с префиксом
  выбранного GDB (`riscv-none-elf-gdb-py3` → `riscv-none-elf-objdump`); формат ELF-носителя полного образа — из
  ELF прошивки; ловушки отказов и диагностика — через адаптер архитектуры (пока Cortex-M); отчёт содержит `arch`.
- Стенд: необязательные `interface` и `transport` для OpenOCD, `interface = "SWD"/"JTAG"` для J-Link. Профиль:
  необязательный `jlink_device`, `reset_halt = "monitor reset init"` для OpenOCD. Блокировка отладчика учитывает
  семейство зонда.

- TODO: дальнейший опыт применения API и направление исследований практики DDTT —
  признаки и вердикты сценариев, адаптивное дерево, зависимость от сборки и инструмента, инструменты в ОЗУ.

## [0.3.0] - 2026-10-06

Расширенный API сценариев. Кандидат 0.3.0-rc.1 не публиковался; тег `v0.3.0` ставит владелец.

### Добавлено

- Навигация и наблюдение: `reach` с ожиданием, `resume`, `step`, `until`, `finish`, `Point` с `with` и `remove()`, `watch` за записью адресуемого объекта.
- Вызовы и управление: `ret` с типизированным значением, `call` функций прошивки, `reset` с командой из `api.toml`, `execute` команд отладчика с журналом.
- Чтение и вычисление: `read`/`write` объектов, `evaluate` выражений с приведением типа, `registers` кадра, `frames` с пределом обхода.
- Профиль прогона: `profile` читает `target.toml` как раньше и даёт разделы `target`, `api`, `user`, `image`, `data`,
  `files`, `build`, `case`, `stand`, `gdb`, а также `get("a.b")`, `origin(path)` и `snapshot()`; `t.record(name, t.profile)`
  записывает снимок. ТЗ API 0.3.4.
- Файлы данных проекта: таблица `[data]` в `session.toml` (`board = "board.toml"`) даёт `t.profile.data["board"]`;
  файл захватывается вместе с конфигурацией и переносится в пакете. Профили проверочной прошивки получили `board.toml`.
- Сведения о сборке: `t.profile.build` — компилятор, пакеты Cube, версии CMSIS/HAL из макросов и ключи `-D`; по ним
  видно, использует ли прошивка HAL (`USE_HAL_DRIVER`) или LL.
- Одна `check` для всех проверок: сопоставители `within`, `near`, `one_of` оставляют в отчёте значение и границы,
  `check(name, actual)` проверяет истинность, `check(rows)` — таблицу строк с выражениями GDB.
- Строки прошивки: `evaluate(path, as_type=str)` читает C-строку из массива `char` или указателя `char *`, сопоставитель
  `matches(pattern)` проверяет её регулярным выражением Python. Функции GDB `$_streq`, `$_strlen`, `$_memeq`, `$_regex`
  работают прямо в таблице `check(rows)`; правила таблицы описаны в карточке `check`. Сценарий `HW_CI_STRINGS` и строки
  `app_info` в проверочной прошивке. ТЗ API 0.3.5.
- Ожидаемый отказ: `with t.refused("point_removed"):` проверяет, что операция отказала с нужным кодом и деталями,
  и записывает вердикт в `checks` вместо ручного `try/except ApiError`. ТЗ API 0.3.6.
- Таблица записей: `t.write([(path, value), ...])` выполняет записи по порядку после проверки всех строк; значение
  записи может быть выражением C (`"ADC1->CR2 & ~ADC_CR2_ADON"`), которое GDB вычисляет до записи. Для серии чтений
  табличная форма не вводится: достаточно `map()` (`dict(zip(paths, map(t.read, paths)))`).
- Символы и память: `symbol(name)` даёт адрес, размер, тип и секцию; `memory(address, size)` читает SRAM или Flash
  профиля, `memory(address, data)` пишет байты в SRAM с проверкой; адреса периферии отклоняются.
- Переменные кадра: `locals()` и `arguments()` одним словарём, оптимизированные значения перечислены отдельно.
- Управление точками: `Point.enable()`/`disable()` сохраняют счётчик, `condition` доступно для записи;
  бюджет `breakpoint_limit` считает только активные точки.
- Навыки для агентов `skills/`: `stm32-gdbtest-integrate` (подмодуль, каталог `hil/`, описание MCU, CMake, пресеты,
  стенд, первый прогон), `stm32-gdbtest-scenarios` (техника сценариев на API 0.3.0, стиль, миграция) и
  `stm32-gdbtest-run` (лестница запуска, схемы стенда, разбор `result.json`, частые отказы). Тест стиля принимает
  файлы сценариев потребителя в командной строке; заголовки YAML навыков проверяет `tests/host/test_skills.py`.
- Общий каталог сценариев: `tests/firmware/common/tests` для всех профилей; пользовательский проект добавляет
  каталоги поиска через `TEST_DIRS` в CMake или повторяемый `--tests` в CLI, пакет переносит их с собой.
- Девять сценариев-примеров: `HW_CI_INJECT_ZERO`, `HW_CI_WHO_WRITES`, `HW_CI_RETURN_VALUE`, `HW_CI_CONDITIONAL_STOP`,
  `HW_CI_STEP_SOURCE`, `HW_CI_UNTIL_TARGET`, `HW_CI_POINT_BUDGET`, `HW_CI_PROFILE`, `HW_CI_CALL_PREDICATE`.
- Штатные сценарии используют прежнее имя `@case`: тестовый случай читается так понятнее внутри
  скрипта. Алиас `@test` остаётся и проверяется сценарием `HW_CI_TEST_ALIAS`.
- Декоратор `@test` как алиас `@case`; статический сборщик принимает оба имени.
- Ключи `api.toml`: `frames.limit`, `call.depth`, `call.args_max`, `execute.output_limit_chars`,
  `reset.command`, `app.delay_ms`.

### Изменено

- Принятые результаты пакета 0.3.0 в `API_ACCEPTANCE`: пять плат, локально на Windows с тремя GDB, локально
  на Orange Pi 5, удалённый сервер с Windows и из WSL2, пакет подготовленного запуска, аппаратный CI GitHub.
- Каталог техник тестирования переписан под API 0.3.0 и текущие сценарии: TECH-001…011 описывают
  `check(rows)`, `write(rows)`, `ret`, `frames`, `memory`; добавлены TECH-012…018 (ожидаемый отказ, кто пишет,
  вызов как предикат, выбор остановки, место остановки без номеров строк, профиль, строки). Раздел о стиле
  сценариев обновлён: вместо `_check_values(target, rows)` — таблица `t.check(rows)` для значений цели, правила
  для `t`, идентификаторов, `refused`, `write(rows)` и мест остановки.
- Стиль штатных сценариев проверяет тест host `tests/host/test_scenario_style.py`; сценарии приведены к нему:
  комментарии функций, таблиц и циклов, пустые строки, выравнивание продолжений, строки до 120 символов
  одной строкой, без завершающих запятых. Оставшиеся числа заменены идентификаторами (`RTC_PRER_PREDIV_A_Pos`,
  `ADC_SQR3_SQ2_Pos`, маски SysTick и HSI, каналы и время выборки HAL) и именованными окнами SRAM; замены
  сверены по ELF. Помощник WFI в сценариях сна использует `t.frames()` и `t.memory()` вместо прямого `gdb`.
- Версия модуля поднята до `0.3.0`; `API_VERSION=1` и схемы JSON/TOML не изменены.
- Справочник API разбит по группам: методы, свойства, декораторы, классы и ошибки; исправлено отображение строк `read` и `evaluate`.
- Остановка классифицируется по виду сообщённой точки, а не только по причине отладчика.
- Свойства `config`, `config_props`, `settings` и `sources` удалены без алиасов: их заменяет `profile`
  (`target.config['api']['user']` → `target.profile.user`). В опубликованные теги они не входили.
- Сценарии, общие для профилей, перенесены из каталогов профилей в общий каталог; `HW_CI_SETTINGS` заменён `HW_CI_PROFILE`.
- `value`, `fields`, `set_value` и `force_return` устарели: при первом вызове за прогон в отчёт попадает предупреждение
  `deprecated` с заменой, удаление — в 0.4.0. `@case` остаётся основным именем без предупреждения.
- Сценарии и примеры приведены к соглашениям 0.3.0: объект Target везде называется `t`, ожидания из устройства записаны
  идентификаторами прошивки (`'DMA_CCR_MINC | DMA_CCR_PSIZE_0 | …'` вместо `1418`, `TIM2_IRQn + 16` вместо `44`),
  физические величины — именованными константами; замены сверены с исходными числами по ELF.
- Проверка сохранения порядка табличных проверок прежнего помощника `_check_values` удалена вместе с помощником.
- `HW_CI_MEASUREMENT_SERIES` больше не требует разных значений температуры: она может не меняться всю серию.
- Ошибка вычисления строковой ячейки `check(rows)` называет строку, ячейку и правило: строка таблицы — выражение GDB.
- Сценарии отказов общего каталога используют `refused`; сценарии ADC и сна всех профилей записывают
  чтение-изменение-запись регистров выражением, а сохранение и восстановление NVIC/SysTick — таблицей записей.
  В F103 оставшиеся литералы `| 1` и `& ~1` заменены идентификаторами `DMA_CCR_EN` и `ADC_CR2_ADON`.
- `HW_CI_INJECT_ZERO` и `HW_CI_RETURN_VALUE` больше не останавливаются на номере строки исходника: результат получателя
  проверяется после `finish`. Номер строки остаётся только в `HW_CI_UNTIL_TARGET`, который проверяет саму адресацию
  `until(файл:строка)`; тест host следит, чтобы строки не появлялись в других сценариях.
- README, TODO, AGENTS и порядок ознакомления в `maintenance` обновлены по итогам пакета 0.3.0: текущее
  состояние и ближайшие шаги, схемы запуска с приёмкой на пяти платах, пример сценария на API 0.3.0, два ТЗ
  и справочник методов в маршруте агента. Метрики аппаратных проверок — полная кампания 0.3.0 (218 сценариев).
- Добавлен справочник принятого API RU/EN: отдельные карточки, примеры и версии поддержки. ТЗ 0.67/API 0.2.4; исправлено ошибочное описание force_return, код не менялся.
- ТЗ 0.66: уточнены процедуры L0/L6; добавлено практическое руководство Docker volume, снимков, диагностики и восстановления стенда. Runtime/API не изменены.
- Ревизии «к выпуску»: общее ТЗ 0.69 и ТЗ API 0.3.7 с итоговой приёмкой; описание выпуска `docs/releases/v0.3.0.md`
  с матрицей «стенд × GDB» и английским текстом в свёрнутом блоке; правило оформления описаний в `VERSIONING`.

### Исправлено

- Удалённый стенд: порт сервера на хосте стенда берётся из 61000–64999 вместо 40000–59999, выше эфемерного
  диапазона Linux, а при отказе «порт занят» runner сам повторяет запуск с другим портом (до трёх попыток).
  Прежде удалённый прогон сразу после локального на том же Orange Pi мог упасть на первом же сценарии. ТЗ 0.68.
- `HW_CI_WHO_WRITES` на F030 (Cortex-M0) зависел от момента останова: точка наблюдения останавливает ядро
  на одну-две инструкции позже записи и могла попасть в эпилог `app_receiver_step`, где GDB теряет кадр `app_loop`.
  Проверочная прошивка считает `app_received.publications` после публикации, и останов остаётся в теле функции.
- `read` и `evaluate` указателя возвращают хранимый адрес, а не адрес самого указателя: HAL-проверки вида
  `hadc.Instance == ADC1` снова сравнивают нужные значения.
- `Point.addresses` возвращает целые адреса, а не объекты `gdb.BreakpointLocation`; значение, которое нельзя
  записать в JSON, больше не лишает прогон отчёта: агент сохраняет его как `repr`.
- Навигация учитывает версию GDB: опорная — GDB 15.2 (xPack 14.2.1). На GDB 14 событие остановки без причины,
  вид выводится по команде, адресу и кадру с признаком `inferred` и одним предупреждением `inferred_stop`;
  подставленная причина у точки наблюдения больше не выдаётся за нативную. ТЗ API 0.3.2.
- `finish` возвращает значение из истории значений GDB (раньше всегда `unavailable`), `returned_from` и состояние `void`;
  `until(location)` даёт `reached` только по адресу цели, иначе `frame_exited`.
- `breakpoint`/`reach` снова принимают `when=` как прежнее имя `condition`, `temporary` у `breakpoint` снова позиционный,
  `Point` сохраняет `is_valid()`/`delete()`: сценарии 0.1/0.2 работают без правок. ТЗ API 0.3.1.
- Повторная точка с другим условием или временная больше не подменяется существующей, а `reach` не удаляет точку сценария
  в том же месте; `clear()` удаляет все точки, а не каждую вторую.
- `write` передаёт `bool` как 1/0, отвергает значения без литерала GDB (`unsupported_value`) и проверяет выражение
  (константу enum) по его результату; `ret` берёт знаковость из `Type.is_signed` (например, `size_t`).

### Ограничения

- Указатели, структуры шире восьми байт и значения с плавающей точкой как цель наблюдения не поддерживаются.
- Часть связок не передаёт событие остановки для точки наблюдения: остановка помечается `inferred` и подтверждается изменением объекта.
- `finish()` не публикует промежуточную копию стека.
- Аппаратная проверка выполнена на пяти стендах; стенды с native DAP не использовались. Полный набор сценариев принят на
  пяти платах по шести схемам запуска ([принятые результаты](docs/ru/API_ACCEPTANCE.md)).
- Точки fault handlers, которые агент ставит при старте, занимают слоты `breakpoint_limit`.

### Fixed

- `reach` сравнивает имя кадра без суффиксов `[clone …]`, `const` и параметров: с LTO GDB
  называет кадр по символу ELF (`HmiManager::init() [clone .constprop.0]`), и верная
  остановка давала FAIL.
- Build manifest с пустыми `cube_packages` и `library_versions` больше не отклоняется:
  HAL и CMSIS могут быть не из пакета `STM32Cube_FW_*` (Arduino Core STM32).
- Удалённый сервер: runner шлёт в SSH-сессию сигнал присутствия каждые 2 с; при обрыве
  связи без закрытия соединения (Wi-Fi, кабель, сон) сервер на хосте стенда
  останавливается и отладчик освобождается через 15 с, а не через часы. Проверено на
  Orange Pi 5 выдёргиванием кабеля.
- `tools/linux_stand.py` повторяет загрузки и `git fetch` при временных ошибках сервера
  (до 4 попыток с паузами); задания CI кэшируют закреплённые загрузки.
- `tools/linux_stand.py install --only …` проверяет только выбранные компоненты: задание
  `prepare` аппаратного CI больше не падает на отсутствующем OpenOCD.
- BIN формируется только из выбранных загружаемых секций (`objcopy -j`): пустая секция
  с адресом в RAM (например, пустая `.data`) больше не растягивает его до сотен мегабайт
  перед отказом «BIN extent differs». Host-тест и регрессия CI на реальном ELF.
- Скрипты компоновщика CI-прошивок и минимального примера: адрес загрузки `.data`
  выровнен на 4 байта (на Cortex-M0 невыровненное копирование давало HardFault);
  CI отклоняет невыровненные секции загрузки. CI-профиль F103C8 — светодиод PB2
  (WeAct BluePill-Plus).
- docs/STATUS.md: число host-тестов и J-Link mapping F030R8 соответствуют коду.
- Flash сравнивается по загружаемым ELF-секциям/LMA: отличия незагружаемых
  промежутков больше не вызывают ложную ошибку или повторную прошивку.
- Валидация границ/перекрытий до сервера, readback блоками, явная область доказательства.
