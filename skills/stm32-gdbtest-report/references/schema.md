# Входной JSON (schema 2)

Один файл описывает обе формы. Полный пример — [example.json](example.json). Генератор
проверяет обязательные поля, связи кодов, ширины таблиц, ряды графиков, часовой пояс в датах
и нейтральность; номера разделов, рисунков, колонка «Где применён», перечень свидетельств и
сводка замечаний вычисляются.

## Верхний уровень

| Поле | Тип | Назначение |
| :--- | :--- | :--- |
| `schema` | 2 | версия формата |
| `demonstration` | bool | `true` — макет; помечается в техническом отчёте |
| `object` | текст | объект проверки |
| `footer` | текст | колонтитул обеих форм |
| `compact` | объект | компактный обзор |
| `technical` | объект | технический отчёт |

## `compact`

| Поле | Назначение |
| :--- | :--- |
| `title`, `subtitle` | шапка; `\n` в названии — перенос строки |
| `date` | «Дата и время проверок: … (UTC+N)»; без часового пояса вход отклоняется |
| `source` | строка «Источник: …» (необязательно) |
| `main` | список пунктов раздела «Главное» |
| `conditions` | строки таблицы «Что / Состав» |
| `sections[]` | `title`, `columns`, `rows`, `widths` (доли, сумма 1), `note` |
| `not_checked` | список для последнего раздела |

## `technical`

| Поле | Назначение |
| :--- | :--- |
| `title`, `subtitle`, `date` | шапка; дата — интервалы кампаний с часовым поясом |
| `how_to_read` | абзацы после стандартного абзаца раздела 1 |
| `methods[]` | `id` (М-N), `name`, `gives`, `accuracy` |
| `methods_note` | абзац под таблицей способов |
| `evidence[]` | карточки (ниже) |
| `planned[]` | `id`, `requirement_ref`, `shows`, `method`, `reason` — строки «нет: …» в перечне |
| `closed_remarks` | строки `[код, где, свидетельство, чем закрыто]` для сводки |
| `excluded` | строки `[что, почему]` |
| `provenance` | `text`, `columns`, `rows`, `widths`, `mono` (индексы моноширинных колонок), `note` |

### Карточка `evidence[]`

| Поле | Назначение |
| :--- | :--- |
| `id`, `title` | С-NN и название |
| `requirement_ref` | короткая ссылка для перечня («8.1.3, 16.1.2») |
| `requirement` | текст плашки требования |
| `status` | PASS, FAIL, ERROR, SKIP, UNKNOWN, PLANNED |
| `scenarios`, `shows` | для перечня |
| `method_ids` | коды способов из `methods` |
| `conditions` | абзац «Условия и способ» |
| `tables[]` | `columns`, `rows`, `widths`, `mono`, `note` |
| `charts[]` | график (ниже) |
| `conclusion` | «Вывод» |
| `not_checked` | «Не проверено» (необязательно) |
| `data` | строка «Данные» — время с часовым поясом |
| `remarks[]` | `id` (З-NN), `title`, `ref`, `status`, `observed`, `why`, `proposal` |

### График `charts[]`

| Поле | Назначение |
| :--- | :--- |
| `kind` | `line`, `step` или `bar` |
| `x_label`, `y_label` | подписи осей с единицами |
| `caption` | подпись рисунка без номера |
| `series[]` | `label`, `role` (`expected` — синий пунктир, `observed` — оранжевый, иначе дополнительные цвета), `x`, `y` |
| `categories` | для `bar`: подписи групп; у рядов только `y` |
| `band` | `low`, `high`, `label` — полоса допуска с источником |
| `annotations[]` | `x`, `y`, `text`, `dx`, `dy` |
| `height` | высота в дюймах (по умолчанию 2,4) |

Пропуск или нечисловое значение в ряду — ошибка входа: отсутствующие данные не рисуются нулями.
