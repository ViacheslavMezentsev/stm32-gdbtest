# Реальная выборка для отчётов

`acceptance-050.json` содержит шесть карточек и очищенные контрольные суммы источников.
Это пример предметной редакции отчёта, не новый формат runner. Внутренние пути,
уникальные ID попыток и инфраструктуры в него не перенесены; локальный индекс остаётся
у составителя. Контрольные суммы связывают выборку с исходными файлами, но не заменяют
наличие этих файлов при независимой перепроверке.

## Что проверено при подготовке

- Архив O1: журнал Windows на 8fdbb58, 684 unittest / 14 пропусков и код 0.
- Архив E1: две сохранённые сводки по 21 ожидаемому исходу; исходы сценариев сохранены.
  Полная повторная проверка всех первичных E1-записей в этот пакет не входила.
- Архив E3 и свежий повтор: 16 MMIO checks, отрицательный контроль [15, 15] против
  [15, 0] с исходным FAIL; реальные callbacks модельной периферии.
- Свежий observer: 8 ожидаемых исходов, включая 2 ERROR и 1 FAIL. Для каждой записи
  проверены SHA-256 records, принадлежность case/run, число записей, sequence,
  observer_cleanup; штатный runner примера также проверяет причину отказа и cleanup.
- Свежий host Linux на базе 2f34dbc: 692 unittest / 5 пропусков; docs+host 6/6.

Архив приёмки датирован 20.10.2026 UTC+5; timestamp UTC может содержать 19.10.
Свежие повторы — 27.10.2026. Не смешивай разные ОС, ревизии и пропуски в один
«рост покрытия». Аппаратные результаты матрицы 0.5.0 в эту выборку не включены.

## Повтор без плат

Из корня модуля:

```sh
python tests/live-observer/run.py --toolchain TOOLCHAIN --gdb GDB_WITH_PYTHON --renode RENODE
python tests/mmio-renode/run.py --toolchain TOOLCHAIN --renode RENODE
```

Используй реальные пути, GCC/GDB и Renode 1.17 по README этих примеров. Host: docs+host
через [локальный CI](../../../docs/ru/local-ci.md), источник и сборка в одном Docker volume.
Сохраняй exit code, исходные ERROR и контрольные суммы. У live-observer обычный
all-PASS критерий неверен: три отрицательных исхода обязательны. Четыре FPB-случая
не поддерживаются моделью, их нельзя приписывать эмулятору.

Собери новую карточку из result/checks/records и журнала, проверь capture штатными
средствами results, затем замени только соответствующие данные в новой копии JSON.
Пример генератора не выбирает «последние» результаты и не вычисляет применимость автоматически.
Отчёт не объявляет прошедшими ещё не выполненные проверки финального SHA 0.5.1.
