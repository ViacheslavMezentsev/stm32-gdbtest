# Измерение и решение о допуске

[Навык](../SKILL.md) · [English](method.en.md)

## Независимость и временная опора

Счётчик измеряет число периодов, часы ПК задают независимый интервал.
HSE_VALUE, SystemCoreClock, UART baud и SysTick, полученные из того же HSE,
не являются независимым эталоном. RTT может доставлять счётчики, но не создаёт
внешний эталон: момент доставки не равен моменту события.

Для часов ПК используйте монотонный счётчик, например perf_counter_ns, на одном
хосте без сна/миграции VM/смены эпохи. Границы каждого запроса должны включать
всю задержку GDB/сервера/транспорта. Не подменяйте их wall clock или временем
начала команды. Погрешность хода и разрешение задаются отдельно.

Возможное инженерное основание: несколько SNTP-ответов от двух разных сервисов
до и после опыта за достаточно длинный интервал. Сохраняйте запросы/ответы,
адреса, transmit/receive/originate timestamps, монотонные границы, RTT, stratum,
LI, root delay/dispersion/precision. Отвергайте неверный originate, режим/версию,
несинхронизированный сервер, KoD, недостоверную эпоху, конфликтующие опоры.
Без аутентификации качество сервера остаётся заявлением сервера.

Для опоры i серверный момент Si находится внутри локального запроса [ai,bi]
с ошибкой серверного времени ±Ei. Для двух опор оцените положительные интервалы
локального времени [a2-b1,b2-a1] и внешнего времени
[S2-S1-E1-E2,S2-S1+E1+E2]. Делением интервалов получите границы скорости часов
ПК относительно внешних. Проверяйте весь интервал и подынтервалы, согласие
источников; учитывайте общую upstream-зависимость сервисов. Добавьте явно
обоснованный запас на ненаблюдаемый кратковременный дрейф. Конфликт или неполные
опоры не разрешают понизить бюджет/объявить калибровку. Сеть может оказаться
недостаточной для требуемого допуска; тогда нужен более точный внешний эталон.

## Измерительная цепочка

Перед опытом подтвердите по reference manual конкретного MCU источник SYSCLK,
AHB/APB и множитель timer clock, prescaler, ARR, режим счёта, clock gating и debug
freeze. Выведите коэффициент D = f_HSE/f_counter, не полагайтесь на привычное
правило «таймер всегда удваивает APB». PLL/внешний clock input меняют вывод.
Для проверки именно кварца исключите bypass/аварийное переключение на HSI.

Чтение CNT должно быть одним свежим чтением нужной разрядности, без кэша,
скрытого повторного чтения или вызова функции в выражении. Контракт MMIO
ограничивает обращения на стороне модуля; транспорт/периферию проверяйте отдельно.
Readback до/после не доказывает отсутствие скрытого изменения с возвратом назад:
нужны исключительное владение и непрерывность epoch. DMA/таймеры могут работать
при halt ядра. Не используйте ожидания RTOS в остановленной песочнице.

Для 32-битного растущего CNT снимите:

- первый отсчёт c1 с границами [a1,b1] монотонного времени;
- после ожидания второй c2 с границами [a2,b2];
- конфигурацию route и epoch до/после, подтверждение halt и продолжения счёта.

Пусть e = clock_budget_ppm / 1e6, r — консервативная ошибка каждой временной
метки (в секундах, не меньше разрешения). При 0 ≤ e < 1:

```text
Tmin = (a2 - b1 - 2r) / (1 + e)
Tmax = (b2 - a1 + 2r) / (1 - e)
delta = (c2 - c1) modulo 2^32
fmin = max(0, delta - 1) * D / Tmax
fmax = (delta + 1) * D / Tmin
value = (fmin + fmax) / 2
uncertainty = (fmax - fmin) / 2
```

Все времена в секундах, все числа конечны; Tmin > 0. ±1 отсчёт учитывает
квантование. Задайте независимую физическую верхнюю границу Fmax счётчика.
Требуйте `Tmax * Fmax + 1 < 2^32` и `delta <= Tmax * Fmax + 1`, иначе число
переполнений неоднозначно либо цепочка не соответствует предпосылкам. Не выводите
Fmax из измеряемого delta. Нулевой delta не подтверждает работающий генератор.
Не обрезайте интервал до допуска и не выбирайте меньший бюджет по желаемому исходу.

## Решение и отрицательные контроли

Задайте допустимый интервал [L,U] из номинала и допуска до опыта; например,
для f0 и p ppm это f0 × (1 ± p/1e6). Границы включены.
Сначала проверьте качество/целостность и требуемую точность измерения:

| Условие | Вердикт допуска |
| --- | --- |
| Полный измерительный интервал внутри [L,U] | IN_TOLERANCE |
| Полный интервал строго ниже L или выше U | OUT_OF_TOLERANCE |
| Пересечение границы, недостаточная точность или неизвестная опора | UNKNOWN |
| Повреждённые данные, смена route/epoch, отказ транспорта | ERROR измерения; допуск UNKNOWN |

Эти имена — термины методики, не новые значения статуса runner. Отдельно сохраняйте
raw результат сценария и результат анализа/допуска. Для DDTT отсутствие допуска
блокирует только зависимые утверждения; независимые проверки сохраняются.

Офлайн проверьте: те же отсчёты с ожиданием 25 и 16 MHz; интервал поперёк границы;
несогласованные опоры; неизвестный бюджет; короткое окно; допустимый один переход
CNT через ноль и неоднозначное число оборотов; смену epoch. Синтетический или
Renode PASS не становится измерением физического кварца.

## Проверенный пример и перенос

Пилот F411/OpenOCD: SYSCLK=HSE, AHB=APB1=1, TIMPRE=0, TIM2 PSC=24,
ARR=0xffffffff, debug freeze TIM2 выключен. D=25, независимая предпосылка
HSE ≤ 50 MHz даёт Fmax=2 MHz. TIM2 продолжает считать при halt; окно ~10 s.
PA8 AF0 MCO1=HSE/5 использовался как доступный выход для будущей приборной сверки,
не как независимый измеритель. Этот профиль нельзя переносить на другой MCU
без проверки цепочки и регистров.

При согласованном бюджете ПК 500 ppm получено 25.001560 MHz с интервалом
24.987985–25.015135 MHz, полуширина 0.0543%. Весь интервал внутри ±1% от 25 MHz.
Повторные шесть NTP-ответов двух сервисов за ~620 s охватили опыт; условные оценки
согласованы, наблюдаемая граница около 175 ppm. Бюджет 500 ppm не уменьшали.
Это один инженерный пилот, не универсальная точность и не оценка температурного
дрейфа. Отклонение центральной оценки +62 ppm меньше погрешности ±543 ppm.

## Очистка, восстановление, свидетельства

До изменений: согласовать затрагиваемую память/выводы, сохранить свежие двойные
Flash/SRAM снимки, исходные CPU/debug/peripheral, проверить SHA-256 и возможность
обратной записи. Для Flash ограничить разрешённые erase-сектора. Раздельно
сохранить исходное живое состояние и выбранный reset-halt baseline.

Для указанного F411 порядок: halt → HSI on/ready → SYSCLK=HSI/SWS verified →
TIM2 stop/interrupts off → PA8 input → HSE off/ready cleared → возврат Flash
при отличии → полная сверка Flash → reset-halt → SRAM последней/полная сверка →
проверка выбранных CPU/debug/config масок. SRAM-алгоритм программирования Flash
может портить RAM, поэтому её возвращают последней. Не заливать RO/W1C снимком.
Чтение GPIO при выключенном тактировании не доказывает внутреннее состояние;
его восстановление здесь основано на reset, сравнение масок лишь дополняет его.

Внешний supervisor ограничивает GDB и сервер, завершает только свои процессы,
имеет отдельный recovery-entrypoint по проверенному свежему снимку. Не снимать
защиту, не менять option bytes, не mass erase. После ошибки не продолжать новые
опыты до подтверждённого восстановления. Независимый повторный сеанс должен
подтвердить память и выбранное состояние; финал halt/run сообщить явно.

Протокол: требование/допуск, схема тактирования, входной ELF/SVD/скрипты и SHA,
версии инструментов, сырые счётчики/монотонные скобки, опоры и бюджет,
погрешность/вердикт, снимки и отдельный исход восстановления. Локальные серийники,
пути и backups не публиковать. После reset/смены ELF/epoch этот допуск не переносится
на приложение автоматически: требуется явное обоснование применимости.
