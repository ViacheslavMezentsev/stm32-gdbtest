# Готовая периферия STM32 и собственные модели

[English](peripherals.en.md). Пути tests/docs/tools считайте от корня модуля,
platforms/scripts — от установленной Renode. Проверяйте фактическую версию.

## Сначала готовая модель

В поставке Renode 1.17 имеются `platforms/cpus/stm32f103.repl`, `stm32f4.repl`,
`stm32f429.repl` и `scripts/single-node/stm32f103.resc`, `stm32f4_discovery.resc`.
Это отправные точки, не утверждение о полном моделировании этих MCU.

| Где смотреть | Примеры типов в REPL |
| --- | --- |
| stm32f103.repl | UART.STM32_UART, GPIOPort.STM32F1GPIOPort, Timers.STM32_Timer, I2C.STM32F1_I2C, DMA.STM32G0DMA, IRQControllers.NVIC |
| stm32f4.repl | UART.STM32_UART, MTD.STM32F4_FlashController |
| stm32f429.repl | наследует stm32f4.repl, добавляет Video.STM32LTDC |

Читайте адреса, параметры, IRQ и DMARequest-связи в REPL, затем исходник класса и
тесты именно установленной версии. Имя STM32G0DMA в платформе F103 показывает,
почему нельзя выбирать совместимость только по имени класса. Сверяйте нужные регистры
и режимы с документацией цели; отдельно проверяйте ADC, DMA, RCC и Flash.
Не копируйте огромные окна MappedMemory из готовой платформы в профиль физического MCU.

Пример команд монитора для подготовленного локального REPL/ELF:

```text
mach create
machine LoadPlatformDescription @path/to/local-platform.repl
sysbus LoadELF @path/to/firmware.elf
machine StartGdbServer 3333
```

Порт должен быть свободен и принадлежать вашему запуску. Для автоматического опыта
для моделей с внешними ресурсами используйте tools/renode_probe.py: собственные процессы, динамический порт, deadline,
журналы и cleanup; порядок вызова описан в docs/ru/RENODE_PROBES.md.
Для самодостаточного REPL и обычных @case используйте штатный backend из docs/ru/RENODE.md.

Штатные resc могут скачивать демонстрационный ELF. REPL могут содержать
`ApplySVD @https://...` внутри init. Для offline подготовьте локальные зависимости,
замените ссылки в своей копии и сохраните происхождение/хеши. Не меняйте установку.
Отдельный опыт без SVD-тегов допустим, если это явно записано: он не проверяет загрузку SVD.
В проверке загрузки трёх платформ 1.17 недоступный SVD дал ERROR в журнале при exit code 0;
не считайте код процесса достаточным PASS. Копии без сетевого ApplySVD загрузились,
но это только проверка создания платформ, без запуска прошивки или приёмки периферии.

## Когда нужна собственная модель

Наш публикуемый пример: tests/renode-cache/platform.repl и flash_model.py —
PythonPeripheral для учебного Flash-кэша; test_model.py проверяет его на host,
run.py — через GDB/Renode. Это ограниченная учебная модель, не точная Flash STM32.
Нейтральный Cortex-M3 в tests/renode-startup не содержит ADC/DMA.

Для небольшого регистра используйте PythonPeripheral: отдельный файл, явный размер
окна, обработка request.IsInit/IsRead/IsWrite, Offset/Length/Value; на чтении задавайте
request.Value. Состояние и журнал обновляйте внутри callback, без чтения регистра
через GDB для логирования. Сначала host-проверка с искусственными request, затем ELF/GDB.
Не предполагайте, что длина callback всегда 4; неподдержанный размер проверяйте явно.
Для прерываний, времени и сложных связей рассмотрите C# и Register Framework.
Порядок создания моделей — [официальное руководство](https://renode.readthedocs.io/en/latest/advanced/writing-peripherals.html).

## SVD, поведение и ширина

SVD-теги не создают поведенческую модель устройства. Учебный SVD должен соответствовать
REPL и callbacks; эталон эффектов задавайте независимо от генератора/парсера SVD.
Отдельно проверьте неверные access/readAction и явное переопределение описания.
Начиная с 0.5.0 модуль предоставляет [SVD и mmio.read/write](../../../docs/ru/api/mmio.md); внутренний парсер не заменяет независимый эталон модели.

Автоматический перевод ширин Renode способен дробить доступы и создавать RMW;
проверяйте поддерживаемые интерфейсы и AllowedTranslation. Неподдержанный адрес/размер
может дать предупреждение и ноль вместо аппаратного fault. Логи обязательны.
Методика счёта обращений и перехода на плату: [MMIO](mmio.md).

Граница опыта: модель → проверенная операция → независимый критерий → исходные
PASS/FAIL/ERROR → ограничения → повтор на согласованной плате. Наличие класса,
загрузка REPL и корректный UART banner не доказывают работу DMA/ADC/Flash.
