# Нейтральный пример C++ / GDB / Renode

[Документация](../../docs/ru/index.md) · [English](README.en.md)

Учебный маршрут Windows без платы: host fake → C++17 ELF в Renode → Python внутри GDB.
Проверяет кэш с отложенным сохранением и вызовы методов уже созданного объекта. Это отдельный
пример, не backend stm32-gdbtest; он не использует штатный Target, session.toml или result.json.
Не загружайте этот ELF в реальную плату: адреса и протокол периферии предназначены только для модели.

## Требования и запуск

Из корня репозитория, Python 3.11+, host `g++` с C++17, ARM GCC с GDB-Python и Renode 1.17 в PATH:

```powershell
# Только контракт кэша, без GDB и Renode.
python -B tests/renode-cache/run.py --host-only
# Четыре host-теста намеренно ограниченной модели, без Renode.
python -B tests/renode-cache/test_model.py
# Полный маршрут: host и два независимых экземпляра Renode.
python -B tests/renode-cache/run.py
# Неверное ожидание: должен завершиться FAIL, код 1; это успешный негативный контроль.
python -B tests/renode-cache/run.py --negative-control
```

GDB выбирается через `--gdb`, `STM32_GDBTEST_GDB`, PATH и существующий поиск тулчейна модуля.
ARM `arm-none-eabi-g++.exe` должен находиться рядом с ним. `--host-cxx` и `--renode` позволяют
передать пути исполняемых файлов; пути с пробелами заключайте в кавычки. Host g++ должен запускаться
с доступными DLL (его каталог обычно находится в PATH). Linux этим runner пока не поддерживается.
Путь рабочего дерева для этого примера должен быть без пробелов (генерируемые resc используют @path).
Не добавляйте `-O` к Python: GDB-сценарий использует assert и отказывает при их отключении.

Проверенное окружение: Windows, Renode 1.17, ARM GCC 13.3.1, GDB 14.2.90/Python 3.11.4.
Компиляция ELF: `-O0 -g3`, без LTO, исключений и RTTI. Запуск не требует сети или USB.

## Файлы и изменение сценария

| Файл | Назначение |
| --- | --- |
| run.py | Снимок входов, сборка, два запуска, журналы и очистка собственных процессов |
| buffered_store.hpp | Учебный кэш без heap: load/read/write/dirty/commit, проверка обратным чтением |
| cache_suite.hpp, cache_host.cpp | Общие 24 проверки и 15 дополнительных host-проверок отказов |
| cache_calls.cpp, cache.ld | Нейтральный ELF; локальный объект и буфер живы на остановке cache_done |
| scenario_cache.py | Читаемый сценарий GDB Python: вызовы, данные, счётчики, границы модели |
| platform.repl, flash_model.py | Cortex-M4, RAM и упрощённое хранилище с MMIO |
| test_model.py | Отдельные host-проверки свойств и намеренных пробелов модели |

Начните с изменения ожидания в scenario_cache.py, а не с прикладной прошивки. Он исполняется
в основном потоке GDB; запуск обычным Python не предоставляет модуль gdb. Кадр reset_handler
выбирается до сохранения указателей на объект/адаптер/буфер. После завершения их времени жизни
указатели использовать нельзя. GDB-вызов исполняет код CPU, а не вычисляет метод на копии объекта.
После MMIO-опытов состояние намеренно изменено: приложение не продолжается, машина завершается.

## Что проверяется

- До commit меняется только кэш; после — точное содержимое страницы и счётчик сохранений.
- Повторный чистый commit не пишет; неверный диапазон отказывает без побочного сохранения.
- Host fake моделирует частичную запись, ошибку чтения и неверное обратное чтение; dirty сохраняется
  для повтора. Возврат байта к прежнему значению не обязан снимать dirty. Деструктор не сохраняет.
- Вызовы C++ сохраняют наблюдаемые PC/SP; это не проверка всех регистров или всех контекстов.
- Стирание страниц 127/128/255 сохраняет соседние контрольные байты.

Счётчики относятся к логическим операциям адаптера, не физическим транзакциям. Вызовы через
`gdb.parse_and_eval` не являются приёмкой `Target.call()`. RTOS/ISR/PSP, LTO и оптимизированные
принудительные вызовы не проверены. Предупреждения GDB CP1252/MSP сохраняются в отчёте.

## Модель и происхождение

Нейтральный код написан для этого примера; прикладной код потребителя, Arduino и HAL не включены.
flash_model.py — самостоятельная учебная реализация наблюдённого упрощённого протокола MMIO.
Названия и смещения напоминают STM32G4, но модель намеренно не является контроллером STM32.

| Свойство | Граница |
| --- | --- |
| Память | 512 КиБ MappedMemory; запись обычной памятью не моделирует физику Flash |
| Стирание | Страница 2048 байт заполняется FF; проверены выбранные границы банков/области |
| KEYR/W1C | Последовательность ключей и очистка флагов реализованы |
| LOCK | Запись CR может обойти блокировку; отмечено NOT_SUPPORTED |
| PG/EOP | PG выставляет EOP без проверки полезной записи; отмечено NOT_SUPPORTED |
| Busy, ECC, износ, потеря питания | Не моделируются |

Негативные проверки фиксируют пробелы, а не требуют такого поведения от реального оборудования.
При улучшении модели пересмотрите эти ожидания и границы. Модель не служит проверкой HAL-драйвера.

## Результаты и повторяемость

Каждый запуск создаёт `build/renode-cache/route-<UTC>-<id>/`: inputs (снимок до сборки), ELF,
команды GDB/resc, исходные stdout/stderr `.bin`, читаемые журналы, summary.json и artifact-sha256.json.
Пути инструментов и хеши записываются локально. Старые результаты не перезаписываются.
`schema=renode-cache-example-1` — формат примера, не контракт отчётности модуля.

Коды: 0 PASS, 1 FAIL утверждения, 2 ERROR подготовки/инструмента/очистки. В негативном контроле
ожидание stores меняется с 1 на 2. Отсутствующий GDB должен дать ERROR без запуска машины.
Проверяйте cycles, model_properties и warnings, а не только exit code; отсутствие свойства не PASS.
Host-only PASS подтверждает только кэш. Отчёты не включаются в аппаратную приёмку/общую сводку модуля.

Renode запускается скрыто, готовность определяется по журналу, без пробного TCP-подключения.
ELF загружается до старта GDB-сервера; GDB использует `-nx -nh`, временную точку и отключается.
После попытки runner посылает quit, при необходимости завершает только своё дерево процессов и
проверяет освобождение порта. Выбор свободного порта имеет окно гонки; чужие серверы не подключаются
намеренно. Ручная отмена, деревья зависших компиляторов и интерактивная debugpy-отладка не приняты.
Файлы и таймауты примера не являются новым публичным TOML/CLI модуля.

Приёмы: [TECH-019/020](../../docs/ru/TESTING_TECHNIQUES.md#tech-019),
[маршрут DDTT](../../docs/ru/DDTT.md#sandbox-route), [шпаргалка](../../docs/ru/SCENARIO_CHECKLIST.md).
Сначала сформулируйте контракт и получите обнаруживаемый FAIL; после исправления повторите
тот же набор, сохранив исходный FAIL. Эмуляционный PASS не заменяет опыт на согласованной плате.
