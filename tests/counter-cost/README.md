# Счётчики и стоимость наблюдения

[TECH-024](../../docs/ru/TESTING_TECHNIQUES.md#tech-024) · [English](README.en.md)

Нейтральный C++-пример с одним исходником для host и Cortex-M3 в Renode, API 3.
Проверяются арифметика, пригодность разности и учёт расходов; физическое время MCU,
DWT, IRQ и RTOS не моделируются. Ядро модуля и платы не используются.

## Условия и независимые ожидания

Счётчик модели восьмибитный (0..255). `difference(before, after, upper, complete)`
возвращает признак пригодности и заполняет valid/delta. `upper` — подтверждённая
извне верхняя граница прироста, а не величина, вычисленная из той же пары отсчётов.
Нужны полная запись, upper < 256, корректные входы и разность не выше upper.
При отсутствии этих условий valid=0: delta=0 не имеет смысла измерения.
Совпавшие before/after дают достоверный ноль только при доказанном отсутствии полного оборота.
В реальном опыте нужны предел скорости и интервала, отсутствие reset/смены эпохи;
по двум отсчётам эти условия установить нельзя.

| Проверка | Ожидание |
| --- | --- |
| 250 → 5, upper=11 | valid=1, delta=11 |
| 7 → 7, upper=0 | valid=1, delta=0 |
| 0 → 255, upper=255 | valid=1, delta=255 |
| upper=256, потерянная выборка, превышенная граница или вход 256 | valid=0 |

`measure(work)` использует **учебные тики**: единица работы стоит 7, каждое из двух
чтений — 3. Это заданная модель, не измеренные циклы процессора. В интервал между
отсчётами попадает только первое чтение: пустой контроль = 3; полное возмущение = 6.
Для work=4: gross=31, net=28, observer=6. Пустой контроль даёт net=0.
После обеих операций от старта 250 счётчик равен 34. Допуск модели net=28 задан до опыта.
Работа >16 отклоняется без изменения объекта; максимальная измеряемая величина <256.
Постоянная baseline=3 допустима здесь потому, что модель задаёт неизменные расходы.
На MCU такой вычет требует отдельной калибровки в сопоставимых условиях и оценки разброса.

## Отдельно: время транспорта

Сценарий TRANSPORT измеряет perf_counter_ns вокруг шести настоящих вызовов GDB.
Первая выборка заранее объявлена прогревом; сохраняются все шесть, медиана и максимум
остальных пяти. Отдельный анализ требует ровно одну запись с шестью целыми
неотрицательными выборками, проверяет прогрев, область и совпадение статистик;
при пропуске/дублировании/искажении данных кампания ERROR, исходный PASS сценария
сохраняется. Это время ПК + GDB + транспорт + операция на цели, **не WCET и не
чистое время функции**. Порога быстродействия нет: проверяются только полнота записи
и корректность вызовов. Между ОС и запусками величины могут существенно отличаться.

## Дефекты и восстановление

DEFECT=1 — вычитание без маски восьмибитного счётчика; DEFECT=2 — не вычтен пустой
контроль; DEFECT=3 — пропущена проверка пригодности. Host сверяет точные имена FAIL.
Renode выполняет четыре сценария для 1,2,3,0,0: 20 исходов, ровно три намеренных FAIL,
два повтора исправленного варианта. FAIL не переписывается в PASS; успешная кампания
подтверждает ожидаемую матрицу, capture, проверку ELF и cleanup VERIFIED.
POD-объект сохраняется по размеру из ELF и восстанавливается в finally с обратным
чтением, включая FAIL. Это не обещание восстановления внешней периферии или MCU.

## Запуск

```powershell
python tests/counter-cost/run.py --host-only
python tests/counter-cost/run.py --toolchain "$HOME/xpack-arm-none-eabi-gcc-14.2.1-1.1" --renode "C:/Program Files/Renode/renode.exe"
```

```sh
python3 tests/counter-cost/run.py --toolchain /opt/xpack-arm-none-eabi-gcc-14.2.1-1.1 --renode /opt/renode-1.17.0/renode
```

Нужны host g++, Python 3.11+, ARM GCC/GDB-Python, Renode 1.17. Входы, SHA-256,
исходные result/records, версии и summary сохраняются в build/counter-cost/<id>.
Docker на Windows: исходники и сборки в volume, см. [локальный CI](../../docs/ru/local-ci.md).

## API: правильно и неправильно

- `call` выполняет операцию один раз; проверяйте outcome/return_state и return_value.
  Не повторяйте вызов ради чтения результата. В async def нужен await.
- `record` до `check` сохраняет исходные наблюдения при FAIL. Храните сырые выборки,
  единицы, прогрев, область измерения и независимый предел применимости.
- Нельзя молча заменить непригодную разность нулём, назвать максимум выборки WCET
  или считать время GDB-вызова циклами CPU. Два производных одного счётчика не независимы.
- Не измеряйте интервалы MMIO через обычный read без анализа эффектов. Перенос на DWT
  требует MMIO/SVD, проверки доступности счётчика и его поведения в halt/sleep,
  сохранения конфигурации и отдельного аппаратного допуска.

## Проверенный объём

27.10.2026: host Windows/Linux — четыре варианта; Renode 1.17 Windows/Linux —
по 20 ожидаемых исходов (17 PASS, 3 намеренных FAIL), два повтора исправления.
ARM GCC 14.2.1 / GDB 15.2.90. Все пять журналов транспорта каждой кампании прошли
отдельный анализ полноты и статистик, во всех сценариях проверены capture и
восстановление POD. Это не аппаратная приёмка и не оценка WCET.
